## РЕШЕНО 2026-10-02 — ответ владельца

**Вариант: автоматически, из размера лица в кадре.**

Формулировка решения, обязательная для спеки:

1. **Размер плана (shot size) вычисляется автоматически** из доли кадра, которую
   занимает лицо. Оператору не нужно выбирать его из меню.
2. **Справочник переносится из legacy дословно** — enum `ShotTypeSize` уже был
   заготовлен: `NONE`, `ECU`, `BCU`, `CU`, `MCU`, `MS`, `MLS`, `LS`, `VLS`,
   `XLS`. В legacy он не был подключён (поля в базе нет, функция не доделана),
   поэтому в SYP это новая реализация, а не перенос работающего кода.
3. **Пороги «доля кадра → размер плана» подбираются замером** на тестовой
   серии `GOT.S01E01` — это отдельная задача плана, цифры не выдумывать.
4. **Оператор может поправить размер вручную** — следует из решения Д-6
   («полный редактор»). Автоматика задаёт значение по умолчанию, человек
   переопределяет; факт правки помечается (как цветовая семантика оверлеев:
   красный = алгоритм, зелёный = оператор).

### Технические решения лида (в спеку, владельцу не требуют подтверждения)

- **Агрегация по плану: берётся самое крупное лицо в плане.** «Крупный план»
  определяется максимумом, а не медианой: если в одном плане лицо занимает
  половину кадра, план крупный, даже если остальные кадры пустые.
- **План без лиц** (пейзаж, кадр без человека) получает `NONE` — значение уже
  есть в справочнике. Отдельного статуса «не определено» не заводим.
- **Не переносим:** `ShotTypePerson` (`NONE/SGN/OTS/TWO/GRP/MASS`) как отдельное
  поле — это тип плана по числу людей, он выбирался вручную. В первый срез не
  входит; при необходимости вернётся отдельным тикетом.

Answer: **(а) автоматически, из размера лица в кадре.** Оператор может поправить
вручную; справочник ECU…XLS переносится как есть; пороги подбираются замером.
