### Что из-за этого не сделано

`tools/reserve-branch-number.sh` лежит в PR #3, а правило именования веток
требует брать номер этим скриптом. Значит, ветку под `speckit-plan`
зарезервировать нечем: скрипта в `master` нет, а выдумывать номер запрещено
Rule (VII.5).

Поэтому план **не запущен**, хотя спека уже одобрена владельцем и СТОП снят.
Ждём слияния PR #3 — и сразу запускаем `speckit-plan` в отдельном worktree.

### Побочная находка о защите ветки

PR #2 слился **без** одобрения, а PR #3 — нет, хотя настройки одинаковые.
Причина в `enforce_admins: false`: администратор (владелец — `svoemesto`,
он admin) может слить в обход требования одобрения. То есть защита `master`
для админа сейчас дырявая.

**Рекомендация:** включить `enforce_admins` в настройках защиты, иначе
«требуется одно одобрение» из конституции можно обойти одним флагом.

### Как только Approve

1. Слить PR #3 (living docs).
2. Зарезервировать номер ветки под план: `./tools/reserve-branch-number.sh speckit-plan`.
3. Создать отдельный worktree (Rule VII.3 — субагенты в изоляции).
4. Запустить долгоживущего субагента на `speckit-plan` по одобренной спеке.
