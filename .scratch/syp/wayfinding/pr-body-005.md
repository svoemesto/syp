## Что исправлено

В памяти проекта был записан неверный факт: якобы для правки branch protection не хватает OAuth-scope `administration`, и владельцу нужно выполнить `gh auth refresh -h github.com -s administration`.

**Совет был неверным.** Scope `administration` не существует — команда отвечает `invalid_scope`. Настоящая причина ошибки 404 была в методе:

| Метод | Результат |
|---|---|
| `PATCH /branches/master/protection` | 404 Not Found |
| `PUT /branches/master/protection` | 422 «не хватает полей» — то есть **работает** |

Рабочее тело для `PUT` передаёт все обязательные параметры (`required_status_checks`, `restrictions` и др.). Scopes токена (`gist`, `read:org`, `repo`, `workflow`) достаточны — права на репозиторий полные.

## Что сделано по итогу

Требование одобрения снято, остальная защита сохранена: push в `master` запрещён, изменения только через запрос на слияние, force push и удаление ветки запрещены, линейная история включена.

## Урок

При `404` от GitHub сначала пробовать другой метод, а не искать недостающее право. Неверный диагноз в памяти проекта опаснее отсутствующего: следующая сессия поверила бы ему и пошла бы менять токен вместо того, чтобы просто поменять метод.
