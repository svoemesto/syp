# Карта решений: путь к спеке первого сквозного среза SYP

Создана 2026-10-02 сессией лида. Источник задачи — #219 «Проект SYP».
Этот файл — рабочая копия тела карты; источник истины — work package в OpenProject.

## Destination

Дать владельцу **спеку первого сквозного вертикального среза**, которую можно
отдать в `speckit-specify` и которую можно реализовать целиком: от исходного
`.mkv` до собранного видеофайла «Show Your Picture» в публичной части, с
прохождением всего пути — детекция границ, описание сцен, поиск персонажей в
каждом кадре, ручная доводка оператором, сборка выборки в один файл, показ
пользователю.

Срез — на **одной серии** (`GOT.S01E01`, 82 834 кадра), не на архиве целиком.
Архив из 73 серий (5,96 млн кадров) — цель последующих спринтов, уже
проверенная на прочность цифрами (см. Notes).

### Три вывода из отчётов, меняющих постановку

1. **Детектора ракурса в legacy нет вообще** — только bbox. Требование
   «Джейми Ланистер, крупный план, в профиль» в старом проекте технически
   невыполнимо; владелец закрыл это решением «положение = bbox + размер плана».
2. **Детектор границ в legacy — Sikuli (GUI-автоматизация Windows), а вторая
   ветка детекта мёртва** (`diffPrev2` никогда не вычисляется). Переносить
   нечего: для SYP детектор сцен — ffmpeg-фильтр.
3. **Автодетекта сцен в legacy не существует** — сцены заводились вручную.
   Требование «описывать каждую сцену» автоматического прецедента не имеет.

### Бюджет, проверенный замерами на этой машине (nsa-i9)

- декодирование серии 1080p — **157 с**; детект границ `scdet t=8` — **162 с**
  (то есть встроенный детектор сцен стоит практически ноль дополнительного
  прохода); извлечение всех кадров 1080p JPEG — **462 кадра/с**;
- stream-copy нарезка 30 с даёт **730 кадров вместо 719** — граница
  округляется до ключевого кадра, покадровая точность не получается;
- **видео-часть — не узкое место**. Упирается в ML-детект лиц (5,96 млн
  детектов на архив).

### Ограничения среды агента, о которых надо помнить

- агент **не может писать на `/disks/*`** напрямую (bwrap-песочница монтирует всё
  в `ro`, включая `/`, в которую при этом писать можно) — любые проверки и
  замеры там делаются **через контейнер**; на хосте запись есть, проверено;
- `ffmpeg` внутри песочницы на длинных операциях **убивается `signal 9`** —
  замеры перекодирования внутри агентской среды недействительны.

## Decisions so far

Решения владельца. **Переигрывать нельзя без нового слова владельца.**

| # | Вопрос | Решение |
|---|---|---|
| Q1 | Что должна найти карта | спека на первый сквозной вертикальный срез |
| Q2 | Папка проекта | `/home/nsa/syp` |
| Q3 | GPU | GPU-first, RTX 4060 Ti 16 ГБ доступна |
| Q4 | Где лежат видео | `/disks/HDD_16Tb_Clouds/GOT` |
| Q5 | Что значит «каждый кадр проанализирован» | **(A)** детектировать лица на **каждом** кадре полным потоком 1080p; кадры не копятся |
| Q6 | Кто размечает | **(A)** алгоритм + ручная доводка; объём ручной работы ограничен границами планов |
| Q7 | Имена персонажей и «положение» | **(A)** система выдаёт кластеры похожих лиц, оператор даёт имена; «положение» = **bbox + размер плана**; ракурс вне среза |
| Q8 | Форма «Show Your Picture» | **(A)** на сервере собирается готовый видеофайл, публичная часть играет его |
| Q9 | Место действия сцены | **(A)** оператор размечает вручную из справочника локаций сериала |
| Q10 | Откуда картинки кадров | **(B)** сохранять уменьшённые превью всех кадров 135×75 (≈17,5 ГБ на весь архив) |
| Д-6 | Объём редактора в срезе | **полный редактор** как в legacy: split/union границ, рисование лица мышью, drag&drop миниатюры на персону, метки «эталон» |
| Д-7 | План или сцена | **две сущности**: сцена состоит из планов (план = непрерывный диапазон кадров) |
| Д-8 | Где хранить результаты | **превью и промежуточные файлы — на SSD, готовые видеофайлы — на HDD** |
| Р-01 | Точность нарезки «до кадра» | **(а)** границы хранятся точно (номер кадра — источник правды); выходной файл — stream-copy склейка, округление до GOP на стыках **допускается как осознанное решение**; lossless-мастер и перекодирование не делаются |
| Р-02 | Сохраняемые фильтры | **Входят полностью, с переиспользованием**: три уровня с И/ИЛИ, сохранение под именем, повторное применение, редактирование, удаление. Обязательно **один универсальный исполнитель**, а не N запросов под каждую пару классов |
| Р-03 | Размер плана внутри сцены | **Автоматически, из доли кадра, которую занимает лицо.** Справочник `ShotTypeSize` (NONE, ECU, BCU, CU, MCU, MS, MLS, LS, VLS, XLS) переносится как есть; пороги подбираются замером на тестовой серии. Оператор может поправить вручную (следствие Д-6). Агрегация по плану — **самое крупное лицо**; план без лиц = `NONE` |
| Р-04 | Версии модели распознавания | **История версий с откатом.** Каждое обучение — новая версия (дата, число эталонов, состав классов); у каждого распознанного лица хранится версия, которой оно опознано. Откат = возврат к предыдущей версии с переобучением |

**Предупреждение по Д-6.** Решение «полный редактор» заметно расширяет первый
вертикальный срез: 4 механики ручной правки, цветовая семантика оверлеев
(красный = алгоритм, зелёный = оператор, оранжевый = отменено, голубой = I-кадр)
и автосохранение без кнопки «Сохранить». Резать это на части можно **только
словом владельца**.

**Следствие Р-01.** Из бюджета проекта выпадает перекодирование целиком:
нет lossless-мастера, нет перекодирования выбранных сцен, нет спорной цифры
«перекодирование дорого». Выход сборки — `concat` со `-c copy`, контейнер MP4,
одна аудиодорожка. Фактическая длительность выборки может отличаться от
расчётной на сумму округлений GOP — интерфейсу показывать обе.

**Решает лид (технические, рекомендация ниже — в спеку):**

Технические развилки **закрыты лидом 2026-10-02** — владельцу не требуют
подтверждения, но и резать их без его слова нельзя:

- **Р-05. Детектор границ сцен: ffmpeg `scdet`.** Замер: 162 с на серию против
  157 с чистого декодирования, то есть почти бесплатно. В legacy детектором был
  Sikuli (GUI-автоматизация Windows), вторая ветка детекта мёртва — переносить
  нечего. Внешний инструмент (PySceneDetect) избыточен.
- **Р-06. Границы в БД: номер кадра — единственный источник правды**, время
  (PTS) — производное, `time_base` на уровне серии. Защищает от разного fps
  внутри одного фильма.
- **Р-07. Таблица кадров — только значимые кадры** (внутри сцен, с лицами,
  границы планов), не все 82 834. Превью лежат в MinIO файлами (Q10=B).
- **Р-08. Типизированные колонки под горячие поля** (место действия, тип и
  размер плана, персоны), EAV — на хвост. В legacy EAV без FK, с ручным
  удалением и фильтрацией строго на равенство — для горячих полей это дорого.
- **Р-09. Эмбеддинги лиц: Postgres `float4[]`**, отдельная таблица
  `face_embedding`. В legacy — строка `"a|b|c"`, в SQL не фильтруется.
- **Р-10. Идемпотентность артефактов:** хеш входных параметров (разрешение,
  кодек, версия алгоритма) + атомарная запись через временный файл +
  **обязательная проверка кода возврата** подпроцесса. В legacy нарушено во
  **всех 12** вызовах ffmpeg: упавший процесс помечался как «сделано».
- **Р-11. Пользовательские правки не перезаписываются анализом:** «сырой»
  результат хранится отдельно от правок оператора. В legacy повторный
  `AnalyzeFrames` затирал ручные метки.
- **Р-12. Неопознанные лица — заглушка-персонаж** (`UNDEFINDED`, `NONPERSON`),
  как в legacy: нужна для отчёта «кто в сцене». `nullable person_id` отклонён.
- **Р-13. Параллелизм очереди** — ограничение по числу заданий на 36 ядрах;
  GPU-очередь общая и сериализованная (одна карта).
- **Р-14. Выход сборки: MP4, одна аудиодорожка**, без перекодирования (следствие
  Р-01).

Исходные формулировки развилок (до решений):

- **Р-05.** Детектор границ сцен: ffmpeg `scdet`/`select=gt(scene,…)` — по измерению 162 с на серию, отдельного
   прохода почти не добавляет; (б) PySceneDetect-подобный внешний инструмент;
   (в) перенести Sikuli-подход — **не вариант**, он Windows-only и O(n).
