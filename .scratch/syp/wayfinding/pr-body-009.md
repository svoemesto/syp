## Две правки по вашим решениям

### 1. Верные числа по замеру, а не по памяти

Замер `ffprobe` по всем 73 файлам архива:

| Что | Было | Стало |
|---|---|---|
| S01E01 | 82 834 кадра | **88 644** |
| Средняя серия | — | **82 769** |
| Архив | 69,1 ч / 5,96 млн | **70,00 ч / 6 042 173** |

Прежние 82 834 — это **среднее по архиву**, ошибочно поданное как число кадров первой серии. Ошибка была в памяти проекта и разошлась по расчётам.

- **`spec.md`** — исправлены SC-001, допущения и границы среза.
- **ADR-0002 и ADR-0009** — текст **не правится** (ADR неизменяем по конституции), исправленный факт зафиксирован примечанием с датой. Это ваш выбор: «править спеку, в ADR добавить примечание».

### 2. Кэш сверки сумм

Вы выбрали: **полная сверка `sha256` при первом запуске**, при повторных — сверка по признакам «размер + время изменения» с кэшем.

Причина, по которой это было предметом решения: подборка из десяти серий — это 56 ГБ чтения, то есть минуты ожидания **до начала работы**, что прямо конфликтует с SC-004.

- **FR-089g** в спецификации: полная сверка при первом запуске; при повторных — сверка по размеру и дате.
- **ADR-0009** дополнен уточнением решения с описанием размена.

## Что этот кэш не ловит — записано явно

Подмена файла с **сохранением размера и времени изменения** останется незамеченной. Это осознанный размен: быстрота повторных запусков в обмен на узкий класс подмены, вероятный только при намеренной подмене с сохранением метаданных.

Дополнительно FR-089g обязывает воркер **показывать пользователю, по какому признаку файл признан совпадающим** — чтобы выбор был виден, а не спрятан внутри реализации.
