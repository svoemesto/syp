## Почему нет кнопки Approve — разобрано до причины

**Это не поломка настройки.** Две независимые причины:

### 1. GitHub запрещает автору одобрять свой PR

PR #3 создан через `gh` под аккаунтом `svoemesto`. Значит, автор PR — владелец,
а GitHub не даёт approve собственному PR: кнопки просто нет в интерфейсе.

При одном аккаунте и одном человеке требование «требуется одно одобрение»
невыполнимо в принципе.

**Решение владельца (2026-10-02): снять требование одобрения.**

### 2. Агент не может снять это сам — нет scope `administration`

```
Token scopes: 'gist', 'read:org', 'repo', 'workflow'
Permissions on repo: admin, maintain, pull, push, triage
```

Прав на репозиторий полные (`admin: true`), но правка branch protection требует
scope `administration`, которого у токена нет. `PATCH /branches/master/protection`
отвечает `404 Not Found` — GitHub маскирует недостаток scope под 404.

### Что нужно сделать (любой один способ)

**Способ 1 — расширить scope токена** (нужен браузер, выполняет владелец):

```bash
gh auth refresh -h github.com -s administration
```

**Способ 2 — снять гейт вручную в интерфейсе GitHub:**

`Settings -> Branches -> master -> Edit` → снять «Require a pull request
before merging» или поставить число одобрений `0` → сохранить.

Оба способа сохраняют остальную защиту: push в `master` по-прежнему запрещён,
изменения только через запрос на слияние, force push и удаление ветки запрещены.

### Чего я сознательно не делаю

Слияние через `--admin` — владелец отверг этот вариант как обесценивание
правила. Пока не сказано иначе, гейт не обхожу.

### Ожидаемая цепочка после снятия требования

1. Слить PR #3 (living docs).
2. Зарезервировать номер ветки под план: `./tools/reserve-branch-number.sh speckit-plan`.
3. Создать отдельный worktree (Rule VII.3 — субагенты в изоляции).
4. Запустить долгоживущего субагента на `speckit-plan` по одобренной спеке.
