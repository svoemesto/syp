# Контракт: HTTP API публичной части (`syp-public-app`)

**Feature**: 001-first-vertical-slice
**Потребитель**: `syp-public-web` (Vue 3) и только он.
**Транспорт**: HTTP/1.1, JSON, префикс `/api`. Аутентификации в первый срез
нет — стек локальный, публикация в интернет не планируется.
**Документация**: каждый публичный метод документирован, ссылка на этот файл
обязательна (FR-100). Per-feature документ —
[`../../../../docs/features/first-vertical-slice.md`](../../../docs/features/first-vertical-slice.md) (FR-101).

## 1. Граница ответственности

Публичная часть **применяет фильтр, даёт выбрать сцены и отдаёт уже выданный
сценарий сборки** — файл, подпись и открытый ключ проверки. Здесь нет разметки,
обучения моделей, справочника локаций, настроек и — отдельно подчёркнуто —
**нет видео**: ни отдачи, ни приёма, ни хранения
(`docs/domains/showcase/domain.md`, инварианты 2 и 3; ADR-0009).

**Создания сценария здесь нет.** Генерация и подпись выполняются в админском
бэкенде, где живёт закрытый ключ подписи; публичная часть только читает уже
подписанное и хранимое (ADR-0014, решение владельца 2026-10-03).

| Есть в публичной части | Нет в публичной части |
|---|---|
| список сериалов | создание и правка сериалов |
| список и применение сохранённых фильтров | редактор дерева условий |
| выбор сцен | доводка границ, отмена решений алгоритма |
| чтение состава сценария и его скачивание | **создание и подпись сценария** |
| отзыв открытого ключа проверки | обучение и версии моделей |
| — | рисование лиц, назначение персон |
| — | операторские задания любого вида |
| — | **видеофайлы: отдача, приём, хранение** |
| — | **исполнитель заданий** |
| — | **закрытый ключ подписи** |

Аутентификации нет, поэтому «нет в публичной части» обеспечивается
**отсутствием эндпоинта**, а не проверкой прав: эндпоинта, которого нет, вызвать
нельзя. То же касается исполнителя заданий: у публичного бэкенда его нет вовсе
(`research.md` Т-20), и то же касается закрытого ключа подписи — переменная
`SYP_SIGNING_PRIVATE_KEY` контейнеру публичной части не передаётся, а класс
ответа с ключом проверки закрытой половины не содержит по построению
(ADR-0011, ADR-0014).

## 2. Общие правила

Коды ответов, формат тела ошибки, пагинация и нумерация кадров — общие с
админкой и описаны в [`admin-api.md`](admin-api.md), раздел 1. Здесь действуют
те же правила.

Специфичных кодов ошибок у этого контейнера нет: отказы проверок перед выдачей
(`EMPTY_SELECTION`, `EPISODE_NOT_ANALYZED`, `INCOMPATIBLE_EPISODE`,
`CHECKSUM_NOT_READY`, `SOURCE_UNREADABLE`) относятся к моменту **создания**
сценария и потому перенесены в
[`admin-api.md`](admin-api.md) разделы 2 и 10.1 вместе с самой выдачей
(ADR-0014). Здесь отказ возможен только на чтении: сценария нет (`404`,
`NOT_FOUND`) либо он не подписан и не готов к выдаче (`409`, `CONFLICT`).

## 3. Сериалы и фильтры

| Метод | Путь | Назначение | FR |
|---|---|---|---|
| `GET` | `/api/serials` | сериалы, у которых есть размеченные данные | FR-084 |
| `GET` | `/api/serials/{movieId}/filters` | сохранённые фильтры: имя, условие, число подходящих сцен | FR-084 |
| `POST` | `/api/filters/{filterId}/apply` | применить фильтр, получить список сцен | FR-071, FR-084 |
| `GET` | `/api/filters/{filterId}/scenes` | сцены по фильтру: серия, границы, планы, персонажи, место действия | FR-084 |
| `GET` | `/api/series/{episodeId}/scenes/{sceneId}/preview` | превью сцены для выбора | FR-084 |

Пользователь видит **условие фильтра текстом**, а не деревом: «Джейми
Ланистер, крупный план, место действия — Лагерь Джейми». Формулировка
собирается на бэкенде из того же дерева, по которому фильтр исполняется, —
расхождение между надписью и результатом невозможно по построению.

Тело `POST /api/filters/{filterId}/apply`:

```json
{
  "filterName": "Джейми в лагере, крупно",
  "formula": "персона «Джейми Ланистер» И место действия «Лагерь Джейми» И размер плана один из CU, BCU",
  "sceneCount": 37,
  "totalDurationMs": 412000
}
```

## 4. Чтение сценария сборки

Сценарий здесь **не создаётся**: он выдан админским бэкендом, подписан там же и
хранится как есть. Публичная часть отдаёт файл, подпись и открытый ключ
проверки (ADR-0014, решение владельца 2026-10-03). Эндпоинта `POST` в этом
разделе нет, и его отсутствие проверяется guard, а не договорённостью.

| Метод | Путь | Назначение | FR |
|---|---|---|---|
| `GET` | `/api/recipes` | сценарии сериала: имя, состояние, число фрагментов, ожидаемая длительность, признак устаревания | FR-084 |
| `GET` | `/api/recipes/{recipeId}` | сценарий: состав фрагментов, ожидаемые величины, суммы | FR-084, FR-083 |
| `GET` | `/api/recipes/{recipeId}/file` | **файл сценария** — то, что пользователь кладёт в папку | FR-080, FR-089b, FR-089f |
| `GET` | `/api/recipes/{recipeId}/signature` | подпись и сумма содержимого для проверки | FR-089c |
| `GET` | `/api/recipes/verification-key` | открытый ключ проверки и его идентификатор | FR-089c |

Признак `isStale` означает, что сценарий создан при другой версии формата
(FR-090). Он **не запрещает** скачивание: файл, подпись и идентификатор ключа
остаются прежними, и ранее выданный сценарий проверяем по своему ключу, пока
тот в списке доверенных.

### 4.1 Как сценарий появляется у пользователя

Пользователь открывает сериал, применяет фильтр, отмечает сцены и видит
сценарии, уже выданные админкой, — со всем, что нужно для проверки: подпись,
сумма содержимого и открытый ключ. Создание сценария в публичной части
отсутствует, и это следствие ADR-0014: подпись ставится там, где живёт закрытый
ключ, то есть в админском бэкенде.

Проверки, которые выполняются **до** создания сценария, — пустой список, разбор
серий, совместимость серий и наличие актуальных эталонных сумм, — относятся к
выдаче и потому живут в
[`admin-api.md`](admin-api.md) § 10.1, а не здесь. Формат отказа не расходится:
те же машинные коды, тот же текст по-русски, тот же перечень проблемных
объектов.

### 4.2 Скачивание файла сценария

`GET /api/recipes/{recipeId}/file` отдаёт **файл сценария** в канонической
форме: `application/json`, имя файла
`<имя-сценария>.syp-recipe.json` в заголовке `Content-Disposition`.

Это единственный способ получить сценарий. **Доставка ручная**: пользователь
сохраняет файл браузером и сам кладёт его в папку, которую наблюдает воркер
(решение владельца 2026-10-02). Автоматической доставки, ссылок с подпиской,
автообновления и докачивания в срезе нет.

Отдаётся **только** артефакт в состоянии `READY`: незавершённый файл не
считается готовым (FR-091). Сценарий в состоянии не `DONE` отдаётся с кодом
`409`.

### 4.3 Подпись и ключ

`GET /api/recipes/{recipeId}/signature`:

```json
{
  "recipeId": 55,
  "contentSha256": "9f2c…",
  "algorithm": "Ed25519",
  "signingKeyId": "syp-2026-10",
  "signature": "Base64…"
}
```

`GET /api/recipes/verification-key`:

```json
{
  "keyId": "syp-2026-10",
  "algorithm": "Ed25519",
  "publicKeyPem": "-----BEGIN PUBLIC KEY-----\n…\n-----END PUBLIC KEY-----\n",
  "notBefore": "2026-10-02T00:00:00Z"
}
```

Ключ нужен воркеру для проверки **до** выполнения сценария (FR-089c). В первом
срезе ключ кладётся в файл настроек воркера; если ключ не задан, воркер
предупреждает и работает в режиме получения ключа при первом запуске, о чём
пишет в журнал (`research.md` Т-26).

### 4.4 Состав сценария

`GET /api/recipes/{recipeId}` — то, что показывается пользователю перед
скачиванием: что войдёт в подборку и чем реальная сборка отличается от
расчётной (FR-082, FR-083).

```json
{
  "recipeId": 55,
  "state": "DONE",
  "schemaVersion": 1,
  "isStale": false,
  "itemCount": 2,
  "expectedDurationMs": 412000,
  "expectedFrameCount": 9876,
  "items": [
    {
      "ordinal": 1,
      "sceneId": 1,
      "episodeId": 7,
      "episodeName": "GOT.S01E01",
      "relativePath": "GOT.S01/GOT.S01E01.BDRip.1080p.mkv",
      "sourceSha256": "3f786850…",
      "firstFrame": 1200,
      "lastFrame": 1455,
      "cutFirstFrame": 1188,
      "cutLastFrame": 1460,
      "title": "Джейми у ворот",
      "location": "Лагерь Джейми",
      "persons": ["Джейми Ланистер"]
    }
  ]
}
```

`cutFirstFrame` отличается от `firstFrame`, когда граница округлилась до
ключевого кадра: ровно то расхождение, которое ADR-0006 разрешает и которое
объясняется пользователю заранее, а не после работы.

Значения `title`, `tbl_locations` и `persons` — **снимки строк на момент выдачи**, а
не ссылки: правка справочника после выдачи не «слепит» уже скачанный сценарий,
а локальный показ работает без сервера (FR-089d). Поле `title` может быть
пустым — у сцены названия может не быть.

## 5. Устойчивость цикла

Требования SC-007, SC-011 проверяются этим циклом целиком:

1. пользователь открывает сериал и видит сохранённые фильтры;
2. применяет фильтр одним действием и получает список сцен (SC-007);
3. отмечает сцены и видит сценарии, выданные админкой по его подборке;
4. снимает сценарий по адресу файла и кладёт у себя;
5. **ни один байт видео не передан и не сохранён на сервере** (SC-011):
   по сети ушли только метаданные и текст сценария.

Перезагрузка страницы ничего не теряет: сценарий — ресурс с адресом,
а не состояние вкладки.

**SC-010 требует решения владельца.** Критерий «пользователь без участия
оператора получает подборку» и решение ADR-0014 «сценарий выдаёт админка»
расходятся: без аутентификации обе точки входа равноправны, но экран выдачи
сценария живёт в админской части, а не в публичной. Критерий не переписывается
агентом — спецификация есть контракт (constitution IX.4). Расхождение записано
в `tasks.md` и ждёт решения.

## 6. Что в контракт не входит

- Разметка, доводка, обучение, настройки — по разделу 1.
- **Создание и подпись сценария** — ADR-0014: подпись выполняется там, где
  живёт закрытый ключ, то есть в админском бэкенде
  ([`admin-api.md`](admin-api.md) § 10.1). Здесь нет ни эндпоинта `POST`, ни
  закрытого ключа.
- **Отдача, приём и хранение видеофайлов** — FR-088 и ADR-0009 запрещают.
  В этом контракте нет ни одного эндпоинта с содержимым видео.
- **Воспроизведение собранного файла на сайте** — файл собирается и смотрится
  на машине пользователя (FR-089d, FR-089e).
- **Автоматическая доставка сценария** — решение владельца 2026-10-02: файл
  пользователь скачивает и кладёт сам.
- Отчёт о выполнении сценария серверу **не возвращается**: он остаётся у
  пользователя (FR-089e).
- Рекомендации и подборки «похожих сцен» — вне объёма.
