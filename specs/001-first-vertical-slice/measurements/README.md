# Отчёты по замерам первого вертикального среза

## Зачем этот каталог

Часть требований проекта — не «сделать», а «померится и подтвердить числом»:
SC-001 (одна рабочая смена), SC-004 (пять минут на сборку), SC-003 (95 %
принятых границ), SC-012 (ноль сценариев при несовпадении суммы). Пока рядом
с требованием нет отчёта о замере с указанием числа, требование считается
незакрытым, даже если код написан.

Каталог создан задачей **T017**. Отчёты пишутся по мере выполнения замеров;
пустой каталог с этим README означает «замеры ещё не выполнялись», а не
«замеры не нужны».

## Форма отчёта

Каждый отчёт — отдельный файл `М-NN-<что-мерили>.md` с четырьмя
обязательными разделами. Отчёт, в котором нет числа, — не отчёт.

| Раздел | Что в нём должно быть |
|---|---|
| **Что мерили** | Формулировка вопроса одним предложением. Не «проверить производительность», а «сколько секунд занимает подсчёт `sha256` файла 5,6 ГБ с отчётом прогресса». |
| **На чём мерили** | Машина, образ контейнера, версии программ, тестовая серия и её характеристики, число прогонов. Замер из песочницы агента помечается отдельно: `ffmpeg` там обрывается `signal 9` на длинных операциях, и такой результат недействителен. |
| **Какое число получили** | Само число, единица измерения, разброс по прогонам. «Примерно быстро» числом не является. |
| **Каким критерием проверяется** | Ссылка на требование или критерий (`SC-003`, `FR-089`, Т-14 плана) и явный вывод: выполнено или нет. |

Дополнительно, если замер даёт неожиданный результат: **что это означает для
плана**. Замер, из которого нельзя сделать вывод, половина работы.

## Тестовая серия

Все замеры идут на `GOT.S01E01` — по измерениям 1920×1080, 23,976 fps
(24000/1001), 3697,2 с, **88 643 кадра**, 5 598 286 865 байт. Полный архив —
73 файла, 70,00 ч, 6 042 173 кадра — цель следующих спринтов и в срез не
входит.

## Уже измеренные бюджеты

Эти числа получены до написания спеки, служат ориентиром и **не заменяют**
замеры М-01…М-13: они сделаны в других условиях, часть — в песочнице агента.

| Что | Значение |
|---|---|
| Декодирование всей серии | 157 с |
| Детекция границ `scdet` | 162 с |
| Извлечение всех 88 643 кадров 1080p JPEG | около 3 мин (462 кадра/с) |
| Нарезка фрагмента 30 с потоковым копированием | 0,55 с |
| Склейка 100 фрагментов (715 МБ) | 7,47 с |

Замеры перекодирования **не подтверждены**: `ffmpeg` в песочнице агента
убивается `signal 9`, файл выходит оборванным. Подтверждено при этом, что
потоковое копирование округляет границу до ключевого кадра (730 кадров вместо
719) — это и есть осознанное решение владельца (ADR-0006), а не дефект.

## Правила замера

1. **Замер из песочницы агента не объявляется надёжным.** Видео-часть пайплайна
   меряется в контейнере; в песочнице `ffmpeg` обрывается на длинных
   операциях.
2. **GPU в песочнице не видна.** Замеры с видеокартой идут через контейнер.
3. **Контейнеры SYP не создаются и не перезапускаются ради замера.**
   Используется одноразовый контейнер, который после замера удаляется.
4. **Число без повторов — мнение.** Минимум три прогона, в отчёте — разброс.
5. **Вывод обязателен.** «Быстро» и «нормально» закрывают не требование.
