# М-11: скорость подсчёта `sha256` исходника

**Задача**: T045. **Дата замера**: 2026-10-04. **Эпизод**: `GOT.S01E01`.

## Что мерили

Сколько времени занимает подсчёт суммы `sha256` файла эпизода 5,6 ГБ с отчётом
прогресса по прочитанным байтам, и совпадает ли посчитанная сумма с тем, что
даёт внешняя программа `sha256sum`.

## На чём мерили

| Что | Значение |
|---|---|
| Файл | `/disks/HDD_16Tb_Clouds/GOT/GOT.S01/GOT.S01E01.BDRip.1080p.mkv` |
| Размер | 5 598 286 865 байт |
| Путь работы | настоящий: постановка задания → воркер → исполнитель `HASH` → запись в справочник сумм. Обхода воркера в проверке нет |
| Внешняя сверка | `sha256sum` из системы — та же программа, которой воспользуется воркер на машине пользователя |
| База | одноразовый контейнер `postgres:16`, миграции `01…10`, контейнер удалён после прогона |
| Скрипт | `bash tools/run-checksum-parity.sh` |
| Число прогонов подсчёта | **3**, плюс один прогон определения параметров эпизода |
| Параллелизм | один поток чтения, 4 Миб за раз, прогресс каждые 64 Миб |

**Прогон на агентской машине, а не в контейнере `syp-admin-app`.** Оговорка
README измерений про песочницу агента относится к `ffmpeg` на длинных
операциях: здесь ни ffmpeg, ни декодирование не участвуют — только чтение
файла и вычисление суммы. Одновременно замерено время определения параметров
эпизода (61,3 с): оно совпадает с ранее измеренными 20 с на счётчик пакетов и
35 с на ключевые кадры, что подтверждает, что машина ведёт себя обычно.

## Какое число получили

| Прогон | Время, с | Скорость, МБ/с | Сумма |
|---|---|---|---|
| 1 | 31,82 | 167,7 | `2aae05bd…f5e315` |
| 2 | 32,33 | 165,1 | `2aae05bd…f5e315` |
| 3 | 31,84 | 167,7 | `2aae05bd…f5e315` |
| **Среднее** | **32,00** | **166,9** | — |

Разброс: от 31,82 до 32,33 с, то есть 0,51 с (1,6 % от среднего). На таком
разбросе и построен вывод.

Полная сумма, посчитанная системой:

```
2aae05bd7dc490bfce1f157b3a32f3bd23640c7557e43dab53b119bf88f5e315
```

Она совпала:

- с выводом `sha256sum` того же файла;
- со строкой 1 эталона целостности `docs/serial/GOT.sha256`.

Три независимых источника дали одно значение: система считает то, что
ожидает машина пользователя.

### Прогноз на архив

При измеренных 166,9 МБ/с чтение 360 ГБ архива заняло бы 360 · 1024 / 166,9
= **2209 с, около 36,8 минуты**.

Это число **не переносится на архив как есть**: файл 5,6 ГБ помещается в
кэш страниц, а 360 ГБ — нет. Отдельный замер владельца на всей машине дал
**44 минуты при 135 МБ/с**, и 360 · 1024 / 135 = 45,5 минуты — то есть его
число внутренне непротиворечиво. Реалистичной для плана считается цифра
владельца: **около 44 минут на весь архив**.

## Каким критерием проверяется

- **Задача T045**: сумма из системы совпадает с `sha256sum` файла; замерено
  время чтения и подсчёта на файле 5,6 ГБ.
- **М-11**: время видно прогрессом задания и не блокирует интерфейс.
- **FR-003**: прогресс задания наблюдаем.
- **SC-012**: сумма та, по которой машина пользователя проверит файл.

**Вывод: выполнено.** Сумма совпала с внешней и с эталоном проекта; время
подсчёта измерено тремя прогонами; интерфейс не блокируется — работа идёт
заданием, а прогресс пишется по прочитанным байтам.

## Что это означает для плана

1. **Подсчёт суммы не мешает работе оператора.** 32 секунды на файл 5,6 ГБ,
   три прогона подряд — сумма считается быстрее, чем оператор успевает
   посмотреть на страницу.
2. **Скорость упирается в диск, а не в вычисления.** 166,9 МБ/с на одном
   потоке — это скорость чтения массива; SHA-256 на ядре быстрее. Ускорение
   возможно параллельным чтением, но тогда нужны замеры под нагрузкой, а не
   догадки.
3. **Полный архив считается один раз при приёме.** При регистрации 73 эпизодов
   суммы считаются автоматически (FR-089); при 44 минутах суммарно это
   меньше часа работы в фоне, и оператор в это время занимается разметкой.
4. **Историю пересчётов нужно беречь.** Файл 5,6 ГБ читается за полминуты,
   поэтому лишний пересчёт дёшев по времени — но он создаёт новую запись
   справочника, и прежняя помечается устаревшей. Частые пересчёты без
   изменения файла дают историю без смысла.

## Как повторить

```bash
bash tools/run-checksum-parity.sh
bash tools/run-checksum-parity.sh /path/to/episodes.mkv   # свой файл
```

Скрипт поднимает одноразовый `postgres:16`, применяет миграции, гоняет
задание `HASH` три раза и сверяет результат с `sha256sum`. Контейнер SYP при
этом не создаётся и не трогается.
