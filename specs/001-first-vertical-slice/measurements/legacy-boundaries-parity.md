# Сверка эталона границ старого проекта: непрерывность

**Задача**: T039. **Дата замера**: 2026-10-04.

## Что мерили

Разбирается ли выгрузка старого проекта (iGOT) в нашу модель планов без
потерь, и — главное — покрывают ли планы эпизод **без разрывов и без
перекрытий**. Непрерывность здесь не украшение: без неё у плана «нет
соседа», а правило «план лежит в сцене целиком» (ADR-0007) считается по
диапазонам кадров и требует, чтобы диапазоны смыкались.

## На чём мерили

| Что | Значение |
|---|---|
| Выгрузка | `/home/nsa/syp/.data/legacy-iGOT`, **вне репозитория** (около гигабайта, `AGENTS.md` § «Внешние источники знаний») |
| Файлы | `InputFiles/*_Segments.csv`, 73 файла, разделитель `;`, кодировка UTF-8 с BOM |
| Эпизод подробного разбора | `GOT.S1E1` (файл `GOT.S01E01.BDRip.1080p.mkv`) |
| Скрипт | `.scratch/syp/legacy-import/verify-legacy.py`, отчёт `verify-legacy-report.json` |
| Происхождение скрипта | прототип `import-s1e1.py`, дополненный разбором всех 73 эпизодов |
| Число прогонов | один; разбор детерминированный, повторов не требует |

В репозиторий переносится **только этот отчёт**. Данные выгрузки остаются
в `.data/` — они не в git и не должны туда попасть.

|---|---|
| Планов (сегментов legacy) | **1028** |
| Разрывов | **0** |
| Перекрытий | **0** |
| Покрытие | с кадра **1** по кадр **88 643** |

Нумерация кадров в legacy **с единицы**, в SYP — с нуля (`research.md` Т-12).
Поэтому покрытие 1…88 643 в legacy соответствует покрытию 0…88 642 в SYP:
это одна и тот же эпизод из 88 643 кадров. Сегменты ложатся в модель планов
напрямую, пересчёт не нужен: сдвиг на единицу задаётся один раз при импорте.

## Каким критерием проверяется

- **Задача T039**: 1028 планов S1E1, 0 разрывов и 0 перекрытий, покрытие от 1
  до 88 643; по всему архиву — 71 005 сегментов на 73 эпизоде.
- **FR-011**: планы образуют непересекающееся покрытие эпизода.
- **ADR-0007**: план лежит в сцене целиком; связь вычисляется по диапазонам.

**Вывод: выполнено.** Эталон границ старого проекта подтверждён на тестовом
эпизоде и на всём архиве: покрытие сплошное, ни разрывов, ни перекрытий нет ни
на одном из 73 эпизодов.

## Что это означает для плана

1. **Импорт эталонов возможен и нужен.** Сегменты legacy — это готовые
   границы планов; на тестовом эпизоде они покрывают её целиком. Их можно
   загрузить в систему как эталон и сверять с результатом автоматики, не
   дожидаясь детектора (это и есть роль эталонных данных в критерии SC-003).
2. **Проверка непрерывности должна быть встроена в импорт.** Ноль разрывов —
   результат, а не предпосылка: проверка обязана отклонять выгрузку, где
   план кончается и следующий начинается не с него же. Сейчас это свойство
   данных, а не кода.
3. **Разброс длин планов задаёт ожидания для М-03.** Медиана 60 кадров при
   максимуме 1526 — на два порядка. Детектор, дающий границы с разбросом
   меньше, чем медиана плана, не может быть настроен правильно: пороги
   подбираются по этому распределению, а не «на глаз».
4. **Перенос данных в репозиторий не производится.** Около гигабайта CSV в
   git не помещается по смыслу: переносится отчёт, а не выгрузка.

## Как повторить

```bash
python3 .scratch/syp/legacy-import/verify-legacy.py
```

Скрипт читает выгрузку из `/home/nsa/syp/.data/legacy-iGOT`. Без неё
завершается ошибкой открытия файла, а не «пустым успехом».
