# Сверка признаков кадров с эталоном старого проекта

**Задача**: T040. **Дата замера**: 2026-10-04. **Серия**: `GOT.S1E1`.

## Что мерили

Совпадает ли признак «это ключевой кадр» из нашей карты ключевых кадров с
признаком `isIFrame` старого проекта, и что означают остальные признаки
legacy для настройки детектора границ и оценки объёма ручной правки.

Проверка на совпадение **по множеству номеров кадров**, а не по числу: две
карты, обе из 792 кадров, могут отличаться расположением, и это разные
факты о файле.

## На чём мерили

| Что | Значение |
|---|---|
| Выгрузка признаков | `/home/nsa/syp/.data/legacy-iGOT/InputFiles/GOT.S1E1_Frames.csv`, **вне репозитория** |
| Столбцы | `frameUUID`, `frameNumber`, `isIFrame`, `isFind`, `isManualAdd`, `isManualCancel`, `isFinalFind`, оценки подобия и разностей |
| Наша карта | `KeyframeMap` серии, заполненная опросом файла (`ffprobe -skip_frame nokey`) и записанная в базу как `series.keyframe_bitmap` |
| Сверка | `.scratch/syp/legacy-import/verify-legacy.py`, отчёт `verify-legacy-report.json` |
| Число прогонов | один; разбор детерминированный |

## Какое число получили

### Признаки кадров S1E1

| Признак legacy | Строк | Что это в нашей модели |
|---|---|---|
| Всего строк | **88 643** | полная таблица кадров, которой у нас **нет** и не будет (Р-07) |
| `isIFrame` | **792** | сверяется с картой ключевых кадров серии |
| `isFind` | **1040** | кадры, на которых автоматика предложила границу |
| `isFinalFind` | **1027** | границы, принятые человеком |
| `isManualAdd` | **13** | границы, добавленные вручную сверх автоматики |
| `isManualCancel` | **26** | предложения автоматики, отменённые человеком |

Номера кадров в файле идут подряд с 1 по 88 643 — пропусков нет, что
согласуется с числом кадров, полученным счётчиком пакетов.

### Сверка карты ключевых кадров

| Величина | Значение |
|---|---|
| Ключевых кадров в карте системы | **792** |
| `isIFrame` в legacy | **792** |
| Множества номеров совпадают | **да, полностью** |
| Ключевых кадров только у нас | 0 |
| Ключевых кадров только в legacy | 0 |

Первые пять номеров у обеих сторон: 0, 240, 480, 720, 957. Последние три:
88 474, 88 498, 88 522. Карта занимает **11 081 байт** — ровно
`ceil(88643 / 8)`, тогда как таблица кадров заняла бы 88 643 строки.

### Соотношения, важные для настройки

| Соотношение | Значение | Что из него следует |
|---|---|---|
| `isFind` и `isFinalFind` одновременно | 1014 | предложено и принято |
| `isFind` без `isFinalFind` | **26** | столько же, сколько `isManualCancel` — это одни и те же кадры: человек отменил предложение |
| `isFinalFind` к числу планов | 1027 / 1028 = **99,9 %** | почти каждая граница автоматики была принята без правки |
| `isManualAdd` к числу планов | 13 / 1028 = **1,3 %** | объём добавленной вручную работы ничтожен |
| `isManualAdd` + `isManualCancel` | **39** кадров | полный объём ручной правки на 88 643 кадра |

Число 39 — самый полезный результат этого замера: на тестовой серии ручная
правка границ заняла бы **менее половины процента** кадров. Требование SC-003
(не менее 95 % принятых границ) эталоном выполняется с большим запасом.

## Каким критерием проверяется

- **Задача T040**: 792 `is_iframe` против числа битов в карте ключевых кадров,
  1040 `is_find` и 1027 `is_final_find` как ориентир для доли принятых
  границ, 13 `manual_add` и 26 `manual_cancel` как ориентир для объёма
  ручной правки.
- **Задача T032** (выполнена ранее): 792 установленных бита на `GOT.S01E01`.
- **FR-023**: признаки кадров доступны интерфейсу.
- **Р-07**: полной таблицы кадров на 88 643 строки нет.

**Вывод: выполнено.** Карта ключевых кадров совпала с эталоном не только по
числу, но и по множеству номеров; остальные признаки сняты и дают ориентир
для порогов и для оценки ручной работы.

## Что это означает для плана

1. **Карта ключевых кадров верифицирована.** Это единственный признак, который
   можно сверить точно, и он совпал. Расхождение было бы признаком ошибки в
   переводе отметок времени в номера кадров (ADR-0001), а такой ошибки нет.
2. **Ручная правка границ — не объём, а инструмент.** 39 кадров на 88 643:
   полный редактор нужен для единичных случаев, а не как основной способ
   разметки. Это согласуется с решением владельца Д-6 и не опровергает его.
3. **`isFind` и `isFinalFind` — прямой ориентир для М-03.** Отношение
   1027/1040 = 98,8 % показывает, что на этой серии предложения автоматики
   принимались почти всегда. Пороги, дающие долю принятых ниже этого,
   хуже того, что делал старый проект.
4. **Два разных механизма в одном столбце.** `isFind` без `isFinalFind`
   ровно 26 — столько же, сколько `isManualCancel`. Значит отмена
   предложения автоматики в старом проекте была выражена снятием признака
   принятия, а не отдельным состоянием. В нашей модели это два разных поля
   (`origin = CANCELLED` у сцены и плана, FR-016) — так точнее, и это надо
   учесть при импорте: отменённая граница не «исчезает», а помечается.

## Как повторить

```bash
python3 .scratch/syp/legacy-import/verify-legacy.py
```

Для сверки карты ключевых кадров скрипт читает выгрузку отметок времени из
`/tmp/kf-s1e1.csv` (её получают проходом `ffprobe -skip_frame nokey`). Без
файла раздел сверки помечается ошибкой, а не пустым результатом.
