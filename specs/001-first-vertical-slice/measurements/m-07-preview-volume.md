# М-07: объём листов превью

**Задача**: T059. **Дата замера**: 2026-10-04. **Серия**: `GOT.S01E01`.

## Что мерили

Сколько места на твердотельном носителе занимают листы превью одной серии:
лист — сетка 16×16 ячеек по 135×75, то есть 256 кадров, и на 88 643 кадра
серии таких листов 347 (research.md Т-03, FR-021).

## На чём мерили

| Что | Значение |
|---|---|
| Файл | `/disks/HDD_16Tb_Clouds/GOT/GOT.S01/GOT.S01E01.BDRip.1080p.mkv` |
| Размер | 5 598 286 865 байт |
| Путь работы | настоящий: `ffmpeg` с фильтром `scale=135:75,tile=16x16` по всей серии, как это делает задание `ANALYZE` |
| Формат листа | PNG, то есть значение по умолчанию раскладки первого среза |
| Носитель | `/disks/SSD_2Tb_Files` (Д-8: превью живут на SSD) |
| Версия программы | ffmpeg 6.1.1-3ubuntu5 |
| Число прогонов | **1** полный проход по серии; плюс один проход на 256 кадров для сравнения PNG и JPEG |
| Скрипт | команды воспроизводимы в разделе «Как повторить» |

**Прогон на агентской машине, а не в контейнере `syp-admin-app`.** Оговорка
README измерений про песочницу агента относится к `ffmpeg`, обрывающемуся на
длинных операциях. Здесь операция длинная — 148 секунд, — но код завершения
проверен: `0`, и на выходе ровно 347 файлов, каждый из них открывается как
изображение. Обрыв был бы виден по числу файлов и по коду возврата, а не
остался бы незамеченным.

## Какое число получили

Полный проход по серии:

| Что | Значение |
|---|---|
| Время прохода | **148,4 с** |
| Код завершения | `0` |
| Листов получено | **347** |
| Объём на серию, PNG | **1 590 267 792 байт = 1516,6 МиБ** |
| Средний лист | 4 582 904 байт |
| Медианный лист | 4 650 606 байт |
| Минимальный лист | 20 836 байт (первый: заставка HBO почти одноцветна) |
| Максимальный лист | 6 576 145 байт |

Число листов совпало с расчётным: `⌈88 643 / 256⌉ = 347`. Сумма объёмов
меньше 347 × 4,6 МиБ, потому что первый лист почти пустой: на нём заставка.

Один и тот же лист из 256 кадров в двух форматах:

| Формат | Размер, байт | Разница |
|---|---|---|
| PNG | 1 687 076 | — |
| JPEG, `-q:v 2` | 321 797 | в **5,24 раза** меньше |

Пересчёт на весь архив из 73 серий при среднем 1516,6 МиБ на серию:

| Формат | На одну серию | На 73 серии |
|---|---|---|
| PNG | 1,48 ГиБ | **108 ГиБ** |
| JPEG `-q:v 2` | 0,31 ГиБ | **21 ГиБ** |

## Каким критерием проверяется

Критерий М-07: «объём на серию укладывается в запас SSD», и «уменьшение
качества или размера листа — параметр, а не переделка».

Свободно на `/disks/SSD_2Tb_Files` на момент замера — **609 ГиБ** из 1,8 Тиб
(занято 66 %). Одна серия занимает 1,48 ГиБ, весь архив в PNG — около 108 ГиБ,
то есть **17,8 %** свободного места.

**Вывод: критерий выполнен.** Запас SSD перекрывает архив листами превью в
формате по умолчанию с большим запасом; переходить на JPEG ради места не
обязательно.

Формат при этом действительно остаётся параметром: переключение PNG на JPEG
меняет одну настройку раскладки и одну команду сборки листа, а не модель
данных. Число выше показывает, сколько именно даёт такой переход.

## Что это означает для плана

1. **Хранить превью в исходном разрешении не нужно и не выгодно.** Превью
   135×75 на серию — это 1,48 ГиБ против 6 042 173 кадров всего архива; в
   исходном разрешении тот же объём стоил бы десятки гигабайт на серию
   (FR-024, решение владельца Q5=A, Q10=B).
2. **Формат листа стоит оставить настройкой.** Соотношение 5,24 раза между
   PNG и JPEG — это разница между «архив занимает 108 ГиБ» и «21 ГиБ». На
   машине с 609 ГиБ свободного места первый вариант проходит, но запас
   перестанет быть избыточным, если рядом появится что-то ещё крупное.
3. **Листы независимы, переделка дешёвая.** Один лист собирается за доли
   секунды (846 мс на 256 кадров, см. ниже), поэтому уменьшение размера листа
   не требует повторного прохода по серии — переделывается только нужный
   диапазон (frame-preview.md § 6).

## Как повторить

```sh
SRC=/disks/HDD_16Tb_Clouds/GOT/GOT.S01/GOT.S01E01.BDRip.1080p.mkv
OUT=/home/nsa/syp/.data/marking

# Полный проход: все листы серии.
time ffmpeg -hide_banner -nostdin -i "$SRC" \
  -vf "scale=135:75,tile=16x16" -fps_mode passthrough -start_number 0 \
  "$OUT/sheet-%06d.png"

# Один лист в двух форматах.
ffmpeg -hide_banner -nostdin -ss 0 -i "$SRC" \
  -vf "select='lt(n\,256)',scale=135:75,tile=16x16" \
  -fps_mode passthrough -frames:v 1 -y "$OUT/one-sheet.png"
ffmpeg -hide_banner -nostdin -ss 0 -i "$SRC" \
  -vf "select='lt(n\,256)',scale=135:75,tile=16x16" \
  -fps_mode passthrough -frames:v 1 -q:v 2 -y "$OUT/one-sheet.jpg"
```

## Ограничения замера

1. **Один прогон.** Разброс не измерен. Для объёма в байтах это неважно:
   детерминированный кодек на одном и том же входе даёт тот же файл. Для
   времени 148,4 с разброс неизвестен, и число следует читать как ориентир.
2. **Прогон с агентской машины.** В контейнере `syp-admin-app` число будет
   своим; каталог на SSD в контейнере смонтирован иначе.
3. **Один компьютер.** Листы пишутся на локальный диск, а не в MinIO. Через
   объектное хранилище объём тот же, но время доставки добавится к 148,4 с.
