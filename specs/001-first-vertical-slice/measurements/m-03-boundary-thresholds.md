# М-03: пороги границ сцен и планов

**Задача**: T057. **Дата замера**: 2026-10-04. **Эпизод**: `GOT.S01E01`.

## Что мерили

Две вещи, и одна из них не измерена:

1. **измерено** — сколько границ даёт детектор при разных порогах, и насколько
   эти границы совпадают с эталонными планами старого проекта;
2. **не измерено** — доля границ, которую человек принимает без правки при
   первом просмотре. Это и есть критерий SC-003, и без оператора его получить
   нечем.

Сетка порогов посчитана **из одного прогона детектора**: оценка кадра от
порога не зависит, порог влияет только на отбор (ADR-0005, research.md Т-05).
Десять значений порога из одного прогона сопоставимы между собой; десять
прогонов — нет, в них добавился бы разброс времени декодирования.

## Каким критерием проверяется

Критерий SC-003: «не менее 95 % границ сцен приняты без правки при первом
просмотре», оценка — выборка из 200 границ на каждое значение порога.

**Вывод: критерий НЕ измерен и не может быть измерен агентом.**

Причина одна и она не техническая: критерий оценивает **решение человека** —
открыл ли оператор монтажную склейку, согласился ли он с границей, которую
предложила машина, и не пошёл ли править. Ни один из доступных артефактов не
содержит этого решения: в старом проекте есть только `isFinalFind` — то есть
факт, что границу приняли, без даты и без того, принял ли её человек при
первом просмотре или после правки.

Что измерено и может быть приложено к решению владельца:

1. **Механика работает.** Сетка посчитана, покрытие эпизода без разрывов и
   перекрытий, 347 листов превью (см. [М-07](m-07-preview-volume.md)), карта
   ключевых кадров совпала с эталоном по 792 номерам без расхождений (PR #15).
2. **Наилучшее совпадение с эталоном — при пороге 4**, то есть при значении,
   которое уже стоит в настройках по умолчанию: 976 из 1028 точных совпадений.
   При пороге 5 совпадение падает до 927, при 8 — до 696. Рост порога
   убирает границы, которые человек в старом проекте считал нужными.
3. **Наши 138 лишних границ** при пороге 4 — это не ошибка по построению:
   порог 4 отбирает оценки выше 4, а человек в старом проекте отбрасывал часть
   из них. Число 52 «не найденных нами» — обратная сторона того же: человек
   поставил границу там, где оценка была ниже 4.
4. **Ориентир «сколько границ человек принимал»** — 1027 `isFinalFind` из
   1028 планов, то есть 99,9 %. Это доля **после** всей работы человека, а не
   доля принятых при первом просмотре, и подменять ею SC-003 нельзя.

## Что требуется от владельца

1. Открыть выборку из 200 границ сцен на `GOT.S01E01` при пороге 8 и
   посчитать, сколько принято без правки при первом просмотре.
2. Повторить то же при пороге 4 и, если доля выше, записать его в настройки
   фильма. Механическая часть для этого уже сделана: смена настройки помечает
   результат устаревшим, но не удаляет его (FR-090).
3. Зафиксировать выборку и её разметку в отчёте рядом с этим, иначе число
   будет невоспроизводимым.

## Как повторить

```sh
SRC=/disks/HDD_16Tb_Clouds/GOT/GOT.S01/GOT.S01E01.BDRip.1080p.mkv

# Один прогон детектора; порог берётся меньший из двух настроек.
time ffmpeg -hide_banner -nostdin -i "$SRC" -vf scdet=threshold=4 -f null - > scdet.log 2>&1

# Сетка порогов и сверка с эталоном старого проекта — из того же прогона.
python3 .scratch/syp/legacy-import/scene-parity.py \
  --scdet-log scdet.log --out scene-parity.json \
  --grid 2 3 4 5 6 8 10 12 15 20 25 30
```

## Ограничения замера

1. **Один прогон детекции.** Разброс по времени не измерен; на числа по
   границам он не влияет, потому что считается по сохранённому выводу.
2. **Совпадение «точно по номеру кадра» — строгое мерило.** Граница монтажной
   склейки и граница, вычисленная по оценке сходства, могут отличаться на
   кадр и при этом означать одно и то же. Поэтому рядом приведена доля
   «в пределах 5 кадров», но и она не заменяет оценку оператора.
3. **Границы сцен с эталоном не сверены** — в старом проекте их нет.
4. **Прогон с агентской машины**, не из контейнера.

## Пересмотр закрытия задачи (2026-10-02)

Задача T057 пересмотрена повторно: закрывать ли её измерениями, которые уже
лежат в этом отчёте. **Решение: оставить открытой.** Ниже — что в измерениях
уже есть, чего в них не хватает и что именно закрыло бы задачу.

Проверялось против строки проверки задачи в `../tasks.md` (T057): «по сетке
порогов на `GOT.S01E01` для каждого значения оценивается выборка из 200 границ;
критерий: не менее 95 % границ сцен приняты без правки при первом просмотре
(М-03, SC-003); выбранные пороги записываются в настройки фильма». Из трёх
требований строки выполнено одно — сетка посчитана.

### Что измерено и закрывает часть критерия

| Часть критерия задачи | Состояние | Чем подтверждено |
|---|---|---|
| Сетка порогов на настоящем эпизоде | **выполнено** | 12 значений порога из одного прогона, 152 с, 1113 оценок |
| Механическое сравнение с эталоном | **выполнено** | 976 из 1028 точных совпадений при пороге 4 (94,94 %) |
| Покрытие эпизода без дыр | **выполнено** | 818 сцен, 1114 планов, 0 разрывов, 0 перекрытий |

### Чего не хватает ровно

1. **Оценки 200 границ сцен оператором** при каждом значении порога из сетки.
   Это и есть критерий SC-003: «не менее 95 % границ сцен приняты без правки
   при первом просмотре». Числа нет ни в одном доступном артефакте: в старом
   проекте сохранился только факт `isFinalFind` (1027 из 1028) без даты и без
   того, сколько раз границу смотрели до принятия. Подставлять 1027 вместо
   выборки — значило бы объявить выполненным критерий, который не проверялся.
2. **Экрана доводки, на котором эта оценка производится.** Он ещё не
   сделан; без него критерий нельзя измерить даже в принципе — смотреть
   границы негде.
3. **Записи выбранных порогов в настройки фильма.** Значения по умолчанию
   (`scene.threshold` = 8, `shot.threshold` = 4) стоят по миграции 07, а не по
   результату SC-003. Выбор порога — следствие пункта 1, а не замена ему.

### Разброс по времени

**Не измерен: один прогон детекции.** Повторных прогонов не было, поэтому
число 152 с — единичное измерение, а не среднее. На выводы по границам это
не влияет (они считаются по сохранённому выводу, а не по времени), но и
распространять 152 с на другие прогоны нельзя: это оценка одного запуска на
машине, у которой видеокарта занята посторонними процессами. Число 152 с в
отчёте приведено как измеренное ровно один раз, и повторением оно не
подтверждено.

### Что закрыло бы задачу

Одно действие человека: открыть выборку из 200 границ сцен на `GOT.S01E01`,
посчитать принятые без правки при первом просмотре и записать число по
порядку из [SC-003: доля принятых границ](sc-003-boundary-acceptance.md).
Число не ниже 95 % закрывает критерий; выбранные пороги записываются в
настройки фильма, и задача закрывается.
