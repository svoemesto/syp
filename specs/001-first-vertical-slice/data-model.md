# Data Model: первый сквозной вертикальный срез SYP

**Feature**: 001-first-vertical-slice
**Источник требований**: [`spec.md`](spec.md) (FR-001…FR-102), ADR-0001…ADR-0008,
`.scratch/syp/research/01a-data-model.md` (знания по старому проекту).
**Решения, раскрытые здесь**: [`research.md`](research.md), пункты Т-01, Т-03, Т-04,
Т-06, Т-09, Т-10, Т-12, Т-16, Т-17, Т-19.

**Хранение**: PostgreSQL 16, доступ **только сырым JDBC**. Никакого
отображения объектов, никакой автогенерации схемы. Схема создаётся и меняется
только нумерованными миграциями с добавлением: [`deploy/syp-db/`](../../deploy/syp-db/).

## 1. Общие соглашения

1. **Номер кадра — единственный источник правды** для всех границ. Время
   нигде не хранится как независимое значение; оно вычисляется от номера кадра
   и `time_base` серии (ADR-0001).
2. **Нумерация кадров с нуля**: первый кадр серии имеет номер 0
   (`research.md` Т-12). Диапазон участка включительный: `first ≤ last`,
   границы `first_frame` и `last_frame` — первый и последний кадр участка.
3. **Связь сцена ↔ план не хранится.** План принадлежит сцене тогда и только
   тогда, когда `plan.first_frame >= scene.first_frame` и
   `plan.last_frame <= scene.last_frame` при одинаковой серии (ADR-0007).
4. **Сырой результат автоматики отделён от рабочих данных.** Прогон анализа →
   сырые границы; рабочая сцена и рабочий план — текущее состояние с признаком
   происхождения (FR-093, constitution IV.4).
5. **Все внешние ссылки — явные внешние ключи** с указанием действия при
   удалении. Каскадное удаление применяется только там, где удаление родителя
   не может оставить «сироту» без внятного смысла.
6. **Справочные значения ограничены проверками на уровне таблицы**, а не
   только кодом: неверный размер плана или неизвестное состояние задания не
   должны попадать в базу.

## 2. Сущности

### 2.1 Сериал

Произведение, с которым работает оператор. Владеет справочником мест действия
и списком серий.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | генерируется базой |
| название | текст | отображаемое имя сериала | **уникально**, не пустое |
| дата создания | дата со временем | — | по умолчанию — текущее |

**Инварианты.** Одна серия принадлежит ровно одному сериалу. Удаление сериала
удаляет его серии и производные от них результаты анализа — операция
необратима и подтверждается оператором.

### 2.2 Место действия

Элемент справочника локаций сериала. FR-050 требует вести справочник, FR-051 —
назначать место действия сцене из этого справочника, FR-052 — **не определять
его автоматически**.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| сериал | внешний ключ на сериал | — | **не пусто**, каскад при удалении сериала |
| название | текст | отображаемое имя локации | **уникально в пределах сериала**, не пустое |

### 2.3 Серия

Видеофайл сериала. FR-001 требует добавить серию в сериал, FR-002 — определить и
сохранить параметры файла. Здесь же хранится признак «это ключевой кадр» по
всей серии (`research.md` Т-04).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| сериал | внешний ключ на сериал | — | **не пусто**, каскад |
| порядковый номер | целое | порядок серий в сериале | **уникален в пределах сериала** |
| название | текст | отображаемое имя серии | не пустое |
| путь к источнику | текст | путь к исходному видеофайлу | **не пусто**, **уникален** — одна серия на один файл |
| размер файла | большое целое | байт | `> 0` |
| время изменения файла | дата со временем | для обнаружения подмены источника | — |
| число кадров | целое | FR-002 | `> 0` |
| числитель частокадровой базы | целое | ADR-0001 | `> 0` |
| знаменатель частокадровой базы | целое | ADR-0001 | `> 0` |
| ширина, высота | целое | разрешение, FR-002 | `> 0` |
| числитель длительности | большое целое | для расчёта фактической длительности | `> 0` |
| знаменатель длительности | большое целое | — | `> 0` |
| кодек видео | текст | FR-002 | не пусто |
| профиль видео | текст | признак совместимости при сборке | может быть пустым |
| формат пикселей | текст | признак совместимости при сборке | не пусто |
| кодек аудио | текст | — | может быть пустым (серия без звука) |
| число аудиоканалов | целое | — | `≥ 0` |
| частота дискретизации аудио | целое | — | `≥ 0` |
| карта ключевых кадров | двоичные данные | один бит на кадр, бит 1 = кадр ключевой | длина соответствует `ceil(frame_count / 8)` |
| число листов превью | целое | сколько листов уже создано | `≥ 0` |

**Инварианты.**

- Исходный видеофайл **никогда не изменяется** — система только читает его
  (`docs/system/02-containers.md`).
- Параметры серии — единственный источник сведений о совместимости при сборке
  (FR-087, `research.md` Т-14).
- Превью и промежуточные файлы серии живут на SSD, собранные видеофайлы — на
  HDD (FR-021, Д-8); в самой таблице серии места хранения нет, они описаны в
  реестре артефактов.

### 2.4 Прогон анализа

Одна попытка получить структуру серии или найти лица. Нужен, чтобы результат
зависел от версии алгоритма и параметров (FR-090) и чтобы сырой результат
автоматики жил отдельно от ручных правок (FR-093).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| серия | внешний ключ на серию | — | **не пусто**, каскад |
| вид | перечисление | `STRUCTURE` — границы и превью; `FACES` — лица и эмбеддинги | одно из двух значений |
| версия алгоритма | текст | FR-090 | не пусто |
| хеш параметров | текст | Р-10: входы задания | не пусто |
| состояние | перечисление | `CREATING`, `WORKING`, `DONE`, `ERROR` | по правилам очереди |
| начало, конец | дата со временем | — | конец не раньше начала |
| текст ошибки | текст | FR-092 | пусто, если состояние `DONE` |
| признак устаревания | логическое | FR-090 | по умолчанию ложь |

### 2.5 Сырая граница

Результат автоматики, **не изменяемый ручными правками**. Только чтение
интерфейса; изменения границ делаются в рабочих таблицах сцен и планов.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| прогон | внешний ключ на прогон анализа | — | **не пусто**, каскад |
| уровень | перечисление | `SCENE` или `SHOT` | одно из двух |
| первый кадр, последний кадр | целое | границы участка | `first <= last`, `first >= 0` |

**Инвариант.** Сырая граница принадлежит ровно одному прогону. Повторный
анализ создаёт **новый** прогон и новые сырые границы; предыдущие остаются.

### 2.6 Кадр

**Только значимые кадры** (Р-07): границы сцен, границы планов и кадры с
найденными лицами. Полная таблица на 82 834 строки не заводится: признак
«ключевой кадр» живёт в карте серии (2.3), остальные признаки нужны лишь там,
где интерфейс что-то показывает.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| серия | внешний ключ на серию | — | **не пусто**, каскад |
| номер кадра | целое | ADR-0001 | `>= 0`, **уникален в пределах серии** |
| признак границы сцены | логическое | FR-023 | по умолчанию ложь |
| признак границы плана | логическое | FR-023 | по умолчанию ложь |
| число лиц | целое | сводный признак для интерфейса | `>= 0` |
| подсказка размера | текст | FR-023, подсказка оператору: на кадре крупность меняется резко | может быть пустым |

**Инварианты.** Кадр не хранится как изображение исходного разрешения —
только превью в хранилище и признаки здесь (FR-024). Строка кадра не создаётся
для кадра, у которого нет ни одного из перечисленных признаков.

### 2.7 Сцена

Непрерывный участок серии. Место действия назначается **только вручную**
(FR-052), происхождение границы различается для алгоритма, оператора и отмены
решения алгоритма (FR-015, FR-016).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| серия | внешний ключ на серию | — | **не пусто**, каскад |
| первый кадр, последний кадр | целое | границы | `first <= last` |
| место действия | внешний ключ на место действия | FR-051 | **пусто**, если не назначено; при удалении локации обнуляется |
| происхождение границы | перечисление | `AUTO` — алгоритм, `OPERATOR` — оператор, `CANCELLED` — решение алгоритма отменено | одно из трёх |
| прогон | внешний ключ на прогон анализа | каким прогоном получена | пусто, если граница создана вручную |
| признак устаревания | логическое | FR-090 | по умолчанию ложь |

**Инварианты.** Планы, лежащие в сцене, вычисляются по правилу 3 раздела 1.
Цветовая семантика интерфейса однозначно выводится из происхождения: красный —
алгоритм, зелёный — оператор, оранжевый — отменено (FR-015, FR-016).

### 2.8 План

Непрерывный участок внутри сцены. Размер вычисляется автоматически по
наибольшему лицу плана (FR-040, FR-041) и может быть исправлен вручную (FR-043).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| серия | внешний ключ на серию | — | **не пусто**, каскад |
| первый кадр, последний кадр | целое | границы | `first <= last` |
| размер | перечисление | FR-044: `NONE`, `ECU`, `BCU`, `CU`, `MCU`, `MS`, `MLS`, `LS`, `VLS`, `XLS` | по умолчанию `NONE`; проверяется ограничением |
| происхождение размера | перечисление | `AUTO` или `OPERATOR` | FR-043 |
| происхождение границы | перечисление | как у сцены | FR-015, FR-016 |
| прогон | внешний ключ на прогон анализа | — | пусто, если вручную |
| признак устаревания | логическое | FR-090 | по умолчанию ложь |

**Инварианты.** План без лиц имеет размер `NONE` (FR-042). План лежит в сцене
целиком; частичное пересечение не допускается (ADR-0007). Столбцы размера и
происхождения границы независимы: оператор может исправить размер, не трогая
границу, и наоборот.

**Индексы.** По серии и первому кадру — основной путь выборки; по диапазону
— основной путь вычисления «сцены, содержащие план».

### 2.9 Персона

Именованная личность. Идентичность не зависит от отображаемого имени:
переименование не ломает обученную модель (`docs/domains/characters/domain.md`,
инвариант 5). Служебные персоны закрывают два рабочих состояния, которые не
являются ошибкой (Р-12).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| сериал | внешний ключ на сериал | — | **не пусто**, каскад |
| отображаемое имя | текст | имя, которое видит оператор | **уникально в пределах сериала** |
| ключ распознавателя | текст | метка класса в модели | **уникален в пределах сериала**; пусто у служебных персон |
| вид | перечисление | `PERSON`, `UNRECOGNIZED` (распознано, но имя не подтверждено), `NONPERSON` (рамка не является лицом) | одно из трёх |

**Инварианты.**

- Служебные персоны `UNRECOGNIZED` и `NONPERSON` создаются при bootstrap для
  каждого сериала и удалению не подлежат.
- Удаление персоны вида `PERSON` **не удаляет лица**: лица переводятся в
  персону вида `UNRECOGNIZED` в той же транзакции, собранные ранее видеофайлы
  не меняются (крайний случай спецификации, FR-036).
- Лицо всегда ссылается на персону; «нет персоны» выражается персоной-заглушкой,
  а пустой ссылкой (Р-12).

### 2.10 Лицо

Рамка лица в кадре. FR-030 требует искать лица в **каждом** кадре, FR-032 —
принимать нарисованное человеком лицо как полноценное, FR-034 — хранить
рамку и принадлежность к плану, FR-036 — не терять неопознанных.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| серия | внешний ключ на серию | — | **не пусто**, каскад |
| номер кадра | целое | ADR-0001, `>= 0` | — |
| порядковый номер лица в кадре | целое | различает несколько лиц в кадре | `>= 0`; **уникален вместе с серией и номером кадра** |
| левая верхняя и правая нижняя границы рамки | целое × 4 | FR-034, в пикселях кадра | `x1 < x2`, `y1 < y2`, в пределах разрешения серии |
| план | внешний ключ на план | FR-034: принадлежность к плану | пусто, только если номер кадра вне диапазонов всех планов серии |
| персона | внешний ключ на персону | FR-033 | **не пусто** (Р-12) |
| происхождение | перечисление | `AUTO` или `OPERATOR` | FR-032: нарисованное человеком лицо помечается `OPERATOR` |
| признак эталона | логическое | FR-060 | по умолчанию ложь |
| распознанное имя | текст | что выдала модель | пусто, если не распознано |
| версия модели, которой распознано | внешний ключ на версию модели | FR-063 | пусто, если не распознано |
| вероятность распознавания | вещественное | — | `0 <= p <= 1` |
| уверенность детектора | вещественное | — | `0 <= p <= 1` |

**Инварианты.**

1. Принадлежность лица к плану **всегда** соответствует правилу 3 раздела 1.
   При любой операции с границами плана (разделение, объединение, отмена
   решения алгоритма) принадлежность пересчитывается в той же транзакции.
2. Лицо с происхождением `OPERATOR` **не удаляется** повторным анализом и не
   заменяется результатом автоматики (SC-006).
3. Лицо без подтверждённого имени остаётся неопознанным и не теряется при
   переобучении, удалении персон и последующих операциях (FR-036).

**Индексы.** По плану — основной путь фильтра по персонажу; по серии и номеру
кадра — основной путь показа матрицы кадров.

### 2.11 Эмбеддинг лица

Вектор признаков лица для кластеризации и обучения. Хранится отдельной
таблицей, а не полем в лице: объём вектора не должен утяжелять строку лица,
которая читается на каждый показ (Р-09).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| лицо | внешний ключ на лицо, первичный ключ | — | каскад при удалении лица |
| ключ модели эмбеддингов | текст | какой моделью получен вектор | не пусто; векторы разных моделей не смешиваются |
| вектор | массив вещественных 4 байта | FR-031, обучение | **не пусто** |

### 2.12 Версия модели распознавания

Результат одного обучения. ADR-0004 и FR-062: каждое обучение создаёт новую
версию с датой, числом эталонов и составом классов; предыдущие версии
сохраняются; FR-061: обучение выполняется заданием очереди; FR-065: порог
распознавания — настройка задания, а не константа кода.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| сериал | внешний ключ на сериал | — | **не пусто**, каскад |
| дата обучения | дата со временем | FR-062 | — |
| версия алгоритма | текст | FR-090 | не пусто |
| хеш параметров | текст | Р-10 | не пусто |
| число эталонов | целое | FR-062 | `>= 0` |
| состав классов | текст (JSON) | FR-062 | не пусто |
| порог распознавания | вещественное | FR-065 | `0 < p <= 1` |
| ключ объекта модели | текст | где лежит обученная модель | пусто, пока обучение не завершено |
| признак активности | логическое | какая версия применяется сейчас | **ровно одна активная версия на сериал** |
| состояние | перечисление | `CREATING`, `WORKING`, `DONE`, `ERROR` | по правилам очереди |

**Инварианты.** Предыдущие версии **не удаляются** (FR-064). Откат (FR-064) —
это обучение на том же наборе эталонов с созданием новой версии; поэтому
состав эталонов каждой версии сохраняется отдельной связью (2.13). Удаление
версии, которой опознаны лица, запрещено: она остаётся в модели как
историческая ссылка (FR-063).

### 2.13 Эталон версии модели

Состав обучающей выборки конкретной версии. Нужен для отката: переобучение на
той же выборке обязано дать восстановимые метки (SC-009).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| версия модели | внешний ключ на версию, часть ключа | — | каскад |
| лицо | внешний ключ на лицо, часть ключа | — | каскад |

### 2.14 Фильтр

Сохранённое именованное дерево условий: три уровня вложенности, на каждом
свой И или ИЛИ (FR-070), сохранение, повторное применение, правка, удаление
(FR-072). Исполняется одним универсальным механизмом (FR-071, ADR-0008).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| сериал | внешний ключ на сериал | — | **не пусто**, каскад |
| название | текст | FR-072 | **уникально в пределах сериала**, не пустое |

**Инварианты.** Глубина дерева **не превышает трёх уровней** — проверяется при
сохранении, превышение отклоняется с внятным сообщением, а не усекается
молча. Неподдерживаемое условие даёт явную ошибку, а не пустой результат
(ADR-0008, последствия 2).

### 2.15 Группа условий

Узел дерева фильтра: свои условия и вложенные группы, соединённые выбранной
связкой.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| фильтр | внешний ключ на фильтр | — | **не пусто**, каскад |
| родительская группа | внешний ключ на группу | третий уровень вложенности | пусто у корневой группы; каскад |
| порядковый номер | целое | порядок следования | — |
| связка | перечисление | `AND` или `OR` — как соединять своих детей | одно из двух |

### 2.16 Условие фильтра

Предикат внутри группы. Набор типов первого среза задан FR-073: персонаж,
место действия, тип плана, размер плана, границы, наличие лица.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| группа | внешний ключ на группу | — | **не пусто**, каскад |
| порядковый номер | целое | — | — |
| тип условия | текст | FR-073 | **проверяется белым списком** |
| предмет | перечисление | `SCENE` или `SHOT` — что рассматриваем | одно из двух |
| оператор | перечисление | `IN`, `NOT_IN`, `BETWEEN`, `IS_NULL`, `IS_NOT_NULL` | одно из пяти |
| значение | JSONB | операнд: идентификатор, перечень значений, диапазон границ | **не пусто**, если оператор требует операнд |
| отрицание | логическое | FR-070: включить или исключить найденное | по умолчанию ложь |

**Инварианты.** Значение типа условия, не входящего в белый список, отвергается
при сохранении: это и есть механизм, дающий явную ошибку вместо пустого
результата (ADR-0008). Исполнение фильтра не обращается к базе «как попало»:
каждый тип условия имеет зарегистрированный обработчик, возвращающий множество
планов (`research.md` Т-08).

### 2.17 Задание

Единица работы в очереди. FR-003 требует показывать прогресс и состояние,
FR-004 — отличать невыполненную задачу от неудачной, FR-088 — чтобы задание
сборки было наблюдаемым и имело результат по адресу подборки.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| вид | текст | что делает задание: `ANALYZE`, `FACES`, `TRAIN`, `ASSEMBLE` | — |
| состояние | перечисление | `WAITING`, `CREATING`, `WORKING`, `DONE`, `ERROR` — **ровно этот набор**, как в правилах очереди проекта | одно из пяти |
| предмет | текст и большое целое | над чем работает: серия, версия модели, сборка | пусто для заданий, не привязанных к предмету |
| параметры | JSONB | вход задания | не пусто |
| хеш параметров | текст | Р-10: входы, по которым определяется, можно ли пропустить работу | не пусто |
| версия алгоритма | текст | FR-090 | пусто, пока не определена |
| сделано, всего | большое целое | прогресс, FR-003 | `0 <= сделано`, `0 <= всего` |
| пояснение прогресса | текст | что сейчас делает задание | пусто |
| текст ошибки | текст | FR-092: ненулевой код завершения — ошибка задания с текстом | пусто, если состояние `DONE` |
| создано, начато, завершено | дата со временем | — | хронологический порядок |

**Инварианты и переходы состояний.**

```
WAITING ──взят воркером──► CREATING ──начало работы──► WORKING ──► DONE
   │                             │                          │
   │                             └──────────► ERROR ◄──────┘
   └────────────────────────────────────────────────────────► ERROR (отмена)
```

1. Задание в состоянии `DONE` означает, что **все** внешние программы, которые
   оно запускало, завершились с нулевым кодом (FR-004, FR-092, SC-005).
2. Ненулевой код завершения внешней программы переводит задание в `ERROR` с
   текстом ошибки, а не в `DONE` — ни при каких условиях (constitution IV.2).
3. Прерванное задание возвращается в `WAITING`; прогресс восстанавливается из
   уже сохранённого значения, а не начинается заново молча
   (`research.md` Т-15).
4. Задание с тем же хешем параметров, что и успешно завершённое, может быть
   отброшено воркером как уже выполненное (Р-10) — **только** если результат
   зарегистрирован как готовый (2.18), а не по факту существования файла.

### 2.18 Артефакт

Регистрация результата задания в хранилище. Даёт атомарность (FR-091): пока
состояние не `READY`, артефакт не считается готовым и не может быть использован
сборкой или показан в интерфейсе.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| задание | внешний ключ на задание | — | пусто для артефактов вне задания |
| вид | перечисление | `PREVIEW_SHEET`, `MODEL`, `CUT_FRAGMENT`, `ASSEMBLY` | — |
| размещение | перечисление | `SSD` или `HDD` | Д-8, FR-021 |
| ключ объекта | текст | где лежит | **не пусто**, **уникален вместе с видом** |
| тип содержимого | текст | — | — |
| размер в байтах | большое целое | — | `>= 0` |
| контрольная сумма | текст | Р-10: входы результата зафиксированы | пусто |
| состояние | перечисление | `WRITING`, `READY`, `FAILED` | **не пусто** |

**Инварианты.**

1. Артефакт пишется по **временному** ключу и переносится на окончательный
   только после нулевого кода завершения (FR-091, FR-092).
2. На SSD размещаются превью, промежуточные нарезки и модели; на HDD —
   собранные видеофайлы (FR-021, Д-8).
3. Артефакт в состоянии не `READY` никогда не выдаётся наружу: незавершённый
   файл не считается готовым (FR-091).

### 2.19 Сборка

Видеофайл из выбранных сцен, инициированная **пользователем публичной части**
(FR-085). Длительности расчётная и фактическая хранятся обе (FR-083).

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| идентификатор | большое целое, первичный ключ | — | — |
| название | текст | отображаемое имя подборки | не пустое |
| состояние | перечисление | `CREATING`, `WORKING`, `DONE`, `ERROR` | — |
| задание | внешний ключ на задание | FR-088 | пусто, пока задание не создано |
| артефакт | внешний ключ на артефакт | FR-084: воспроизведение по адресу подборки | пусто, пока файл не готов |
| ожидаемая длительность | большое целое, мс | расчёт по сумме кадров планов | `>= 0` |
| фактическая длительность | большое целое, мс | измерена заново после сборки | `>= 0` |
| ожидаемое число кадров | большое целое | — | `>= 0` |
| фактическое число кадров | большое целое | FR-082: округление на стыках | `>= 0` |
| создано, завершено | дата со временем | — | — |
| текст ошибки | текст | FR-087: внятное объяснение | пусто, если `DONE` |

**Инварианты.** Сборка допускает сцены **из разных серий сериала** (FR-086).
Если параметры серий несовместимы, запись сборки не создаётся вовсе — отказ
происходит до начала работы (FR-087).

### 2.20 Элемент сборки

Состав подборки с сохранением порядка. Здесь же фиксируются фактические
границы фрагмента после округления до ключевого кадра — это материальная
основа для показа обеих длительностей (FR-083) и для объяснения пользователю,
почему длительность отличается.

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| сборка | внешний ключ на сборку, часть ключа | — | каскад |
| порядковый номер | целое, часть ключа | порядок сцен в подборке | `>= 0` |
| сцена | внешний ключ на сцену | что вошло | **не пусто** |
| серия | внешний ключ на серию | денормализация для проверки совместимости | **не пусто** |
| ожидаемые границы | два целых | первый и последний кадр плана | `first <= last` |
| фактические границы | два целых | после округления до ключевого кадра | пусто, пока фрагмент не нарезан |

## 3. Связи

```
Сериал ──1:N──► Серия ──1:N──► Кадр (только значимые)
   │               │
   │               ├──1:N──► Прогон анализа ──1:N──► Сырая граница
   │               │              (append-only)
   │               ├──1:N──► Сцена ──(вычисляется по диапазонам)──► План
   │               ├──1:N──► План ──1:N──► Лицо
   │               └──1:N──► Лицо ──1:1──► Эмбеддинг
   │
   ├──1:N──► Место действия ──(назначается сцене вручную)
   ├──1:N──► Фильтр ──1:N──► Группа условий ──1:N──► Условие
   └──1:N──► Версия модели ──1:N──► Эталон версии

Задание ──1:N──► Артефакт ──► Сборка ──1:N──► Элемент сборки
```

Вычисляемые связи, которых в схеме нет **намеренно**:

| Связь | Правило вычисления | Основание |
|---|---|---|
| сцена → планы | диапазон плана целиком внутри диапазона сцены при равной серии | ADR-0007 |
| план → персонажи | лица, у которых сохранённый план — этот план | FR-034 |
| сцена → персонажи | объединение персон по планам сцены | для отчёта «кто в сцене» |
| серия → готовность результата | наличие артефактов в состоянии `READY` нужного вида | FR-091 |

## 4. Проверки целостности, вынесенные в базу

Правила, нарушение которых не должно быть возможно на уровне хранилища:

1. Граница участка: `first_frame >= 0` и `last_frame >= first_frame` — сцена,
   план, сырая граница, элемент сборки.
2. Рамка лица: `x1 < x2`, `y1 < y2`, обе точки в пределах разрешения серии.
3. Размер плана — одно из десяти значений справочника FR-044.
4. Состояние задания — одно из пяти значений очереди; состояние версии модели
   и сборки — одно из четырёх.
5. Естественный ключ лица: серия + номер кадра + порядковый номер лица.
6. Порог распознавания в пределах `(0; 1]`.
7. Порядковый номер серии уникален в пределах сериала; путь к источнику
   уникален во всей таблице.
8. Имя персоны и ключ распознавателя уникальны в пределах сериала.
9. Ровно одна активная версия модели на сериал.

## 5. Чего в модели нет и почему

| Не вводим | Почему |
|---|---|
| Время границы отдельным полем | ADR-0001 запрещает второй источник правды |
| Связь сцена → планы списком идентификаторов | ADR-0007 прямо запрещает |
| Строка на каждый кадр серии | Р-07: только значимые кадры |
| Кадр как изображение исходного разрешения | FR-024 |
| Машинозависимые пути по компьютерам | стек одномашинный, пути задаются конфигурацией |
| Универсальное свойство «ключ-значение» для горячих полей | Р-08: место действия, тип и размер плана, персона — типизированные поля; произвольные свойства в первый срез не входят |
| Модель дорожек как полноценная сущность | вне объёма среза, зафиксировано решением владельца |
| Драматургическая единица поверх сцены | вне объёма среза, зафиксировано решением владельца |
| Аутентификация и учётные записи пользователей | вне объёма среза, стек локальный |
