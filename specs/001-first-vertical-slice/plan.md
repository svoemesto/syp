# Implementation Plan: Первый сквозной вертикальный срез SYP

**Branch**: `004-speckit-plan` | **Date**: 2026-10-02 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-first-vertical-slice/spec.md`
(57 FR, 10 SC, 4 пользовательские истории, утверждена владельцем 2026-10-02).

**Этот план не меняет ни одного FR и ни одного SC.** Спецификация — контракт
( constitution IX.4). План раскрывает её в архитектуру, данные и порядок
работы; расхождения с планом фиксируются как «нерешённые вопросы» в разделе
11, а не правкой спецификации.

## Summary

Строится **первый сквозной вертикальный срез**: одна серия (82 834 кадра)
проходит путь от файла в архиве до готового видео «Show Your Picture», которое
пользователь смотрит в публичной части, — без участия оператора на последнем
шаге.

Технический подход:

1. **Границы сцен и планов** определяются встроенным детектором ffmpeg за один
   проход, двумя порогами; номер кадра — единственный источник правды
   (ADR-0001, ADR-0005).
2. **Лица ищутся в каждом кадре** полным потоком исходного разрешения на
   видеокарте, силами среды исполнения нейросетей внутри `syp-admin-app`;
   кадры на диск не пишутся, пишутся только превью (ADR-0002, FR-024).
3. **Превью всех кадров** хранятся листами 16×16 в объектном хранилище на
   SSD: один запрос на 256 кадров вместо 256 запросов.
4. **Связи по кадрам вычисляются**, а не хранятся: сцена содержит планы по
   правилу диапазонов (ADR-0007). Принадлежность лица к плану хранится, как
   требует FR-034, и поддерживается транзакцией доводки.
5. **Сырой результат автоматики отделён от ручных правок**: прогон анализа →
   сырые границы; рабочие границы хранят происхождение (FR-093, SC-006).
6. **Всё, что долго, идёт через очередь заданий** с наблюдаемым состоянием;
   код возврата внешней программы проверяется всегда, запись артефакта
   атомарна (constitution IV, FR-004, FR-091, FR-092, SC-005).
7. **Фильтры исполняются одним универсальным механизмом** через реестр
   обработчиков условий, а не запросом на каждое сочетание (ADR-0008,
   FR-071).
8. **Сборка идёт без перекодирования**, фрагменты режутся от ближайшего
   ключевого кадра, обе длительности показываются пользователю (ADR-0006,
   FR-081, FR-082, FR-083).
9. **Шесть контейнеров, два бэкенда, два фронтенда, сырой JDBC**, нумерованные
   добавочные миграции Postgres 16 (Hard Gate «Контейнеры», constitution III).

## Technical Context

**Язык и версия**: Kotlin + Spring Boot (версия фиксируется на фазе 0 при
создании каркаса; выбор версии — задача фазы 0, а не предположение этого
плана), Gradle multi-module. Фронтенд: Vue 3 + Vite.

**Основные зависимости**: среда исполнения нейросетей с поддержкой видеокарты
для детекции лиц и эмбеддингов (конкретная библиотека и её версия — результат
замера М-01, `research.md` Т-01); ffmpeg 6.1.1 и ffprobe того же семейства;
драйвер драйверов PostgreSQL; клиент объектного хранилища MinIO; клиентский
классификатор для обучения на эталонных векторах.

**Хранилище**: PostgreSQL 16 (`syp-db`) — границы, сцены, планы, лица, персоны,
версии моделей, фильтры, задания, сборки. MinIO (`syp-storage`) на SSD —
листы превью, нарезанные фрагменты, обученные модели. Файловая система на
HDD — собранные видеофайлы. Исходные видео — только чтение.

**Тестирование**: встроенный тестовый фреймворк Kotlin для бэкенда
(юнит-тесты правил домена и интеграционные тесты против поднятой базы);
Vitest и проверка типов для фронтендов. Отдельный маршрут сквозной проверки —
[`quickstart.md`](quickstart.md).

**Целевая платформа**: Linux, локальная машина. Видеокарта доступна только
из контейнеров, в агентской среде её нет.

**Тип проекта**: веб-приложение с двумя бэкендами и двумя фронтендами плюс
видео-пайплайн.

**Целевые показатели (из SC, без добавления новых критериев)**:

| Показатель | Значение | Источник |
|---|---|---|
| Полный анализ одной серии | укладывается в одну рабочую смену | SC-001 |
| Размеченная серия силами одного оператора | один рабочий день | SC-002 |
| Принятые без правки границы сцен | не менее 95 % | SC-003 |
| Сборка из 100 сцен | меньше 5 минут ожидания | SC-004 |
| Задания, сообщившие успех после сбоя | 0 | SC-005 |
| Потерянные ручные правки при повторном анализе | 0 | SC-006 |
| Повторное применение сохранённого фильтра | одно действие из списка | SC-007 |
| Воспроизведение собранного файла | полностью, без пропусков | SC-008 |
| Возврат к версии модели | прежние метки без повторного обучения | SC-009 |
| Пользователь без оператора | применяет фильтр, выбирает, собирает, смотрит | SC-010 |

**Ограничения**:

- Ровно шесть контейнеров; седьмой воркер заводить нельзя
  (`research.md` Т-01, Т-20).
- Никакого отображения объектов: только сырой JDBC. Миграции нумерованные и
  добавочные, автогенерация схемы запрещена (constitution III).
- Детекция лиц — **в каждом** кадре, адаптивный шаг запрещён без нового
  решения владельца (ADR-0002).
- Сборка без перекодирования (ADR-0006).
- Ловушка среды агента: выводы о правах на диски из неё делать нельзя, `ffmpeg`
  в ней обрывается на длинных операциях — замеры видео-части идут через
  контейнер.

**Объём**: одна серия для отладки; шесть доменов; четыре пользовательские
истории; 57 требований; 10 критериев. Архив из 73 серий — цель следующих
спринтов, в срез не входит.

## Фазы реализации

Каждая фаза перечисляет цель, состав, покрываемые требования и критерий
готовности. Критерий готовности — проверяемый факт, а не «сделано».

### Фаза 0. Каркас, развёртывание, очередь

**Цель**: поднять проект целиком и получить работающую очередь заданий с
наблюдаемым состоянием — до написания доменной логики.

**Входит**:

- Gradle multi-module: `syp-core`, `syp-admin-app`, `syp-public-app`;
  каталоги фронтендов `syp-admin-web`, `syp-public-web` (имя каталога = имя
  контейнера, Hard Gate Build/Deploy/Containers);
- шесть контейнеров, `deploy/do.sh`, файл окружения с портами из диапазонов
  7910–7999 и 9020–9099 (`research.md` Т-22);
- подключение `syp-db` и `syp-storage`, создание бакета превью на SSD и
  каталога собранных видео на HDD (FR-021, Д-8);
- применение миграций `deploy/syp-db/01…07` и проверка ограничений тестом;
- **очередь заданий**: таблица заданий, захват воркером, пять состояний,
  запись прогресса, отмена;
- **исполнитель внешних программ**: единая точка запуска, объединение вывода
  и ошибок, **проверка кода возврата всегда**, чтение потока прогресса;
  регистрация артефактов с состояниями `WRITING` / `READY` / `FAILED` и
  атомарное переименование по завершении;
- проверки в pre-commit и CI: запрет отображения объектов, проверка кодов
  возврата, линтеры, отсутствие секретов (`AGENTS.md` § Tier-2 «Каталог
  guards»).

**Покрывает**: FR-003, FR-004, FR-090, FR-091, FR-092, FR-100, FR-101, FR-102,
FR-021.

**Критерий готовности**: очередь принимает тестовое задание, оно проходит все
пять состояний и заканчивается `DONE`; тестовое задание с падающей внешней
программой заканчивается `ERROR` с текстом ошибки; артефакт, прерванный на
середине, не имеет состояния `READY`.

### Фаза 1. Приём сериала и серии

**Цель**: оператор создаёт сериал, добавляет серию, система сама определяет и
хранит параметры файла.

**Входит**:

- сущности «сериал», «серия», «место действия» и миграции для них;
- опрос файла: число кадров, частокадровая база, разрешение, длительность,
  кодек, профиль, формат пикселей, параметры аудио, **карта ключевых
  кадров** — упакованной битовой картой, один бит на кадр
  (`research.md` Т-04);
- настройки сериала по умолчанию: пороги границ, пороги размера плана,
  порог детектора, параметры кластеризации, раскладка листа превью;
- внятная ошибка на недоступный файл — «успех с пустым результатом»
  запрещён;
- экран приёма в админке.

**Покрывает**: FR-001, FR-002, FR-003, FR-012, FR-023, FR-050 (справочник
заводится здесь, наполняется в фазе 6).

**Критерий готовности**: серия `GOT.S01E01` зарегистрирована, её параметры
совпадают с измеренными (82 834 кадра, 1920×1080, 23,976 fps), карта
ключевых кадров заполнена; недоступный файл даёт внятную ошибку.

### Фаза 2. Анализ структуры видео

**Цель**: серия получает сцены, планы и превью — автоматически, за одно
задание, с проверяемым результатом.

**Входит**:

- **задача `ANALYZE`**: один проход ffmpeg с встроенным детектором; поток
  оценок кадра разбирается на два порога — высокий даёт границу сцены,
  низкий границу плана внутри сцены (`research.md` Т-05);
- **листы превью**: 16×16 ячеек по 135×75, 256 кадров на лист, запись
  по временному ключу с последующим переносом на окончательный
  (`research.md` Т-03);
- прогресс задания из потока прогресса ffmpeg;
- **прогон анализа** и **сырые границы** — отдельными сущностями, результат
  автоматики не смешивается с рабочими границами (FR-093);
- таблица **значимых кадров**: границы сцен, границы планов, кадры с лицами;
  полная таблица на 82 834 строки не заводится (Р-07);
- пометка результата устаревшим при смене версии алгоритма или порогов;
- экран структуры: список сцен, планы внутри, сырой результат для сравнения.

**Покрывает**: FR-010, FR-011, FR-012, FR-020, FR-021, FR-022, FR-023, FR-024,
FR-034 (принадлежность плана как пустая до нахождения лиц), FR-090, FR-091,
FR-092, FR-093.

**Критерий готовности**: задание `ANALYZE` на тестовой серии завершается
`DONE`; сцены покрывают серию без разрывов и перекрытий; число листов
превью равно округлению числа кадров до размера листа; смена порога помечает
результат устаревшим, не удаляя его.

**Замеры фазы**: М-03 (пороги границ, критерий SC-003), М-06 (пропускная
способность канала кадров), М-07 (объём листов).

### Фаза 3. Лица: поиск, эмбеддинги, кластеры

**Цель**: в каждом кадре серии найдены лица, они сгруппированы, ни одно
не потеряно.

**Входит**:

- **задача `FACES`**: проход ffmpeg отдаёт кадры исходного разрешения в
  процесс; детектор на видеокарте; кадры **не пишутся** на диск (FR-024);
- сохранение рамки, порядкового номера лица в кадре, уверенности детектора;
- пересчёт принадлежности лиц планам при сохранении (FR-034);
- **эмбеддинги** отдельной таблицей; классификация «лицо / не лицо» по
  пропорциям рамки с порогом-настройкой (`research.md` Т-18);
- **кластеризация** на холодном старте: разбиение на центры и слияние близких
  по порогу (`research.md` Т-16);
- лицо без подтверждённого имени получает персону-заглушку, а не пустую
  ссылку (Р-12);
- ракурс лица **не определяется** — в первый срез не входит (FR-035);
- экран лиц: миниатюры, кластеры, назначение имён.

**Покрывает**: FR-030, FR-031, FR-033 (хранение назначения), FR-034, FR-035,
FR-036, FR-063 (поле версии модели), FR-092.

**Критерий готовности**: общее число найденных лиц совпадает с числом
обработанных кадров по признаку «кадр обработан», а не с долей кадров;
прерванная на середине детекция не оставляет готовых артефактов и не портит
ранее найденное; неопознанные лица присутствуют в отчёте «кто в сцене».

**Замеры фазы**: М-01 (среда исполнения и видеокарта), М-02 (модели детектора
и эмбеддингов), М-05 (параллелизм), М-08 (параметры кластеризации).

### Фаза 4. Размер плана

**Цель**: у каждого плана есть крупность, вычисленная автоматически.

**Входит**:

- вычисление по **самому крупному лицу плана**: доля площади рамки в площади
  кадра;
- перевод доли в одну из десяти категорий справочника;
- план без лиц получает «нет размера»;
- пороги — настройка сериала, подбор замером, а не константа кода;
- возможность ручного исправления значения с сохранением признака
  происхождения;
- отображение размера в редакторе планов.

**Покрывает**: FR-040, FR-041, FR-042, FR-043, FR-044.

**Критерий готовности**: на 200 планах серии автоматическое значение совпадает
с ручным после подбора порогов; ручное исправление не перетирается
пересчётом.

**Замер фазы**: М-04 (пороги размера плана).

### Фаза 5. Ручная доводка — полный редактор

**Цель**: четыре механики ручной правки работают и не теряются (решение
владельца Д-6).

**Входит**:

- матрица кадров: граница плана **разрывает строку**, на стыке страниц план
  виден с обеих сторон;
- цветовая семантика: красный — алгоритм, зелёный — оператор, оранжевый —
  отменено оператором, голубой — ключевой кадр, синий — есть лица;
- **разделение и объединение планов**; согласование пересекающихся сцен в той
  же операции;
- **отмена решения алгоритма** как отдельное состояние, а не как отсутствие
  данных;
- **рисование лица мышью** с пометкой «сделано человеком»;
- **назначение лица персоне перетаскиванием**;
- пометка и снятие метки эталона;
- ручное исправление размера плана;
- **автосохранение без кнопки «Сохранить»**; ответ приходит с обновлённым
  участком, интерфейс не перезапрашивает всё дерево;
- **повторный анализ не стирает ручное**: сырой результат обновляется, рабочее
  — нет; отменённые оператором границы сохраняют признак отмены.

**Покрывает**: FR-013, FR-014, FR-015, FR-016, FR-022, FR-023, FR-032, FR-033,
FR-043, FR-060, FR-093, SC-006.

**Критерий готовности**: после полного цикла «правка → повторный анализ →
правка → повторный анализ» ни одна ручная правка не потеряна, все
принадлежности лиц планам согласованы с диапазонами, интерфейс нигде не
показывает кнопку «Сохранить».

### Фаза 6. Место действия сцены

**Цель**: оператор ведёт справочник локаций сериала и назначает место
действия сценам.

**Входит**:

- справочник локаций сериала: добавление, переименование, удаление;
- назначение места действия сцене из справочника; снятие назначения;
- **автоматического определения места действия нет** ни в одном сценарии;
- удаление локации не разрушает сцены: назначение снимается.

**Покрывает**: FR-050, FR-051, FR-052.

**Критерий готовности**: место действия назначается только вручную и только
из справочника своего сериала; в коде отсутствует любой вызов
определения места действия.

### Фаза 7. Обучение и версии модели

**Цель**: эталоны → обучение → имена у лиц → возврат к прежней версии без
повторного обучения оператором.

**Входит**:

- пометка и снятие метки эталона (механика из фазы 5 используется здесь);
- **задача `TRAIN`**, а не кнопка, блокирующая интерфейс;
- новая версия при каждом обучении: дата, число эталонов, состав классов;
  предыдущие версии сохраняются;
- **порог распознавания — настройка задания**, а не константа кода;
- сохранение версии модели, которой опознано каждое лицо;
- **откат**: новая версия на прежнем составе эталонов, предыдущие версии не
  удаляются;
- задание переопознавания: метки предыдущей версии не стираются молча.

**Покрывает**: FR-060, FR-061, FR-062, FR-063, FR-064, FR-065, FR-036, SC-009.

**Критерий готовности**: обучение выполняется заданием; после обучения лица
получили имена; переобучение не стирает метки предыдущей версии; откат
восстанавливает прежние метки без повторного обучения оператором.

**Замер фазы**: М-10 (время обучения).

### Фаза 8. Фильтры

**Цель**: фильтры строятся, сохраняются и исполняются одним механизмом.

**Входит**:

- дерево условий: три уровня, на каждом свой И или ИЛИ; превышение глубины
  отвергается внятным сообщением, а не усекается молча;
- условия первого среза: персонаж, место действия, тип плана, размер плана,
  границы, наличие лица;
- **реестр обработчиков условий**: обработчик типа условия возвращает
  множество планов; дерево сводится рекурсивно, И — пересечение, ИЛИ —
  объединение; добавление нового типа условия — регистрация одного
  обработчика (`research.md` Т-08);
- **неизвестный тип условия — явная ошибка, а не пустой результат**
  (ADR-0008); это обеспечено проверкой на уровне хранилища;
- сохранение под именем, повторное применение одним действием, правка,
  удаление;
- обратное отображение «планы → сцены» при выдаче результата
  (`research.md` Т-21).

**Покрывает**: FR-070, FR-071, FR-072, FR-073, SC-007.

**Критерий готовности**: фильтр с тремя уровнями применяется корректно;
сохранённый фильтр применяется повторно одним действием из списка; фильтр с
неизвестным типом условия отвергается с текстом; в коде нет ни одной ветки
«объект × признак» вне реестра обработчиков.

### Фаза 9. Сборка подборки

**Цель**: выбранные сцены склеиваются в один видеофайл без перекодирования.

**Входит**:

- **проверка совместимости серий до создания задания**: разрешение, кодек,
  профиль, формат пикселей, частокадровая база, параметры аудио; при
  расхождении — отказ с перечнем несовместимых серий и различающимися
  признаками (`research.md` Т-14);
- допуск сцен **из разных серий сериала**;
- нарезка фрагментов потоковым копированием **от ближайшего ключевого кадра
  не позже начала плана**; фрагменты стартуют с самостоятельного ключевого
  кадра — необходимое условие конкатенации;
- склейка потоковым копированием, выход MP4, одна аудиодорожка;
- **задача `ASSEMBLE` с видимым прогрессом**; исполнитель — воркер
  публичного бэкенда, админский воркер этот вид заданий не берёт
  (`research.md` Т-20);
- фактические длительность и число кадров измеряются заново; обе величины
  показываются вместе с причиной расхождения;
- запись по адресу подборки, только для артефакта в состоянии `READY`.

**Покрывает**: FR-080, FR-081, FR-082, FR-083, FR-086, FR-087, FR-088, FR-091,
FR-092.

**Критерий готовности**: подборка из 100 смен собирается менее чем за 5 минут;
фактическая длительность отличается от расчётной на сумму округлений, и
обе величины показаны; сборка несовместимых серий отклоняется до создания
задания; админка не имеет ни одного способа запустить сборку.

**Замер фазы**: М-09 (скорость сборки, критерий SC-004).

### Фаза 10. Публичная часть

**Цель**: пользователь без оператора получает подборку и смотрит её.

**Входит**:

- список сериалов, список сохранённых фильтров, текстовая формулировка
  условия (собирается из того же дерева, по которому фильтр исполняется,
  — расхождение между надписью и результатом невозможно);
- применение фильтра, список сцен, выбор сцен, превью для выбора;
- **инициация сборки пользователем**;
- наблюдение за заданием с прогрессом; **перезагрузка страницы задание не
  теряет** — состояние читается по адресу подборки;
- воспроизведение собранного файла с поддержкой воспроизведения по
  диапазону;
- список вошедших сцен с расчётными и фактическими границами;
- **в публичной части нет** ни разметки, ни обучения, ни настроек: это
  обеспечено отсутствием эндпоинтов, а не проверкой прав.

**Покрывает**: FR-084, FR-085, FR-088, FR-083, SC-004, SC-008, SC-010.

**Критерий готовности**: пользователь проходит весь путь без обращения к
оператору: фильтр → выбор сцен → сборка → ожидание → просмотр; файл
воспроизводится полностью; список сцен виден; перезагрузка страницы во время
сборки ничего не теряет.

### Фаза 11. Надёжность, документированность, приёмка

**Цель**: доказать, что требования и критерии выполнены, и закрыть срез.

**Входит**:

- проверка всех проверяемых свойств контракта очереди (раздел 6
  [`contracts/job-queue.md`](contracts/job-queue.md)): семь утверждений, каждое
  тестом;
- проверка, что публичные API документированы полностью и ведут на
  per-feature документ; что документ обновлён в том же изменении;
- полный прогон маршрута [`quickstart.md`](quickstart.md) на тестовой серии;
- измерение SC-001, SC-002, SC-003, SC-005, SC-006 на фактах, а не на
  ощущениях: выборка границ пересматривается и пересчитывается, случаи сбоя
  фиксируются при каждом прогоне;
- приведение живой документации в соответствие: домены, компоненты,
  системные документы, ADR при новых решениях.

**Покрывает**: FR-093, FR-100, FR-101, FR-102, SC-001…SC-010.

**Критерий готовности**: все 10 критериев имеют измеренное подтверждение;
все 57 требований имеют тест или проверочный маршрут; живая документация
соответствует состоянию системы; линтер документации проходит.

**Решение о структуре**. Раскладка «Option 2: веб-приложение» из шаблона
развита до двух бэкендов и общего модуля. Обоснования:

1. **Общий модуль `syp-core`.** База, хранилище, очередь, запуск внешних
   программ, листы превью нужны обоим бэкендам. Дублировать их — значит
   разойтись в том, как проверяется код возврата и как пишется артефакт, а
   это ровно то, где цена ошибки максимальна (SC-005).
2. **Разделение по доменам внутри модулей.** Раскладка повторяет
   `docs/domains/*/domain.md`, поэтому документация и код раскладываются
   одинаково, и правка документации не расходится с кодом.
3. **Каталог фронтенда = имя контейнера.** Требование Hard Gate
   Build/Deploy/Containers: в корне проекта `package.json` нет, `npm run`
   из корня не работает.
4. **Воркеры по видам заданий** внутри каждого бэкенда
   (`research.md` Т-20), а не отдельный модуль: отдельный контейнер запрещён,
   а логика воркера — инфраструктура, ей место в `syp-core` и в тонком слое
   каждого бэкенда.
5. **`domain`-папки и `components/` документации соответствуют пакетам
   `catalog/`, `analysis/`, `characters/`, `annotation/`, `selection/`,
   `showcase/`** — срез не нарушает L1 → L2 → L3.
