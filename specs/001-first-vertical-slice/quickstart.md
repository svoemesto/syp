# Quickstart: сквозная проверка первого среза (схема «рецепт»)

**Feature**: 001-first-vertical-slice
**Назначение**: проверочный маршрут, доказывающий, что срез работает от
исходного файла в архиве до **локального** просмотра готового файла на машине
пользователя. Это **руководство по проверке**, а не описание реализации: тела
методов, тексты миграций и полные наборы тестов живут в задачах и в фазе
реализации.

**Тестовый эпизод**: `GOT.S01E01.BDRip.1080p.mkv` — 1920×1080, 23,976 fps,
3697,2 с, 88 643 кадра. Один эпизод, как и требует срез.

**Ссылки**: [контракт админки](contracts/admin-api.md),
[контракт публичной части](contracts/public-api.md),
[контракт очереди](contracts/job-queue.md),
[формат сценария](contracts/recipe-format.md),
[модель данных](data-model.md).

## 1. Предпосылки

| Что | Как проверить |
|---|---|
| Шесть контейнеров подняты | `cd deploy && bash do.sh status` |
| Миграции применены | все семь файлов `deploy/syp-db/*.sql` применены по порядку |
| Эпизод зарегистрирована в базе | её параметры совпадают с измеренными: 88 643 кадра, 1920×1080 |
| Превью на SSD, видеофайлов на сервере нет | размещение проверяется осмотром хранилища (FR-021, FR-088) |
| Настройки фильма созданы | одиннадцать значений по умолчанию присутствуют |
| Ключ подписи создан | закрытый ключ в переменной окружения, открытый отдаётся публичной частью |
| **На машине пользователя** | `ffmpeg`, `ffprobe`, `openssl` на месте; копия дерева фильма; воркер установлен; файл настроек создан |
| Архив доступен на чтение | `docker exec syp-admin-app ls -l <путь к файлу эпизода>` |
| GPU видна контейнеру | `docker exec syp-admin-app nvidia-smi` показывает карту |

**Ловушка среды агента.** Проверки прав на дисках из агентской сессии
недействительны: внутри неё всё смонтировано только для чтения, включая корень,
в который писать можно. Все проверки хранения выполняются **внутри
контейнера**. `ffmpeg` в агентской сессии обрывается на длинных операциях —
замеры видео-части оттуда недействительны.

## 2. Маршрут проверки

Маршрут идёт по порядку пользовательского пути. Каждый шаг указывает, что
проверяется и каким требованием закрывается.

### Шаг 1. Приём эпизода

**Действие.** Создать фильм, добавить эпизод указанием пути к файлу.

**Ожидание.** Система сама определила и сохранила: число кадров, частокадровую
базу, разрешение, длительность, кодек, профиль, формат пикселей, параметры
аудио, карту ключевых кадров. Значения совпадают с измеренными: 88 643 кадра,
1920×1080, 23,976 fps.

**Проверяет**: FR-001, FR-002.

**Отрицательный случай.** Указать путь к несуществующему файлу: система
возвращает внятную ошибку со значением `SOURCE_UNREADABLE`, а не «успех с
пустым результатом».

**Отрицательный случай.** Указать путь к файлу **вне** корня фильма: система
отвергает регистрацию. Иначе в сценарий попал бы относительный путь, который
на машине пользователя указывает неизвестно куда (FR-089a).

### Шаг 2. Сверка целостности исходника

**Действие.** Поставить подсчёт `sha256` для эпизода (при регистрации эпизода это
делается само) и дождаться завершения.

**Ожидание.** Задание проходит состояния и заканчивается `DONE`; в справочнике
появилась запись с суммой, размером файла и временем подсчёта. Сумма совпадает с
`sha256sum` файла, посчитанным снаружи.

**Проверяет**: FR-089, FR-090, FR-003, FR-004.

**Отрицательный случай.** Поставить пересчёт второй раз: появляется **новая**
запись, прежняя остаётся; актуальной остаётся ровно одна. Изменить время
изменения файла: прежняя сумма помечается устаревшей, и публичная часть
отказывает в сценарии с кодом `CHECKSUM_NOT_READY`, а не выдаёт сценарий,
который у пользователя не пройдёт сверку.

### Шаг 3. Анализ структуры

**Действие.** Поставить эпизод на анализ и дождаться завершения задания.

**Ожидание.** Задание проходит состояния `WAITING` → `CREATING` → `WORKING` →
`DONE`; прогресс виден и растёт. Появились сцены с границами по номерам кадров
и планы внутри них. Созданы листы превью, число листов соответствует
округлению числа кадров до размера листа.

**Проверяет**: FR-003, FR-010, FR-011, FR-012, FR-020, FR-021, FR-023, FR-024,
FR-092, SC-005.

**Отрицательный случай.** Искусственно оборвать внешнюю программу в середине
работы: задание обязано перейти в `ERROR` с текстом ошибки, листы превью не
должны быть отмечены как готовые, повторный запуск — продолжить работу, а не
начать с нуля молча.

**Отдельно про границы.** Сверить сохранённые границы с сырым результатом
автоматики: они совпадают до первого ручного вмешательства. Это и есть
FR-093.

### Шаг 4. Матрица кадров

**Действие.** Открыть эпизод в редакторе.

**Ожидание.** Видна матрица превью; граница плана **разрывает строку**; на
стыке страниц один и тот же план виден с обеих сторон, чтобы было понятно,
что он продолжается. Ключевые кадры отмечены отдельным знаком, границы сцен —
другим. Границы, полученные алгоритмом, и изменённые человеком окрашены
по-разному.

**Проверяет**: FR-022, FR-023, FR-015.

### Шаг 5. Поиск лиц

**Действие.** Поставить эпизод на поиск лиц.

**Ожидание.** Задание выполняется на видеокарте, прогресс виден. Лица найдены
**в каждом** кадре эпизода — общее число найденных лиц совпадает с числом
обработанных кадров, а не с их долей. У каждого лица сохранены рамка и
принадлежность к плану. Неопознанные лица не потеряны.

**Проверяет**: FR-030, FR-034, FR-035, FR-036, FR-024, ADR-0002.

**Ракурс не определяется (FR-035).** В первом срезе ракурс лица не
рассматривается: ни в одном ответе нет признака «анфас / профиль / три
четверти». Если он появился — это выход за объём среза, а не деталь.

**Отрицательный случай.** Сцена без единого лица: у плана появляется размер
«нет размера», сцена остаётся в выборке, но под фильтр «персона = X» не
подходит.

### Шаг 6. Кластеры и имена

**Действие.** Посмотреть кластеры похожих лиц, дать одному из них имя.

**Ожидание.** Кластеры — группы похожих лиц без имени. После назначения
имени лица кластера принадлежат персоне; у лица появляется персона.

**Проверяет**: FR-031, FR-033.

**Проверка качества (замер М-08).** Один человек не должен распадаться на
несколько кластеров, разные люди — сливаться. Число центров и порог слияния
подбираются здесь же и записываются в настройки фильма.

### Шаг 7. Размер плана

**Действие.** Посмотреть размеры планов, исправить один вручную.

**Ожидание.** Размер вычислен автоматически по самому крупному лицу плана из
десяти значений справочника; у плана без лиц — «нет размера». Исправленный
план помечен как исправленный оператором и **больше не пересчитывается**
автоматически.

**Проверяет**: FR-040, FR-041, FR-042, FR-043, FR-044.

**Замер (М-04).** На 200 планах эпизода оператор проставляет размер вручную,
после чего пороги подбираются под эти значения и записываются в настройки.
Ручная работа — разовая, она же основание для порогов.

### Шаг 8. Полный редактор

**Действие.** Разделить план двойным щелчком в середине плана. Объединить два
соседних плана. Отменить решение алгоритма. Нарисовать рамку лица мышью.
Перетащить миниатюру лица на персону. Назначить место действия сцене.

**Ожидание.** Каждая правка сохраняется **сама**, без кнопки «Сохранить»,
и ответ приходит сразу. При разделении плана принадлежность лиц к планам
пересчитывается: лицо, оказавшееся во второй половине, принадлежит второму
плану. Отмена решения алгоритма показана оранжевым. Нарисованное лицо
помечено «сделано человеком» и **не исчезает** при повторном анализе.

**Проверяет**: FR-013, FR-014, FR-015, FR-016, FR-032, FR-033, FR-034, FR-051,
FR-060, SC-006.

**Ключевая проверка SC-006.** После всех правок запустить анализ заново. После
завершения: все ручные границы на месте, все нарисованные лица на месте, все
имена и локации на месте. Сырой результат автоматики при этом обновился, и
разница между сырым и рабочим видна.

### Шаг 9. Место действия

**Действие.** Завести две локации в справочнике фильма, назначить их сценам.

**Ожидание.** Локация выбирается только из справочника фильма. Автоматического
определения нет ни в одном сценарии.

**Проверяет**: FR-050, FR-051, FR-052.

### Шаг 10. Обучение и версии модели

**Действие.** Пометить 10–20 лиц эталонами, задать порог распознавания,
запустить обучение. Дождаться. Добавить ещё эталонов, переобучить.

**Ожидание.** Обучение идёт **заданием очереди**, интерфейс не блокируется.
Появилась новая версия с датой, числом эталонов и составом классов; предыдущая
версия сохранена. У лица хранится версия, которой оно опознано. Повторный
анализ с новой версией не стирает метки предыдущей.

**Проверяет**: FR-060, FR-061, FR-062, FR-063, FR-065.

**Откат.** Вернуть предыдущую версию. Метки распознавания восстанавливаются
**без повторного обучения оператором**.

**Проверяет**: FR-064, SC-009.

### Шаг 11. Фильтры

**Действие.** Построить фильтр с тремя уровнями вложенности, на каждом задать
И или ИЛИ. Сохранить под именем. Применить повторно одним действием из
списка. Отредактировать и удалить.

**Ожидание.** Список сцен соответствует условию. Повторное применение — одно
действие. Фильтр с неизвестным типом условия отвергается с внятным сообщением,
а **не** возвращает пустой список.

**Проверяет**: FR-070, FR-071, FR-072, FR-073, SC-007, ADR-0008.

### Шаг 12. Выдача сценария из публичной части

**Действие.** В публичной части открыть фильм, применить сохранённый фильтр,
отметить сцены, запросить сценарий. Скачать файл сценария и подпись, забрать
открытый ключ проверки.

**Ожидание.** Сценарий инициирует **пользователь**, а не оператор. Ответ
содержит число фрагментов, ожидаемую длительность и число кадров, сумму
содержимого и идентификатор ключа. Файл сценария скачивается браузером; в
админке есть только чтение — выдать сценарий оттуда нечем.

**Проверяет**: FR-080, FR-082, FR-083, FR-084, FR-085, FR-086, FR-087, FR-088,
FR-089a, FR-089c.

**Подборка из разных эпизодов (FR-086).** Добавить сцену из другого эпизода того же
фильма: если параметры совместимы — сценарий выдаётся; если нет — отказ
**до выдачи** с перечнем несовместимых эпизодов и различающимися признаками.

**Без эталонной суммы (FR-089).** Убрать у эпизода актуальный сумму и повторить
запрос: ответ `409` с кодом `CHECKSUM_NOT_READY`, а не сценарий.

**Округление на стыках (FR-082).** В составе сценария у каждого фрагмента видны
обе пары границ: расчётная и фактическая. Разница — округление до ключевого
кадра; она равна сумме округлений на стыках.

**Каноничность (основа подписи).** Запросить сценарий с тем же набором сцен
дважды: файлы **побайтово одинаковы**. Если нет — подпись непроверяема, и это
дефект, а не особенность.

**Никакого видео (FR-088).** В ответах публичной части нет ни одного ответа с
видеосодержимым; в хранилище нет ни одного видеофайла подборок.

### Шаг 13. Установка воркера на машине пользователя

**Действие.** На машине пользователя: положить воркер, создать файл настроек
(корни каталогов, доверенный открытый ключ), создать каталог сценариев и каталог
результатов.

**Ожидание.** Воркер запускается и **до** чтения сценария проверяет среду:
`ffmpeg`, `ffprobe`, `openssl`, права на каталоги. Если чего-то нет — внятное
сообщение о том, что установить, сценарий не тронут.

**Проверяет**: ADR-0009, последствие 7.

**Отрицательный случай.** Убрать `ffmpeg` из `PATH` и положить сценарий: воркер
пишет в журнал объяснение и **не** начинает работу. Сценарий остаётся в папке.

### Шаг 14. Сборка на машине пользователя

**Действие.** Скопировать файл сценария в каталог сценариев. Дождаться работы
воркера.

**Ожидание.** В журнале видно: проверка среды, проверка подписи, проверка версии
формата, проверка структуры каталогов, сверка сумм, нарезка, склейка, отчёт,
главы, запуск показа. Рядом с готовым файлом — отчёт о выполнении с обеими
длительностями. Перезапуск воркера не поднимает показ заново.

**Проверяет**: FR-089b, FR-081, FR-083, FR-089e, FR-091, SC-004, SC-012.

**Отрицательный случай (подмена файла).** Изменить один байт в копии исходника
у пользователя и положить сценарий: воркер **отказывается** работать и называет
несовпавший файл. Нарезка не начинается вовсе.

**Отрицательный случай (подмена сценария).** Изменить один байт в файле
сценария: воркер **не выполняет** его, пишет, что подпись не сходится, и
оставляет файл на месте.

**Отрицательный случай (чужой сценарий).** Положить сценарий для другого
фильма: воркер сообщает о несовпадении фильма и ничего не выполняет.

**Отрицательный случай (структура каталогов).** Переименовать каталог сезона у
пользователя: воркер называет ожидаемый путь и останавливается.

**Отрицательный случай (прерывание).** Остановить воркер в середине нарезки:
под окончательным именем не остаётся файла; при повторном запуске работа
продолжается по кэшу сверки, а не читает диск заново.

**Замер (М-09, М-12).** Сборка из 100 сцен — замерить время целиком, включая
сверку сумм; критерий SC-004 — меньше 5 минут. Отдельно замерить сверку сумм
без кэша (М-12) на одном эпизоде и на десяти.

### Шаг 15. Локальный показ

**Действие.** Посмотреть готовый файл.

**Ожидание.** Файл воспроизводится целиком, без пропусков и зависаний. Список
сцен показывает название, персонажей и место действия каждого фрагмента;
перемотка к сцене попадает в её начало. Главы видны в плеере, понимающем главы.
**Сайт при этом не участвует**: страница открыта локально, с сервера не идёт ни
одного запроса.

**Проверяет**: FR-089d, SC-008, SC-010.

**Отрицательный случай.** Выключить сервер (или разорвать сеть) и посмотреть
файл: показ работает полностью. Если локальная страница требует сеть — сценарий
не самодостаточен, и это дефект.

### Шаг 16. Ни одного байта видео на сервере

**Действие.** Обойти хранилище и журналы сетевых обращений публичной части.

**Ожидание.** Видеофайла подборок нет нигде; по сети уходили только метаданные и
текст сценария; исходные видео не читались по сети.

**Проверяет**: SC-011, FR-088, FR-089e.

## 3. Проверки, которые выполняются один раз и фиксируются

| Проверка | Что даёт | Куда записывается |
|---|---|---|
| М-01: связка среды исполнения и видеокарты | подтверждение, что вычисления с GPU работают в контейнере | отчёт по фазе 4 |
| М-02: выбор моделей детекции и эмбеддингов | решение по моделям с числами | настройки фильма + отчёт |
| М-03: пороги границ сцен и планов | основание для SC-003 | настройки фильма + отчёт |
| М-04: пороги размера плана | основание для FR-040 | настройки фильма + отчёт |
| М-05: параллелизм очереди | основание для SC-001 | конфигурация развёртывания |
| М-06: пропускная способность канала кадров | подтверждение, что узкое место — детектор, а не передача | отчёт по фазе 3 |
| М-07: объём листов превью | подтверждение запаса SSD | отчёт по фазе 3 |
| М-08: параметры кластеризации | качество группировки | настройки фильма + отчёт |
| М-09: скорость сборки на машине пользователя | проверка SC-004 | отчёт по фазе 12 |
| М-10: время обучения | понимание нагрузки на очередь | отчёт по фазе 8 |
| М-11: скорость подсчёта `sha256` на диске архива | понимание нагрузки на задание `HASH` | отчёт по фазе 2 |
| М-12: время сверки сумм на машине пользователя | вторая половина SC-004 | отчёт по фазе 12 |
| М-13: перемотка по главам в целевом плеере | пригодность глав для SC-008 | отчёт по фазе 13 |

## 4. Критерии приёмки среза

| Критерий | Как проверяется |
|---|---|
| SC-001 | полный анализ эпизода укладывается в одну рабочую смену |
| SC-002 | оператор доводит размеченный эпизод до готового состояния за рабочий день |
| SC-003 | при первом просмотре без правки принимается не менее 95 % границ сцен |
| SC-004 | сборка из 100 сцен **на машине пользователя**, включая сверку сумм, — меньше 5 минут |
| SC-005 | ни одно задание и ни одна сборка воркером не сообщает об успехе после сбоя внутренней программы — ноль случаев |
| SC-006 | ни одна ручная правка не теряется при повторном анализе — ноль случаев |
| SC-007 | сохранённый фильтр применяется повторно за одно действие из списка |
| SC-008 | локальный файл воспроизводится полностью, без пропусков и зависаний |
| SC-009 | возврат к предыдущей версии модели восстанавливает прежние метки без повторного обучения |
| SC-010 | пользователь проходит весь путь сам: фильтр, выбор, сценарий, папка, воркер, показ |
| SC-011 | ни один байт исходного видео не покидает машину администратора; в хранилище нет видеофайлов подборок |
| SC-012 | воркер отказывается выполнять сценарий при несовпадении хотя бы одной суммы и называет файл |

Требования FR-100, FR-101 и FR-102 проверяются не маршрутом, а осмотром: каждый
публичный метод документирован и ссылается на
[`../../docs/features/first-vertical-slice.md`](../../docs/features/first-vertical-slice.md);
этот документ обновлён в том же изменении, что и контракты; ни одного
отображения объектов в коде нет, все миграции — нумерованные и добавочные.

SC-003, SC-005 и SC-012 проверяются выборкой и подсчётом, а не ощущением:
границы пересматриваются по списку, случаи сбоя фиксируются при каждом прогоне,
подмены выполняются по одному сценарию на каждый отрицательный случай.
