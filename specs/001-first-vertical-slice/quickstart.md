# Quickstart: сквозная проверка первого среза

**Feature**: 001-first-vertical-slice
**Назначение**: проверочный маршрут, доказывающий, что срез работает от
исходного файла до просмотра готового видео. Это **руководство по проверке**,
а не описание реализации: тела методов, тексты миграций и полные наборы тестов
живут в задачах и в фазе реализации.

**Тестовая серия**: `GOT.S01E01.BDRip.1080p.mkv` — 1920×1080, 23,976 fps,
3697 с, 82 834 кадра. Одна серия, как и требует срез.

**Ссылки**: [контракт админки](contracts/admin-api.md),
[контракт публичной части](contracts/public-api.md),
[контракт очереди](contracts/job-queue.md),
[модель данных](data-model.md).

## 1. Предпосылки

| Что | Как проверить |
|---|---|
| Шесть контейнеров подняты | `cd deploy && bash do.sh status` |
| Миграции применены | все семь файлов `deploy/syp-db/*.sql` применены по порядку |
| Серия зарегистрирована в базе | её параметры совпадают с ожидаемыми: 82 834 кадра, 1920×1080 |
| Настройки сериала созданы | девять значений по умолчанию присутствуют |
| Архив доступен на чтение | `docker exec syp-admin-app ls -l <путь к файлу серии>` |
| GPU видна контейнеру | `docker exec syp-admin-app nvidia-smi` показывает карту |

**Ловушка среды агента.** Проверки прав на дисках из агентской сессии
недействительны: внутри неё всё смонтировано только для чтения, включая корень,
в который писать можно. Все проверки хранения выполняются **внутри
контейнера**. `ffmpeg` в агентской сессии обрывается на длинных операциях —
замеры видео-части оттуда недействительны.

## 2. Маршрут проверки

Маршрут идёт по порядку пользовательского пути. Каждый шаг указывает, что
проверяется и каким требованием закрывается.

### Шаг 1. Приём серии

**Действие.** Создать сериал, добавить серию указанием пути к файлу.

**Ожидание.** Система сама определила и сохранила: число кадров, частокадровую
базу, разрешение, длительность, кодек, профиль, формат пикселей, параметры
аудио, карту ключевых кадров. Значения совпадают с измеренными: 82 834 кадра,
1920×1080, 23,976 fps.

**Проверяет**: FR-001, FR-002.

**Отрицательный случай.** Указать путь к несуществующему файлу: система
возвращает внятную ошибку со значением `SOURCE_UNREADABLE`, а не «успех с
пустым результатом».

### Шаг 2. Анализ структуры

**Действие.** Поставить серию на анализ и дождаться завершения задания.

**Ожидание.** Задание проходит состояния `WAITING` → `CREATING` → `WORKING` →
`DONE`; прогресс виден и растёт. Появились сцены с границами по номерам кадров
и планы внутри них. Созданы листы превью, число листов соответствует
округлению числа кадров до размера листа.

**Проверяет**: FR-003, FR-010, FR-011, FR-012, FR-020, FR-023, SC-005.

**Отрицательный случай.** Искусственно оборвать внешнюю программу в середине
работы: задание обязано перейти в `ERROR` с текстом ошибки, листы превью не
должны быть отмечены как готовые, повторный запуск — продолжить работу, а не
начать с нуля молча.

**Отдельно про границы.** Сверить сохранённые границы с сырым результатом
автоматики: они совпадают до первого ручного вмешательства. Это и есть
FR-093.

### Шаг 3. Матрица кадров

**Действие.** Открыть серию в редакторе.

**Ожидание.** Видна матрица превью; граница плана **разрывает строку**; на
стыке страниц один и тот же план виден с обеих сторон, чтобы было понятно,
что он продолжается. Ключевые кадры отмечены отдельным знаком, границы сцен —
другим. Границы, полученные алгоритмом, и изменённые человеком окрашены
по-разному.

**Проверяет**: FR-022, FR-023, FR-015.

### Шаг 4. Поиск лиц

**Действие.** Поставить серию на поиск лиц.

**Ожидание.** Задание выполняется на видеокарте, прогресс виден. Лица найдены
**в каждом** кадре серии — общее число найденных лиц совпадает с числом
обработанных кадров, а не с их долей. У каждого лица сохранены рамка и
принадлежность к плану. Неопознанные лица не потеряны.

**Проверяет**: FR-030, FR-034, FR-036, ADR-0002.

**Отрицательный случай.** Сцена без единого лица: у плана появляется размер
«нет размера», сцена остаётся в выборке, но под фильтр «персона = X» не
подходит.

### Шаг 5. Кластеры и имена

**Действие.** Посмотреть кластеры похожих лиц, дать одному из них имя.

**Ожидание.** Кластеры — группы похожих лиц без имени. После назначения
имени лица кластера принадлежат персоне; у лица появляется персона.

**Проверяет**: FR-031, FR-033.

**Проверка качества (замер М-08).** Один человек не должен распадаться на
несколько кластеров, разные люди — сливаться. Число центров и порог слияния
подбираются здесь же и записываются в настройки сериала.

### Шаг 6. Размер плана

**Действие.** Посмотреть размеры планов, исправить один вручную.

**Ожидание.** Размер вычислен автоматически по самому крупному лицу плана из
десяти значений справочника; у плана без лиц — «нет размера». Исправленный
план помечен как исправленный оператором и **больше не пересчитывается**
автоматически.

**Проверяет**: FR-040, FR-041, FR-042, FR-043, FR-044.

**Замер (М-04).** На 200 планах серии оператор проставляет размер вручную,
после чего пороги подбираются под эти значения и записываются в настройки.
Ручная работа — разовая, она же основание для порогов.

### Шаг 7. Полный редактор

**Действие.** Разделить план двойным щелчком в середине плана. Объединить два
соседних плана. Отменить решение алгоритма. Нарисовать рамку лица мышью.
Перетащить миниатюру лица на персону. Назначить место действия сцене.

**Ожидание.** Каждая правка сохраняется **сама**, без кнопки «Сохранить»,
и ответ приходит сразу. При разделении плана принадлежность лиц к планам
пересчитывается: лицо, оказавшееся во второй половине, принадлежит второму
плану. Отмена решения алгоритма показана оранжевым. Нарисованное лицо
помечено «сделано человеком» и **не исчезает** при повторном анализе.

**Проверяет**: FR-013, FR-014, FR-015, FR-016, FR-032, FR-033, FR-034, FR-051,
FR-060, SC-006.

**Ключевая проверка SC-006.** После всех правок запустить анализ заново. После
завершения: все ручные границы на месте, все нарисованные лица на месте, все
имена и локации на месте. Сырой результат автоматики при этом обновился, и
разница между сырым и рабочим видна.

### Шаг 8. Место действия

**Действие.** Завести две локации в справочнике сериала, назначить их сценам.

**Ожидание.** Локация выбирается только из справочника сериала. Автоматического
определения нет ни в одном сценарии.

**Проверяет**: FR-050, FR-051, FR-052.

### Шаг 9. Обучение и версии модели

**Действие.** Пометить 10–20 лиц эталонами, задать порог распознавания,
запустить обучение. Дождаться. Добавить ещё эталонов, переобучить.

**Ожидание.** Обучение идёт **заданием очереди**, интерфейс не блокируется.
Появилась новая версия с датой, числом эталонов и составом классов; предыдущая
версия сохранена. У лица хранится версия, которой оно опознано. Повторный
анализ с новой версией не стирает метки предыдущей.

**Проверяет**: FR-060, FR-061, FR-062, FR-063, FR-065.

**Откат.** Вернуть предыдущую версию. Метки распознавания восстанавливаются
**без повторного обучения оператором**.

**Проверяет**: FR-064, SC-009.

### Шаг 10. Фильтры

**Действие.** Построить фильтр с тремя уровнями вложенности, на каждом задать
И или ИЛИ. Сохранить под именем. Применить повторно одним действием из
списка. Отредактировать и удалить.

**Ожидание.** Список сцен соответствует условию. Повторное применение — одно
действие. Фильтр с неизвестным типом условия отвергается с внятным сообщением,
а **не** возвращает пустой список.

**Проверяет**: FR-070, FR-071, FR-072, FR-073, SC-007, ADR-0008.

### Шаг 11. Сборка из публичной части

**Действие.** В публичной части открыть сериал, применить сохранённый фильтр,
отметить сцены, запустить сборку. Дождаться. Воспроизвести файл.

**Ожидание.** Сборка инициируется **пользователем**, а не оператором. Задание
с прогрессом; перезагрузка страницы задание не теряет. После завершения видео
воспроизводится целиком, видно список вошедших сцен и обе длительности, если
они разошлись.

**Проверяет**: FR-080, FR-081, FR-082, FR-083, FR-084, FR-085, FR-088, SC-004,
SC-008, SC-010.

**Подборка из разных серий (FR-086).** Добавить сцену из другой серии того же
сериала: если параметры совместимы — сборка проходит; если нет — отказ
**до начала работы** с перечнем несовместимых серий и различающимися
признаками.

**Расхождение длительностей (FR-083).** Расчётная длительность считается по
сумме кадров планов, фактическая измеряется заново. Расхождение равно сумме
округлений до ключевых кадров на стыках и сопровождается объяснением.

**Замер (М-09).** Сборка из 100 сцен — замерить время ожидания; критерий
SC-004 — меньше 5 минут.

## 3. Проверки, которые выполняются один раз и фиксируются

| Проверка | Что даёт | Куда записывается |
|---|---|---|
| М-01: связка среды исполнения и видеокарты | подтверждение, что GPU работает в контейнере | отчёт по фазе 2 |
| М-02: выбор моделей детекции и эмбеддингов | решение по моделям с числами | настройки сериала + отчёт |
| М-03: пороги границ сцен и планов | основание для SC-003 | настройки сериала + отчёт |
| М-04: пороги размера плана | основание для FR-040 | настройки сериала + отчёт |
| М-05: параллелизм очереди | основание для SC-001 | конфигурация развёртывания |
| М-06: пропускная способность канала кадров | подтверждение, что узкое место — детектор, а не передача | отчёт по фазе 2 |
| М-07: объём листов превью | подтверждение запаса SSD | отчёт по фазе 2 |
| М-08: параметры кластеризации | качество группировки | настройки сериала + отчёт |
| М-09: скорость сборки | проверка SC-004 | отчёт по фазе 9 |
| М-10: время обучения | понимание нагрузки на очередь | отчёт по фазе 7 |

## 4. Критерии приёмки среза

| Критерий | Как проверяется |
|---|---|
| SC-001 | полный анализ серии укладывается в одну рабочую смену |
| SC-002 | оператор доводит размеченную серию до готового состояния за рабочий день |
| SC-003 | при первом просмотре без правки принимается не менее 95 % границ сцен |
| SC-004 | сборка из 100 смен — меньше 5 минут ожидания |
| SC-005 | ни одно задание не сообщает об успехе после сбоя внутренней программы — ноль случаев |
| SC-006 | ни одна ручная правка не теряется при повторном анализе — ноль случаев |
| SC-007 | сохранённый фильтр применяется повторно за одно действие из списка |
| SC-008 | видеофайл подборки воспроизводится полностью, без пропусков и зависаний |
| SC-009 | возврат к предыдущей версии модели восстанавливает прежние метки без повторного обучения |
| SC-010 | пользователь получает подборку без обращения к администратору |

SC-003 и SC-005 проверяются выборкой и подсчётом, а не ощущением: границы
пересматриваются по списку, случаи сбоя фиксируются при каждом прогоне.
