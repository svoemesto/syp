# Воркер SYP — программа на машине пользователя

## Что это

Воркер выполняет сценарий сборки на машине пользователя. Он **не является**
контейнером SYP: у него нет доступа к базе и хранилищу сервера, он не
собирается тем же конвейером, что серверные части, и его нельзя положить в
`Gradle` или `docker compose` (ADR-0009, ADR-0011, `plan.md` § «Project
Structure»).

Сценарий — **данные, а не исполняемый сценарий оболочки**. Воркер не запускает
найденный файл через `bash` и не исполняет пришедшие команды: он разбирает
сценарий как структурированные данные. Причина прямая — файл приходит из
интернета, и его подмена привела бы к выполнению чужого кода на машине
пользователя (`plan.md` § «Ключевые решения плана», решение 1).

## Что воркер делает

1. Наблюдает каталог со сценариями (`inbox`).
2. Находит сценарий, проверяет его версию формата.
3. **До разбора** проверяет подпись Ed25519 открытым ключом.
4. **До нарезки** сверяет `sha256` каждого исходного файла со снимком суммы
   в сценарии.
5. Режет фрагменты и склеивает их потоковым копированием, без
   перекодирования.
6. Кладёт рядом локальную страницу со списком сцен и запускает показ.
7. Пишет отчёт о выполнении **у себя**, на машине пользователя.

## Чего воркер не делает

- Не собирает подборку «по сети» и не обращается к серверу за недостающими
  данными: сценарий самодостаточен (FR-089d).
- Не правит границы, заданные сценарием, и не «улучшает» их: округление до
  ключевого кадра — зафиксированное решение владельца (ADR-0006).
- Не перекодирует видео (ADR-0006, Р-01).
- Не загружает готовый файл обратно на сервер: байты видео не покидают машину
  пользователя (SC-011, FR-089e).

## Правила, которые воркер обязан соблюдать

Это те же правила, что у очереди заданий сервера
(`specs/001-first-vertical-slice/contracts/job-queue.md`, раздел 4.1):

1. **Код возврата внешней программы проверяется всегда.** Упавший `ffmpeg`
   даёт ошибку в журнале и ненулевой код возврата, а не «готово». В старом
   проекте не проверял код возврата ни один из двенадцати вызовов ffmpeg —
   повторение этого дефекта означало бы, что битый файл выдаётся за подборку.
2. **Атомарная запись результата:** файл появляется под окончательным именем
   только целиком.
3. **Идемпотентность по входам:** сверка `sha256` кэшируется по паре «размер +
   время изменения»; повторный запуск того же сценария не читает диск заново,
   но и не пропускает проверку при изменённом файле.
4. **Подпись проверяется до разбора сценария**, суммы источников — до
   нарезки. Первый запуск на машине — единственное исключение: проверка
   подписи ослаблена осознанно, ключ получается с сервера, ослабление
   записывается в журнал, и со второго запуска оно не повторяется
   (FR-089h). **Суммы источников проверяются всегда, без исключений.**

## Установка без сборки

Воркер написан на Python 3 и использует **только стандартную библиотеку**.
Сборка не нужна: файлы копируются как есть.

### Требования

| Что | Версия | Зачем |
|---|---|---|
| Python | 3.9 или новее | стандартная библиотека, без внешних пакетов |
| `ffmpeg` и `ffprobe` | 6.x | нарезка и склейка потоковым копированием |
| `openssl` | 1.1 или новее | проверка подписи Ed25519 |
| Python-модуль `cryptography` | по возможности | ускоряет проверку подписи |

Модуль `cryptography` **не обязателен**: при его отсутствии воркер проверяет
подпись через `openssl`. Ставить ничего не нужно — файл `syp_worker.py`
запускается как есть.

### Установка

```bash
# 1. Положить каталог воркера в удобное место, например ~/syp-worker
cd ~/syp-worker

# 2. Проверить, что всё необходимое есть
python3 --version
ffmpeg -version | head -1
openssl version

# 3. Создать настройки из примера
cp config.example.json config.json

# 4. Вписать в config.json свои пути и доверенный открытый ключ
#    (ключ берётся у воркера: GET /api/recipes/verification-key)

# 5. Запустить
python3 syp_worker.py --config config.json
```

Скрипт делается исполняемым: `chmod +x syp_worker.py` и запуск
`./syp_worker.py`. Ничего собирать не нужно.

## Формат файла настроек

Файл `config.json` — обычный JSON в кодировке UTF-8. Описание полей — в
`config.example.json`, где ключи записаны с пустыми значениями: пример не
должен содержать ни одного рабочего секрета.

| Ключ | Что это |
|---|---|
| `serial_root` | корень дерева исходников у пользователя; пути из сценария отсчитываются от него (FR-089a) |
| `inbox` | каталог, куда пользователь кладёт скачанный сценарий |
| `output` | каталог для готового файла, отчёта и локальной страницы |
| `log` | путь журнала выполнения |
| `trusted_public_key` | открытый ключ подписи в base64, полученный у воркера |
| `trusted_key_id` | идентификатор ключа, которым подписан сценарий |
| `ffmpeg_path` | путь к `ffmpeg`; по умолчанию берётся из `PATH` |
| `ffprobe_path` | путь к `ffprobe`; по умолчанию берётся из `PATH` |
| `verify_source_checksums` | проверять ли `sha256` источников; `true` по умолчанию и не рекомендуется выключать |

Путь `serial_root` у пользователя **свой**: у него своя копия дерева под своим
корнем. Сценарий обращается к файлам по относительным путям именно поэтому.
