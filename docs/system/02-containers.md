# L2: Контейнеры

Шесть контейнеров. Каталог фронтенда совпадает с именем контейнера.

## Состав

| Контейнер | Роль | Аналог в Karaoke |
|---|---|---|
| `syp-db` | PostgreSQL 16, база проекта | `karaoke-db` |
| `syp-storage` | MinIO, объектное хранилище: превью кадров, промежуточные файлы | `karaoke-storage` |
| `syp-admin-app` | Бэкенд админки: разметка, анализ, очередь заданий | `karaoke-app` |
| `syp-admin-web` | Фронтенд админки (Vue 3 + nginx) | `karaoke-webvue3` |
| `syp-public-app` | Бэкенд публичной части: выдача сценария сборки. **Без исполнителя заданий** | `karaoke-web` |
| `syp-public-web` | Фронтенд публичной части (Vue 3 + nginx) | `karaoke-public` |

## Разграничение ответственности

**Админка** (`syp-admin-*`) — всё, что делает человек при подготовке:
разметка, обучение моделей, настройки.

**Публичная часть** (`syp-public-*`) — только то, что делает пользователь с
готовым: выбор фильтра, выбор сцен, получение сценария сборки. Ни видео, ни
исполнителя заданий здесь нет (ADR-0009, FR-085, FR-088).

Смешивать ответственность двух фронтендов **запрещено**.

## Где что хранится

| Данные | Где | Почему |
|---|---|---|
| Исходные видео | `/disks/HDD_16Tb_Clouds/GOT` | Только чтение, никогда не изменяются. |
| Превью кадров, промежуточные файлы | SSD (`/disks/SSD_2Tb_Files`) | Быстрый доступ, 609 ГБ свободно. |
| Сценарии сборки (канонические байты) | SSD (`/disks/SSD_2Tb_Files`) | Мало: это текст, а не видео. |
| **Готовые видеофайлы подборок** | **на машине пользователя** | Сервер их не хранит и не передаёт (FR-088, FR-089e). |
| База данных | `syp-db` | Границы, сцены, планы, лица, персоны, фильтры, версии моделей, справочник сумм, сценарии сборки. |

## Правила работы с контейнерами

1. Сборка и перезапуск — только через `deploy/do.sh`; `docker restart`
   запрещён.
2. Перед перезапуском — остановить очередь и дождаться, пока задания
   закончатся.
3. Gradle запускается с `GRADLE_USER_HOME`, docker — с `DOCKER_CONFIG`.
5. Воркер на машине пользователя **не является седьмым контейнером**: он не
   входит в этот стек, не имеет доступа к базе и хранилищу сервера и
   устанавливается пользователем вручную.
4. При разборе сбоя — сначала `docker logs`, потом гипотезы.
