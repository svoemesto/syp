Этот каталог — **Single Source of Truth (SSoT)** для архитектуры SYP.
Описывает **текущее состояние** системы, а не историю изменений.

**Core Principle**: документация — не запись о том, что мы *делали*; это
определение того, что система *есть*. Изменился код — изменилась документация.

## Navigation Map

### 1. Системная архитектура (C4 Model)

Навигация от верхнего контекста к техническим компонентам.

- **L1: Контекст системы**: [system/01-context.md](system/01-context.md) —
  место SYP в мире, кто им пользуется.

### 2. Архитектурное управление

- **ADR (это «почему»)**: [adr/](adr/) — только добавляемые записи решений.
  Действующими считаются ADR со статусом `Accepted`.
- **Epics (это «куда движемся»)**: [epics/](epics/) — стратегические переходы,
  затрагивающие несколько доменов.
- **Guidelines**: [guidelines/](guidelines/) — стандартные паттерны и
  ограничения.
- **Backlog**: [BACKLOG.md](BACKLOG.md) — что ещё не сделано.

### 3. Плейбуки (как делать)

- **How-to**: [howto/](howto/) — пошаговые кросс-доменные процедуры.
  Формат: один каталог на плейбук, `howto/<slug>/playbook.md`.
  **Правило**: how-to по природе кросс-доменный и не размещается внутри
  `components/`; доменный компонент фиксирует возможность или инвариант,
  а не рецепт.
- **Каталог плейбуков**: все плейбуки обязательно перечислены ниже.
  Пока плейбуков нет.

### 4. Публичные проекции

- **Public Specs**: [public/](public/) — человекочитаемые проекции внутренней
  документации. Это выходы, а не источники: для технического исследования ими
  не пользуются.

### 5. Шаблоны и инструменты

- **Шаблоны**: [templates/](templates/) — структуры для новых доменов,
  компонентов, ADR и эпиков.
- **Линтер**: [scripts/lint-docs.py](scripts/lint-docs.py) — обязателен к
  запуску перед коммитом: `python3 docs/scripts/lint-docs.py`.
- **Память проекта**: [STATE-OF-PLAY.md](STATE-OF-PLAY.md) — точка подхвата
  между сессиями, читается первой.

## Правила работы с этой базой

1. **Hard Gate**: не искать по `docs/` до чтения этого файла.
2. Документация описывает **текущее состояние**, а не изменения.
3. Новые файлы — по шаблонам `templates/`.
4. При изменении кода документация мутирует **в том же изменении**.
5. Проверка: `python3 docs/scripts/lint-docs.py` — без ошибок.
