# Эталон целостности исходников сериала

## Что это

Файл `GOT.sha256` — контрольные суммы `sha256` всех исходных видеофайлов
сериала на машине администратора. Пути в нём **относительные от корня
сериала**, поэтому структура каталогов у пользователя должна повторять эту
же (FR-089a).

```bash
# проверка на машине пользователя — из корня сериала
sha256sum -c GOT.sha256
```

## Назначение

Сценарий сборки, который пользователь скачивает с сайта, **безнадёжен, если
файлы подменены**: он вырежет кадры из другого видео и склеит «сцену»,
которой не существует. Поэтому воркер сверяет суммы **до** нарезки, а не
после (FR-089, ADR-0009).

## Проверено

- 73 файла, 8 сезонов, 360 ГБ;
- расчёт занял 44 минуты при 135 МБ/с чтения;
- выборочная перепроверка одного файла (5,2 ГБ) — результат «ЦЕЛ», 39 секунд;
- пути относительные, сортировка в C-локали — эталон воспроизводим на
  любой машине независимо от настроек локали.

## Как это используется

Полная сверка при первом запуске. При повторных запусках допускается сверка
по признакам «размер + время изменения» с кэшем (FR-089g) — воркер обязан
показывать, по какому признаку файл признан совпадающим, потому что при
кеше подмена с сохранением размера и даты останется незамеченной. Это
осознанный размен, а не дефект.

## Куда это движется

Файл лежит в репозитории как **версионированный эталон**. В системе
эти данные переезжают в таблицу справочника сумм исходника
(`data-model.md`, сущность 2.19): одна активная запись на файл, история
пересчётов, снимок сумм попадает в сценарий. Репозиторий остаётся источником
правды для офлайн-проверки, база — для работы системы.

## Пересчёт

Эталон становится недействительным, если переписаны исходники. Пересчёт
делается целиком, с проверкой числа строк, во временный файл с последующим
переименованием: **неполный эталон хуже отсутствующего** — он молча отвергнет
у пользователя корректные файлы.
