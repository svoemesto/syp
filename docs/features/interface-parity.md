# Фича: соответствие интерфейса формам старого проекта

**Спецификация**: [`specs/001-first-vertical-slice/spec.md`](../../specs/001-first-vertical-slice/spec.md)
**Источник истины по составу форм**: [`docs/research/legacy-ui-map.md`](../research/legacy-ui-map.md)
**Статус**: перенос начат; события вынесены полностью, работа по ним — на заглушках

**Зачем этот документ.** Владелец указал: сначала интерфейс целиком приводится к
старым формам, включая события, а работа с бекендом по событиям ставится на
заглушки. После того как весь интерфейс перенесён и работает, по заглушкам
проходят и выясняют, что каждая из них должна делать на самом деле. Поэтому
документ описывает **состав и порядок переноса**, а не поведение событий.

## Что переносится

Одиннадцать форм старого проекта разобраны в
[`legacy-ui-map.md`](../research/legacy-ui-map.md). Перенос идёт от главного
редактора, потому что остальные формы открываются из него.

| Форма | Старший элемент | Состояние переноса |
|---|---|---|
| `shots-edit-view` | вкладки Frames, Persons, Scenes, Events | переносится, Events — с заглушками |
| `project-actions-view` | таблица файлов, чекбоксы операций, кнопка Train face model | переносится |
| `frame-faces-edit-view` | лица одного кадра | переносится |
| `person-select-view` | выбор персоны с поиском | переносится |
| `person-edit-view` | свойства персоны, имя, фото | переносится |
| `filter-edit-view` | три уровня: фильтры, группы, условия | переносится |
| `filter-condition-create-view` | создание условия | переносится |
| `project-edit-view` | главное окно, меню, четыре таблицы свойств | переносится |
| `project-select-view` | выбор проекта | переносится |
| `database-select-view` | выбор базы | переносится |
| `database-edit-view` | свойства базы | переносится |

## Структура главного редактора

Левая часть — планы. Правая — четыре вкладки, как в старом проекте.

- **Frames**: холст матрицы миниатюр кадров, таблица страниц кадров с
  колонками «Время: с», «Время: по», «Кадры: с», «Кадры: по», полоса прогресса.
- **Persons**: список персон файла с фото, холст матрицы миниатюр лиц, таблица
  страниц лиц.
- **Scenes**: таблица сцен с множественным выбором, планы выбранных сцен,
  персоны выбранных сцен, свойства сцены, кнопки создания и удаления.
- **Events**: полный аналог Scenes. Таблица событий с множественным выбором,
  планы выбранных событий, персоны выбранных событий, свойства события, кнопки
  создания и удаления.

## Порядок работы

1. Каркас главного редактора: левая часть с планами и четыре вкладки.
2. Вкладка Scenes — на существующих данных.
3. Вкладка Events — на заглушках, с видимой пометкой заглушки.
4. Вкладки Frames и Persons — на существующих данных.
5. Всплывающие формы: лица кадра, выбор персоны, свойства персоны.
6. Экран операций над проектом, включая кнопку обучения модели.
7. Фильтры: три уровня и создание условия.
8. Окна проекта и базы.

## События: что значит «заглушка»

Событие в старом проекте — полный аналог сцены: та же таблица с множественным
выбором, те же планы, те же персоны, те же свойства, кнопки создания и удаления.

Заглушка означает: форма, разметка, элементы, подписи, порядок колонок и все
действия оператора **присутствуют и работают поверх правки на стороне браузера**,
но не ходят в бэкенд. Данные событий — заранее заданный пример в том же виде, в
каком их отдавал бы сервер. Каждая заглушка помечена в интерфейсе, чтобы её
нельзя было принять за работающую функцию: молчаливая заглушка хуже отсутствия.

## Дефекты старого проекта, которые не переносятся

Соответствие — формам, а не ошибкам. Перечисленное ниже в старом проекте не
работает или неверно, и повторять это нельзя.

| Дефект | Решение |
|---|---|
| `Delete selected scenes` — обработчик с пустым телом, действие отсутствует | кнопка удаления сцен работает |
| `Create Event Based Scene` создаёт событие, а не сцену | переименование по тому, что кнопка действительно делает |
| на вкладке Events два индикатора названы именами сцен, из-за чего прогресс не отображается | индикаторы Events названы своими именами и отображаются |
| клавиатурный плеер: `Z`, `X` и признаки состояния присваиваются и нигде не читаются | либо работает, либо отсутствует; заготовок без поведения нет |
| английская заглушка `Label` в индикаторе | подпись настоящая |
| смешение языков: вкладки, блоки и кнопки подписаны по-английски | единый язык интерфейса |
| тултипы кнопок свойств повторяют шаблон списка файлов | тултипы по своему назначению |

## Порядок прогона по заглушкам

Когда интерфейс перенесён и работает, по каждой заглушке события выясняется:

1. Что делала та же форма в старом проекте.
2. Что она должна делать в нашем, с учётом нашей модели: сцены и планы, а не
   файлы видео.
3. Чем это отличается от того, что сделала заглушка, и какие данные для этого
   нужны.

Выводы пишутся сюда же, раздел «События», и заменяют заглушку по одной.
