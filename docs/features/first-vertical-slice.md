# Фича: первый сквозной вертикальный срез (схема «рецепт»)

**Спецификация**: [`specs/001-first-vertical-slice/spec.md`](../../specs/001-first-vertical-slice/spec.md)
**План**: [`specs/001-first-vertical-slice/plan.md`](../../specs/001-first-vertical-slice/plan.md)
**Задача**: OpenProject, проект `syp` (id 4), **#226**
**Статус**: спроектировано, реализация не начата

**Зачем этот документ.** Требование FR-101: у каждой фичи ведётся отдельный
документ, и он обновляется в том же изменении, что и код. FR-100: каждый
публичный API документирован со ссылкой сюда. Документ описывает фичу **в
терминах предметной области**, а не устройство кода.

## Что делает фича

Оператор берёт серию из архива, запускает анализ, получает сцены и планы с
найденными лицами, доводит результат руками — границы, имена, место действия,
эталоны. Пользователь в публичной части применяет фильтр, выбирает сцены и
**получает сценарий сборки**. На своей машине он кладёт сценарий в папку, воркер
проверяет подпись и суммы файлов, режет и склеивает файл **без перекодирования**,
после чего запускается локальный показ со списком сцен.

Один проход без участия человека: серия в архиве → готовый локальный файл «Show
Your Picture» на машине пользователя.

**Ключевое отличие от прежней схемы.** Сервер **не производит видео**: он
формирует рецепт (ADR-0009). Видеофайлы подборок не хранятся, не принимаются и
не передаются; готовый файл остаётся у пользователя.

## Границы фичи

| Внутри | Снаружи |
|---|---|
| Приём сериала и серии, параметры файла, корень каталога | Публикация в интернет, работа вне локальной машины |
| Границы сцен и планов, доводка оператором | Распознавание ракурса лица, позы, ключевых точек |
| Превью кадров и матрица кадров | Автоматическое определение мест действия |
| Поиск лиц в каждом кадре, эмбеддинги, кластеры | Иерархические теги |
| Имена персонажей, эталоны, версии модели, откат | Тип плана по числу людей |
| Размер плана: автоматически и вручную | Перекодирование видео, потерянный мастер |
| Справочник мест действия и назначение вручную | Анализ всех серий архива до отладки на одной |
| Фильтры: три уровня, сохранение, повторное применение | Полноценная модель дорожек |
| Справочник `sha256` исходников | Автоматическая доставка сценария пользователю |
| Формирование и подпись сценария сборки | Хранение и выдача готового видео |
| Воркер на машине пользователя | — |
| Локальный показ со списком сцен | — |

## Сценарии использования

1. **Оператор размечает серию** (P1). Берёт серию, запускает анализ, видит
   сцены и планы с найденными лицами, правит границы и назначает имена.
2. **Оператор обучает распознавание** (P2). Отмечает эталоны, обучает, лица
   получают имена; предыдущая версия модели сохраняется и доступна для
   возврата.
3. **Оператор готовит данные** (P2). Строит фильтр по персонажам и местам
   действия, проверяет, что у серий посчитаны суммы исходников.
4. **Пользователь получает подборку у себя** (P3). Открывает сериал, применяет
   фильтр, выбирает сцены, запрашивает сценарий, скачивает его, кладёт в папку,
   запускает воркер, смотрит локальный файл со списком сцен. Именно он инициирует
   всё это — оператор подготавливает данные, но не собирает за него.

## Ключевые сущности

Сериал, серия, сцена, план, кадр, лицо, персона, место действия, фильтр,
версия модели, задание, **справочник сумм**, **сценарий сборки**, **фрагмент
сценария**. Полное описание полей, ограничений и связей —
[`data-model.md`](../../specs/001-first-vertical-slice/data-model.md).

Сущностей «сборка» с готовым видеофайлом в модели **нет**: на машине
пользователя файл появляется из фрагментов сценария и обратно не возвращается.

## Правила, которые этот документ защищает

1. **Номер кадра — единственный источник правды для границ.** Время
   вычисляется от него, а не хранится рядом.
2. **План лежит в сцене целиком.** Частичное пересечение не допускается.
3. **Лица ищутся в каждом кадре.** Адаптивный шаг не вводится.
4. **Кадры исходного разрешения не хранятся.** Только превью и результаты
   анализа.
5. **Ручная правка не теряется** при повторном анализе; сырой результат
   автоматики хранится отдельно.
6. **Задание не сообщает об успехе**, если внутренняя программа завершилась с
   ошибкой. То же правило действует в воркере на машине пользователя.
7. **Незавершённый файл не считается готовым.**
8. **Склейка не перекодирует** видео; округление до ключевого кадра на стыках —
   осознанное допущение, обе длительности показываются.
9. **Сценарий — данные, а не программа.** Воркер не выполняет файл, он его
   разбирает.
10. **Подпись проверяется до выполнения, суммы — до нарезки.** Подмена,
    обнаруженная через час работы, недопустима.
11. **Сценарий не выдаётся без актуальной суммы исходников** и при
    несовместимых сериях — отказ приходит до работы, а не после.
12. **Публичная часть не хранит, не принимает и не передаёт видео.** Эндпоинта с
    видеосодержимым не существует.
13. **Публичный бэкенд не имеет исполнителя заданий:** собрать подборку за
    пользователя нечем.
14. **Готовый файл и отчёт о выполнении остаются у пользователя.**
15. **Фильтры выполняются одним универсальным механизмом**; неподдерживаемое
    сочетание даёт явную ошибку, а не пустой результат.
16. **Обучение — задание очереди**, а не кнопка, блокирующая интерфейс.
17. **Публичная часть только показывает результат и выдаёт сценарий**; разметки и
    обучения в ней нет.
