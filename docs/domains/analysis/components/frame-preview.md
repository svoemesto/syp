# Спецификация компонента: Превью кадров

Домен: [Analysis](../domain.md). Спецификация: `specs/001-first-vertical-slice/`.
Происхождение: план `007-speckit-plan-recipe`; правка по ADR-0009 — снято
разделение носителей, готового видео на сервере не бывает.

## Ответственность | Responsibility

Компонент отвечает за **изготовление и выдачу уменьшенных превью кадров
серии** так, чтобы интерфейс мог показать матрицу кадров, не обращаясь к
исходному видеофайлу и не запрашивая по одному кадру.

Компонент **не хранит** кадры в исходном разрешении: изображение исходного
кадра в системе отсутствует, в хранилище попадают только уменьшенные
превью и результаты анализа.

## Интерфейсы и Контракты | Interfaces and Contracts

- **Изготовление листов**: серия, диапазон кадров → листы превью,
  зарегистрированные как готовые артефакты. Вызывается заданием анализа.
- **Выдача листа**: серия, номер листа → изображение листа.
- **Выдача страницы матрицы**: серия, диапазон кадров, размер окна →
  список позиций кадров с указанием листа и области кадрирования для каждой.
- **Смещение страницы**: текущая страница и шаг колеса → соседняя страница.

## Логика и Алгоритмы

1. **Лист, а не отдельный файл.** Превью упаковываются в сетку фиксированного
   размера: 16 на 16 превью по 135×75, то есть 256 кадров на лист. Листы
   нумеруются по порядку и отражают последовательность кадров серии без
   пропусков. Причина — количество запросов: поштучное хранение потребовало бы
   десятков тысяч запросов на одну серию и не давало бы атомарности на уровне
   страницы матрицы.
2. **Лист появляется целиком.** Запись идёт во временный ключ, после
   успешного завершения внешней программы — перенос на окончательный, и
   только затем регистрация как готового артефакта. Незавершённый лист не
   считается готовым.
3. **Нумерация кадров с нуля.** Раскладка листа и номера кадров считаются от
   одной нумерации; расхождение на единицу дало бы постоянный сдвиг
   превью относительно границ.
4. **Матрица разрывает строку на границе плана.** Состав страницы вычисляется
   сервером по размеру окна: если следующий кадр начинает новый план, он
   начинает новую строку, а не следующую ячейку. На стыке страниц крайний
   план показывается с обеих сторон, чтобы оператор видел, что он
   продолжается.
5. **Значимые кадры не выделяются пустотой.** В ячейке всегда превью; признаки
   границы, ключевого кадра и наличия лиц накладываются поверх, а не
   заменяют изображение.
6. **Повторное изготовление листа не требует повторного декодирования всей
   серии**: листы независимы, переделывается только нужный диапазон.

## Зависимости | Dependencies

- → очередь заданий и исполнитель внешних программ: изготовление идёт
  заданием, код завершения проверяется всегда.
- → объектное хранилище на SSD: листы размещаются на твердотельном носителе.
  Готовых видеофайлов на сервере нет: подборка собирается на машине
  пользователя (ADR-0009).
- → `boundary-store`: чтобы разрывать строку по границам планов.
- → параметры сериала: размеры листа — настройка, а не константа кода.
