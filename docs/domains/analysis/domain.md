# Домен Analysis — Сцены и планы

## Обзор контекста (Bounded Context)

Находит **структуру** видео: границы сцен и планов с точностью до кадра,
хранит их и отдаёт превью кадров для интерфейса. Не знает, кто в кадре, и не
знает, как зовут персонажа.

## Dependencies | Зависимости

- Catalog — параметры серии.
- Annotation — ручная доводка границ оператором.
- Characters — результаты поиска лиц в кадрах.

## Ubiquitous Language | Единый язык

| Термин | Значение |
|---|---|
| **Сцена** | Непрерывный участок серии с общим местом действия. |
| **План** | Непрерывный участок сцены; вложен в неё целиком. |
| **Граница** | Номер кадра: первый и последний кадр участка. |
| **План целиком внутри сцены** | `first >= scene.first AND last <= scene.last` при равном файле. |
| **Превью кадра** | Уменьшенное изображение 135x75; исходный кадр не хранится. |
| **Значимый кадр** | Кадр внутри сцены, с лицом или на границе плана. |
| **Результат анализа** | Сырые границы, отделены от ручных правок оператора. |
| **Задание** | Единица работы в очереди: `ANALYZE`, `FACES`, `TRAIN`, `HASH`. |
| **Состояние задания** | `WAITING`, `CREATING`, `WORKING`, `DONE`, `ERROR` — ровно пять значений. |
| **Артефакт** | Зарегистрированный результат задания в хранилище: `WRITING`, `READY`, `FAILED`. |
| **Временный ключ** | Ключ, по которому артефакт пишется до переноса на окончательный. |
| **Прогресс задания** | Сколько единиц работы сделано из скольких: счётчик приходит из потока внешней программы, а не из индекса цикла. |
| **Пометка устаревания** | Признак «результат получен при других входах». Ставится, ничего не удаляет; пересчёт запускает оператор. |
| **Серия в коде** | Русский термин «серия» в этом домене — сущность `Episode`, таблица `tbl_episodes`, ссылка `id_episode`; имя в коде и в базе по решению владельца 2026-10-03 (каталог, § «Имена сущностей»). |

## Публичные контракты (API)

Реализованы в `syp-admin-app`; контракт — раздел 5 файла
`specs/001-first-vertical-slice/contracts/admin-api.md`.

| Метод и путь | Что делает |
|---|---|
| `POST /api/series/{episodeId}/analysis` | поставить серию на анализ структуры, ответ `202` |
| `GET /api/series/{episodeId}/structure` | сцены с планами и сведениями об актуальности результата |
| `GET /api/series/{episodeId}/raw-boundaries` | сырой результат автоматики последнего прогона |
| `GET /api/series/{episodeId}/frames` | страница значимых кадров с признаками |
| `GET /api/series/{episodeId}/frames/flags` | признаки кадров диапазона, включая признак ключевого кадра |
| `GET /api/series/{episodeId}/preview-sheets/{index}` | содержимое листа превью |
| `GET /api/series/{episodeId}/preview-url` | адрес листа и область кадрирования кадра на нём |

Списки кадров и лиц пагинируются всегда; по умолчанию 200 строк, потолок
2000. Сырой результат автоматики отдаётся **отдельным** эндпоинтом, а не
внутри структуры: сравнить предложение машины с решением человека можно
только рядом.

## Domain Invariants | Инварианты и правила бизнеса

1. Границы хранятся и отображаются **точно, до номера кадра**.
2. План лежит в сцене целиком; частичное пересечение не допускается.
3. Кадры в исходном разрешении **не хранятся** — только превью и результаты.
4. Сырой результат автоматики не перезаписывается ручными правками.
5. Результат задания помечается устаревшим при смене версии алгоритма или
   параметров обработки.
6. Готовых видеофайлов подборок на сервере нет: домен отдаёт границы и
   превью, а не картинку (ADR-0009).
7. **Долгая работа идёт через очередь заданий** с пятью состояниями:
   наблюдаемое состояние обязательно, кнопка, блокирующая интерфейс на десятки
   секунд, — нарушение (constitution IV).
8. **Код возврата внешней программы проверяется всегда.** Ненулевой код
   переводит задание в `ERROR` с читаемым текстом, а не в `DONE` (FR-004,
   SC-005). В старом проекте не проверял код возврата ни один из двенадцати
   вызовов ffmpeg.
9. **Незавершённый артефакт не считается готовым.** Регистрация `READY`
   выполняется только после переноса временного объекта на окончательный ключ,
   то есть после нулевого кода завершения (FR-091).
10. **Исполнитель заданий есть только у админского бэкенда**; вида задания
    `ASSEMBLE` не существует (FR-085, research.md Т-20).
11. **Прогресс задаётся потоком внешней программы** и монотонен: при
    возврате задания в очередь уже показанное оператору значение не
    уменьшается (FR-003, research.md Т-15).
12. **Прогон неудачи не остаётся в состоянии работы.** Ошибка внешней
    программы переводит и задание, и прогон в состояние ошибки с текстом:
    прогон, оставшийся «в работе» навсегда, выглядел бы как задание, которое
    ещё идёт.
13. **Устаревший результат показывается, а не прячется.** Ответ о структуре
    несёт машинный код `STALE_RESULT` и признак по каждой границе; отказом
    код становится только там, где действие обязано опираться на актуальные
    границы (FR-090).

## Структура компонентов (C4 L3)

| Компонент | Ответственность |
|---|---|
| `scene-detection` | Поиск границ сцен. |
| `shot-detection` | Поиск границ планов внутри сцены. |
| [frame-preview](components/frame-preview.md) | Генерация и выдача превью кадров. |
| [analysis-run](components/analysis-run.md) | Прогон анализа: сырой результат отдельно от ручного, пометка устаревания, прогресс задания. |
| `boundary-store` | Хранение границ с точностью до кадра. |
| [job-queue](components/job-queue.md) | Очередь заданий: пять состояний, наблюдаемый прогресс, проверка результата перед пропуском работы. |
| [artifact-registry](components/artifact-registry.md) | Хранилище и регистрация артефактов: атомарная запись, состояния `WRITING` / `READY` / `FAILED`. |
