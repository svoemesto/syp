# Спецификация компонента: Приём эпизода

Домен: [Catalog](../domain.md). Спецификация: `specs/001-first-vertical-slice/`.

## Ответственность | Responsibility

Компонент превращает путь к файлу в зарегистрированном эпизод с полным набором
измеренных параметров. Он отвечает за три вещи, и все три — про то, чтобы
параметры эпизода соответствовали содержимому файла:

1. **путь лежит внутри корня каталога фильма** — иначе относительный путь к
   файлу, который попадёт в сценарий сборки, был бы выдуманным (FR-089a);
2. **файл доступен** — несуществующий или нечитаемый файл даёт внятный отказ, а
   не «успех с пустым результатом» (FR-092);
3. **параметры сняты с самого файла** — число кадров, частокадровая база,
   разрешение, длительность, кодек, профиль, формат пикселей, параметры звука и
   карта ключевых кадров (FR-002, FR-023).

Оператор эти величины не вводит. Введённые расходились бы с содержимым, и
расхождение обнаружилось бы позже и не там, где его можно было бы исправить.

## Интерфейсы и Контракты | Interfaces and Contracts

- **Регистрация**: фильм, путь к файлу, необязательное название → эпизод с
  определёнными параметрами либо отказ с кодом.
- **Проверка пути**: фильм, путь → настоящий путь к файлу либо отказ. Проверка
  публична отдельно от регистрации, потому что её смысл самостоятелен: ответ на
  «этот файл вообще относится к этому фильму?» не должен стоять целого опроса
  файла.
- **Опрос**: путь к файлу → параметры файла с картой ключевых кадров.

Коды отказов: `SOURCE_UNREADABLE` — файл недоступен или лежит вне корня
фильма; `NOT_FOUND` — фильм не заведён; `CONFLICT` — такой файл уже
зарегистрирован.

## Логика и Алгоритмы | Logic and Algorithms

1. **Порядок проверок неслучаен**: форма пути, принадлежность корню,
   существование файла. Обратный порядок приводит к тому, что эпизод, указанная
   не в том каталоге и несуществующая, сообщает «файла нет» — оператор ищет
   несуществующий файл вместо того, чтобы исправить корень.
2. **Проверка идёт по настоящему пути, а не по написанному.** Символ внутри
   корня может уводить вбок; путь, прошедший проверку на бумаге, оказался бы
   снаружи, а сценарий получил бы «правильный» относительный путь к файлу,
   лежащему совсем в другом месте.
3. **Опрос идёт в три прохода.** Заголовок контейнера и потоков даёт разрешение,
   кодек, профиль, формат пикселей, частокадровую базу и параметры звука.
   Счётчик видеопакетов даёт число кадров: в Matroska поле числа кадров у потока
   не записано. Ключевые кадры читаются в режиме «показывать только ключевые»:
   проход не декодирует изображение.
4. **Время не читается из контейнера.** Объявленная контейнером длительность
   считается по последнему пакету и с величиной, вычисленной по кадрам, не
   совпадает. Хранится длительность кадра, а длительность эпизода вычисляется из
   неё и числа кадров — второго источника правды о времени рядом нет (ADR-0001).
5. **Перевод отметок времени в номера кадров точен.** Вычисление идёт на
   дробных числах без округления на каждом шаге: ошибка в доли кадра на файле в
   5,6 ГБ накапливается до нескольких кадров и разъезжается по всем границам.
6. **Карта ключевых кадров — один бит на кадр.** На эпизоде из 88 643 кадров это
   11 081 байт вместо 88 643 строк, которые запрещены (Р-07, research.md Т-04).
   Длина карты обязана быть ровно `ceil(кадров / 8)` байт, и это закреплено
   ограничением базы: короче — часть кадров молча считается неключевой, длиннее
   — границы фрагментов считаются по не тем кадрам.
7. **Файл не изменяется.** Регистрация только читает; ни один байт архива не
   пишется и не переносится.

## Зависимости | Dependencies

- → [SerialRegistry](serial-registry.md): фильм и его корень каталога.
- → карта ключевых кадров эпизода: источник фактических границ фрагментов
  сценария, дополнительного прохода по видео для сценария не требуется
  (research.md Т-28).
- → параметры эпизода: единственный источник сведений о совместимости при сборке
  (FR-087).
- → `ffprobe`: внешняя программа, путь к ней фиксирован настройкой
  развёртывания (ADR-0010).

  данных.
