# Спецификация компонента: Реестр фильмов

Домен: [Catalog](../domain.md). Спецификация: `specs/001-first-vertical-slice/`.

## Ответственность | Responsibility

Компонент держит то, **что** вообще обрабатывается: фильмы с их корнями
каталогов, эпизода в составе фильмов, справочник мест действия и настройки
анализа и выдачи сценария.

Корень каталога фильма — не украшение, а часть смысла. Сценарий сборки
обращается к файлам по путям относительно этого корня: у пользователя своя
копия дерева под своим корнем, и общий корень — единственное, что переносит
смысл пути с машины администратора на машину пользователя (FR-089a).

## Интерфейсы и Контракты | Interfaces and Contracts

- **Список фильмов**: → фильмы с числом эпизодов каждого.
- **Создание фильма**: название, корень каталога → фильм с настройками по
  умолчанию.
- **Чтение фильма**: идентификатор → фильм, его эпизодов и настройки.
- **Удаление фильма**: идентификатор → удаление вместе с производными данными.
  Файлы архива не трогаются: они принадлежат не системе.
- **Справочник мест действия**: фильм → список мест; добавление и удаление.
  Название уникально в пределах фильма.
- **Настройки**: фильм → значения порогов; изменение значения → настройки
  после изменения и список действительно изменившихся ключей.

## Логика и Алгоритмы | Logic and Algorithms

1. **Корень проверяется дважды.** В коде — чтобы оператор получил внятный
   текст, и ограничениями базы — чтобы мимо кода тоже было нельзя. Корень
   обязан быть абсолютным путём без завершающего слэша: один и тот же каталог,
   записанный двумя способами, дал бы два фильма.
2. **Один эпизод принадлежит ровно одному фильму.** Это внешний ключ, а не
   соглашение.
3. **Каскад задан в базе, а не в коде.** Удаление фильма уносит эпизоды, сцены,
   планы, лица, персоны, версии моделей, фильтры, сценарии сборки, справочник
   сумм и настройки. Операция необратима и подтверждается оператором.
4. **Место действия назначается только из справочника и только вручную.**
   Автоматического определения нет (FR-052). Удаление локации обнуляет ссылку
   у сцен, а не подменяет её другой локацией: молчаливая подмена изменила бы
   размеченные данные без правки оператора (constitution IV.4).
5. **Настройки живут в базе, а не в коде.** Новый фильм получает одиннадцать
   значений по умолчанию от триггера. Пороги подбираются замером, и смена
   порога после замера не должна требовать правки кода и пересборки (ADR-0003).
6. **Неизвестный ключ настройки отвергается.** Настройка вне перечисления не
   попала бы ни в один расчёт, и её смена молча ничего не меняла бы — худший
   вид поломки. Значение проверяется по смыслу, а не только по типу: порог вне
   интервала или неубывающие пороги размера плана сделали бы последующий
   анализ бессмысленным.
7. **Значения по умолчанию в коде отсутствуют.** Отсутствующая настройка
   объявляется дефектом данных, а не заменяется значением из источника:
   подстановка означала бы вторую правду, которая разъехалась бы с базой при
   первом же изменении.
8. **Запись идёт по различию значений.** Строка переписывается, только если её
   значения действительно изменились. Дата обновления в хеш не входит: это не
   свойство настройки, а следствие записи.

## Зависимости | Dependencies

- → [SeriesImport](series-import.md): эпизода заводятся через приём, а не в
  обход него.
- → карта ключевых кадров эпизода: эпизод хранит её вместе с параметрами файла.
- → настройки фильма: пороги и параметры кластеризации входят в хеш параметров
  задания; смена настройки переводит полученные с прежними параметрами
  результаты в состояние устаревших (FR-090) — это делает слой анализа, который
  знает, каким набором параметров результат получен.
- → ключевые кадры: по ним округляются фактические границы фрагментов
  (research.md Т-28).
