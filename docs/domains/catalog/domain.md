# Домен Catalog — Сериалы и серии

## Обзор контекста (Bounded Context)

Отвечает за то, **что** вообще обрабатывается: произведения (сериалы) и их
составные видеофайлы (серии). Хранит параметры файла и путь к источнику.
Не знает о сценах, лицах и подборках.

## Dependencies | Зависимости

- Внешний источник: архив видео `/disks/HDD_16Tb_Clouds/GOT` — **только
  чтение**, система ничего в нём не изменяет.
- Домен Analysis читает параметры серии отсюда.

## Ubiquitous Language | Единый язык

| Термин | Значение |
|---|---|
| **Сериал** | Произведение, с которым работают: название, список серий, справочник локаций. |
| **Серия** | Один видеофайл сериала — файл с серией сезона. |
| **Параметры серии** | Число кадров, частокадровая база (`time_base`), разрешение, длительность, кодек. |
| **Номер кадра** | Единственный источник правды для границ; время производно от него. |
| **Источник** | Путь к исходному видеофайлу; файл только читается. |
| **Корень каталога сериала** | Каталог сериала на машине администратора. От него отсчитываются относительные пути в сценарии сборки. |
| **Длительность кадра** | Время одного кадра в секундах. Хранится у серии вместо частоты кадров: время границы вычисляется от номера кадра. |
| **Карта ключевых кадров** | Бит на кадр у серии: бит 1 — кадр ключевой. Источник фактических границ фрагментов сценария. |
| **Настройка** | Порог или параметр сериала, который меняется замером, а не правкой кода. |

### Имена сущностей | Entity names

Русские термины «сериал» и «серия» описывают, **что** это; имена в коде и
в базе — по решению владельца 2026-10-03. Таблицам всех сущностей проекта
принадлежит префикс `tbl_` и форма во множественном числе (соглашение —
`specs/001-first-vertical-slice/data-model.md` § 1.8, миграция
`16_tbl_prefix_rename.sql`).

| Термин | Класс | Таблица | Столбец-ссылка |
|---|---|---|---|
| Сериал | `Movie` | `tbl_movies` | `id_movie` |
| Серия | `Episode` | `tbl_episodes` | `id_episode` |

Пути доступа `/api/serials` и `/api/series` в карту переименования не входят
и остались прежними; имена в ответах — новые: `movieId`, `episodeId`.

## Публичные контракты (API)

Реализованы в `syp-admin-app`; контракт — раздел 3 файла
`specs/001-first-vertical-slice/contracts/admin-api.md`.

| Метод и путь | Что делает |
|---|---|
| `GET /api/serials` | список сериалов с числом серий |
| `POST /api/serials` | создать сериал: название и корень каталога |
| `GET /api/serials/{movieId}` | сериал, его серии и настройки |
| `DELETE /api/serials/{movieId}` | удалить сериал вместе с производными данными |
| `GET /api/serials/{movieId}/series` | список серий |
| `POST /api/serials/{movieId}/series` | зарегистрировать серию по пути к файлу |
| `GET /api/series/{episodeId}` | параметры серии и состояние готовности |
| `DELETE /api/series/{episodeId}` | снять серию с учёта; файл не трогается |
| `GET /api/serials/{movieId}/settings` | пороги, параметры кластеризации, версия формата сценария, число аудиодорожек |
| `PUT /api/serials/{movieId}/settings` | изменить пороги и параметры |

Справочник мест действия (`GET` и `POST /api/serials/{movieId}/locations`)
наполняется в фазе плана 7.

Отказы несут общие коды и русский текст. Код `SOURCE_UNREADABLE` означает и
«файла нет», и «путь вне корня сериала»: для файла серии это одно и то же
состояние, а различие остаётся в тексте отказа.

## Domain Invariants | Инварианты и правила бизнеса

1. Номер кадра — единственный источник правды для границ; время пересчитывается
   от `time_base` конкретной серии.
2. Исходные видеофайлы **никогда не изменяются**.
3. Одна серия принадлежит ровно одному сериалу.
4. Серии одного сериала могут отличаться параметрами видео — совместимость
   проверяется перед выдачей сценария, а не предполагается.
5. Путь каждой серии лежит **внутри** корня сериала: иначе относительный путь
   в сценарии был бы выдуманным (FR-089a). Проверка идёт по настоящему пути:
   символ внутри корня может уводить вбок.
6. Корень каталога сериала — абсолютный путь без завершающего слэша: один и тот
   же каталог, записанный двумя способами, дал бы два сериала.
7. Длина карты ключевых кадров обязана быть ровно `ceil(кадров / 8)` байт.
8. Пороги и параметры анализа хранятся в базе; настройка, которую никто не
   читает, отвергается, а не сохраняется молча.
9. Место действия назначается сцене только вручную и только из справочника
   сериала.
10. Действительно изменившаяся настройка **помечает результаты анализа
    устаревшими, но не удаляет их** и не запускает пересчёт: пересчёт
    уничтожил бы ручные правки оператора, а решение принимает человек
    (FR-090). Пометку делает слой [Analysis](../analysis/domain.md): хранилище
    настроек отдаёт список изменившихся ключей и о входах результата не знает.
