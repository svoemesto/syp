# Домен Catalog — Фильмы и эпизода

## Обзор контекста (Bounded Context)

Отвечает за то, **что** вообще обрабатывается: произведения (фильмы) и их
составные видеофайлы (эпизода). Хранит параметры файла и путь к источнику.
Не знает о сценах, лицах и подборках.

## Dependencies | Зависимости

- Внешний источник: архив видео `/disks/HDD_16Tb_Clouds/GOT` — **только
  чтение**, система ничего в нём не изменяет.
- Домен Analysis читает параметры эпизода отсюда.

## Ubiquitous Language | Единый язык

| Термин | Значение |
|---|---|
| **Фильм** | Произведение, с которым работают: название, список эпизодов, справочник локаций. |
| **Эпизод** | Один видеофайл фильма — файл с эпизодом сезона. |
| **Параметры эпизода** | Число кадров, частокадровая база (`time_base`), разрешение, длительность, кодек. |
| **Номер кадра** | Единственный источник правды для границ; время производно от него. |
| **Источник** | Путь к исходному видеофайлу; файл только читается. |
| **Корень каталога фильма** | Каталог фильма на машине администратора. От него отсчитываются относительные пути в сценарии сборки. |
| **Длительность кадра** | Время одного кадра в секундах. Хранится у эпизода вместо частоты кадров: время границы вычисляется от номера кадра. |
| **Карта ключевых кадров** | Бит на кадр у эпизода: бит 1 — кадр ключевой. Источник фактических границ фрагментов сценария. |
| **Настройка** | Порог или параметр фильма, который меняется замером, а не правкой кода. |

### Имена сущностей | Entity names

**Этот раздел — источник правды по именам сущностей.** Решение владельца
2026-10-03. Остальные документы обязаны соответствовать таблице ниже; если
расхождение есть, правьте документ, а не эту таблицу.

| Термин | Класс | Таблица | Столбец-ссылка | Путь доступа |
|---|---|---|---|---|
| Фильм | `Movie` | `tbl_movies` | `id_movie` | `/api/movies` |
| Эпизод | `Episode` | `tbl_episodes` | `id_episode` | `/api/episodes` |

Правила, которые из этой таблицы следуют и которые действуют во всём
проекте:

1. **Таблицы** всех сущностей имеют префикс `tbl_` и имя во множественном
   числе (соглашение — `specs/001-first-vertical-slice/data-model.md` § 1.8,
   переименование выполнено миграцией `16_tbl_prefix_rename.sql`).
2. **Столбец-ссылка** на сущность называется по её собственному имени с
   префиксом `id_`.
3. **Русский термин** в текстах — «фильм» и «эпизод». Прилагательные
   согласуются с ними по мужскому роду: «каждого эпизода», «один фильм»,
   «на том эпизоде».
4. **Пути доступа** начинаются с `/api/movies` и `/api/episodes`. Переименованы
   и сегмент коллекции, и имена переменных пути: `{movieId}`, `{episodeId}`.
5. **Имена в JSON** — `movieId`, `movieName`, `episodeId`, `episodeName`,
   `episodeCount`.
6. **Названия ограничений и индексов** в базе остались прежними: решение
   владельца их не охватывало (ADR-0015).

Что переименование **не** охватывает: названия файлов и каталогов
(`docs/serial/`, `components/series-import.md`) и слова, где «сериал» — часть
другого слова («сериализованные»). Имена файлов — идентификаторы
документации, а не язык описания.

## Публичные контракты (API)

Реализованы в `syp-admin-app`; контракт — раздел 3 файла
`specs/001-first-vertical-slice/contracts/admin-api.md`.

| Метод и путь | Что делает |
|---|---|
| `GET /api/movies` | список фильмов с числом эпизодов |
| `POST /api/movies` | создать фильм: название и корень каталога |
| `GET /api/movies/{movieId}` | фильм, его эпизодов и настройки |
| `DELETE /api/movies/{movieId}` | удалить фильм вместе с производными данными |
| `GET /api/movies/{movieId}/episodes` | список эпизодов |
| `POST /api/movies/{movieId}/episodes` | зарегистрировать эпизод по пути к файлу |
| `GET /api/episodes/{episodeId}` | параметры эпизода и состояние готовности |
| `DELETE /api/episodes/{episodeId}` | снять эпизод с учёта; файл не трогается |
| `GET /api/movies/{movieId}/settings` | пороги, параметры кластеризации, версия формата сценария, число аудиодорожек |
| `PUT /api/movies/{movieId}/settings` | изменить пороги и параметры |

Справочник мест действия (`GET` и `POST /api/movies/{movieId}/locations`)
наполняется в фазе плана 7.

Отказы несут общие коды и русский текст. Код `SOURCE_UNREADABLE` означает и
«файла нет», и «путь вне корня фильма»: для файла эпизода это одно и то же
состояние, а различие остаётся в тексте отказа.

## Domain Invariants | Инварианты и правила бизнеса

1. Номер кадра — единственный источник правды для границ; время пересчитывается
   от `time_base` конкретного эпизода.
2. Исходные видеофайлы **никогда не изменяются**.
3. Один эпизод принадлежит ровно одному фильму.
4. Эпизода одного фильма могут отличаться параметрами видео — совместимость
   проверяется перед выдачей сценария, а не предполагается.
5. Путь каждого эпизода лежит **внутри** корня фильма: иначе относительный путь
   в сценарии был бы выдуманным (FR-089a). Проверка идёт по настоящему пути:
   символ внутри корня может уводить вбок.
6. Корень каталога фильма — абсолютный путь без завершающего слэша: один и тот
   же каталог, записанный двумя способами, дал бы два фильма.
7. Длина карты ключевых кадров обязана быть ровно `ceil(кадров / 8)` байт.
8. Пороги и параметры анализа хранятся в базе; настройка, которую никто не
   читает, отвергается, а не сохраняется молча.
9. Место действия назначается сцене только вручную и только из справочника
   фильма.
10. Действительно изменившаяся настройка **помечает результаты анализа
    устаревшими, но не удаляет их** и не запускает пересчёт: пересчёт
    уничтожил бы ручные правки оператора, а решение принимает человек
    (FR-090). Пометку делает слой [Analysis](../analysis/domain.md): хранилище
    настроек отдаёт список изменившихся ключей и о входах результата не знает.
