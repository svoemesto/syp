# Спецификация компонента: Справочник сумм исходников

Домен: [Selection](../domain.md). Спецификация: `specs/001-first-vertical-slice/`.

## Эндпоинты | Endpoints

| Метод и путь | Что делает |
|---|---|
| `GET /api/episodes/{episodeId}/checksum` | состояние подсчёта, алгоритм, значение, дата, признак устаревания |
| `POST /api/episodes/{episodeId}/checksum` | поставить пересчёт суммы |

## Ответственность | Responsibility

Компонент держит эталонные суммы `sha256` исходных файлов эпизодов — то, с чем
машина пользователя сверяет файл **до** нарезки.

Смысл компонента — в порядке проверки. Подмена файла, обнаруженная через час
работы, недопустима; сумма, посчитанная заранее и записанная в сценарий,
превращает час работы в минуту ожидания отказа (ADR-0009, последствие 4).

## Интерфейсы и Контракты | Interfaces and Contracts

- **Постановка пересчёта**: эпизод → задание с наблюдаемым состоянием и
  прогрессом по прочитанным байтам.
- **Текущий сумма**: эпизод → запись справочника либо указание, что её нет.
- **Пригодность эпизода к выдаче**: эпизод → признак «можно выдавать сценарий».
- **Снимок для сценария**: эпизод → значение суммы, которое попадёт во фрагменты
  сценария.

## Логика и Алгоритмы | Logic and Algorithms

1. **Считается один раз, заданием.** Чтение файла 5,6 ГБ — это работа, а не
   запрос; она идёт через очередь, а прогресс идёт по прочитанным байтам.
   Считает сам процесс задания, а не внешняя программа: программа отдала бы
   результат одной строкой в конце, и интерфейс не видел бы движения.
   Правило о проверке кода возврата касается внешних программ, которых у
   подсчёта нет; отказом служит ошибка чтения с текстом на русском.
2. **История сохраняется.** Пересчёт создаёт новую запись, а не заменяет
   прежнюю. Актуальная сумма ровно один на эпизод; при изменении файла прежняя
   помечается устаревшей. Стирать прежнюю нельзя: по ней видно, что файл
   менялся.
3. **Без актуальной суммы сценарий не выдаётся.** Сценарий, ссылающийся на
   устаревшую или отсутствующую сумму, у пользователя упадёт на сверке. Отказ
   должен прийти на машине администратора, а не на машине пользователя.
4. **Снимок, а не ссылка.** В сценарий попадает значение на момент выдачи.
   Иначе сценарий, скачанный вчера, сегодня соответствовал бы другой сумме, и
   подпись над ним перестала бы что-либо значить.
5. **Формат значения фиксирован.** 64 шестнадцатеричных символа в нижнем
   регистре, алгоритм ровно `SHA-256`. Именно такой вывод даёт `sha256sum` на
   машине пользователя, поэтому сверка идёт без преобразований.
6. **Ошибка счёта — ошибка задания, а не пустой результат.** Обрыв чтения,
   отсутствие файла, ошибка ввода-вывода: состояние `ERROR` с текстом.
7. **У незавершённого подсчёта суммы нет.** Запись справочника появляется при
   постановке задания — иначе прерванный подсчёт оставил бы после себя
   пустоту, и по записям нельзя было бы отличить «считается» от «никогда не
   считалось». Частично посчитанная сумма суммой не является: она появляется
   только после полного чтения файла.
8. **Второй подсчёт того же эпизода отклоняется, пока идёт первый.** Два
   одновременных чтения одного файла делили бы его между собой, а оператор
   видел бы два задания, каждое из которых утверждает, что считает.

## Зависимости | Dependencies

- → очередь заданий: пересчёт — задание вида `HASH` с прогрессом.
- → параметры эпизода: размер файла и время изменения, при которых считали.
- → `recipe-builder`: снимок суммы попадает во фрагменты сценария.
