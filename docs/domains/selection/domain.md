# Домен Selection — Фильтры и сборка

## Обзор контекста (Bounded Context)

Отвечает на вопрос «покажи мне сцены с таким персонажем в таком месте» и
**формирует рецепт** сборки для машины пользователя. Фильтры сохраняются и
переиспользуются. Сам файл собирается у пользователя, не перекодируя исходник
(ADR-0009).

## Dependencies | Зависимости

- Characters — персоны для условий фильтра.
- Annotation — локации и размеры плана.
- Analysis — сцены и планы для сборки.

## Ubiquitous Language | Единый язык

| Термин | Значение |
|---|---|
| **Условие** | Один предикат: персонаж, локация, тип плана, размер, границы, наличие лица. |
| **Фильтр** | Именованное дерево условий, до трёх уровней, на каждом свой И/ИЛИ. |
| **Подборка** | Набор сцен, выбранный фильтром. |
| **Сценарий сборки** | Рецепт: фрагменты с относительными путями и границами по кадрам, с подписью. |
| **Сборка** | Получение видеофайля на машине пользователя по сценарию, без перекодирования. |
| **Округление на стыке** | Захват лишнего кадра при склейке без перекодирования. |

## Публичные контракты (API)

Определяются в `speckit-plan`: построение фильтра, сохранение и повторное
применение, выбор сцен, запуск сборки, получение результата.

## Domain Invariants | Инварианты и правила бизнеса

1. Фильтр выполняется **одним универсальным механизмом**, а не отдельной
   логикой под каждое сочетание условий.
2. Сборка не перекодирует видео: качество исходника сохраняется.
3. Пути в сценарии **относительные** — структура каталогов повторяет машину
   администратора.
4. Несовместимые по параметрам серии отклоняются **до** выдачи сценария, а не
   после получаса работы у пользователя.
5. Сценарий сопровождается подписью: воркер проверяет её до выполнения.
6. Сценарий несёт `sha256` исходников: воркер сверяет их **до** нарезки.
7. Без актуальной суммы исходника сценарий **не выдаётся**: пользователь
   получил бы рецепт, который у него упадёт через час работы.
8. Сумма, попавшая в сценарий, — **снимок на момент выдачи**, а не ссылка на
   текущее значение справочника.

## Структура компонентов (C4 L3)

| Компонент | Ответственность |
|---|---|
| `filter-builder` | Построение дерева условий. |
| `filter-store` | Сохранение, повторное применение, правка, удаление. |
| [condition-registry](components/condition-registry.md) | Единый исполнитель фильтра: реестр обработчиков условий. |
| [recipe-builder](components/recipe-builder.md) | Генератор сценария: фрагменты, обе пары границ, относительные пути, снимки данных сцен. |
| [recipe-compatibility](components/recipe-compatibility.md) | Проверка совместимости серий **до** выдачи сценария. |
| [recipe-signer](components/recipe-signer.md) | Подпись сценария и отзыв открытого ключа проверки. |
| [checksum-registry](components/checksum-registry.md) | Справочник `sha256` исходников: эталон проверки на машине пользователя. |

Сборка и нарезка в этом домене **не выполняются**: домен формирует рецепт,
выполняет его воркер на машине пользователя — домен
[Showcase](../showcase/domain.md), компонент `local-worker`.
