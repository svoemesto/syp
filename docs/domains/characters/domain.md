# Домен Characters — Лица и персонажи

## Обзор контекста (Bounded Context)

Находит **лица в каждом кадре**, группирует похожие в кластеры и учит
распознаванию на эталонах. Даёт ответ на вопрос «кто в кадре и где он».

## Dependencies | Зависимости

- Analysis — кадры и принадлежность кадра плану.
- Annotation — имена и метки «эталон» от оператора.

## Ubiquitous Language | Единый язык

| Термин | Значение |
|---|---|
| **Лицо** | Прямоугольник в кадре с привязкой к плану. |
| **Персона** | Именованная личность; идентичность не зависит от отображаемого имени. |
| **Кластер** | Группа похожих лиц без имени; оператор даёт имя. |
| **Эталон** | Лицо, помеченное для обучения. |
| **Версия модели** | Результат одного обучения: дата, число эталонов, состав классов. |
| **Неопознанное лицо** | Лицо без подтверждённой персоны; не теряется при операциях. |
| **Положение в кадре** | Рамка лица и принадлежность плану. Ракурс в первый срез не входит. |
| **Эпизод в коде** | Русский термин «эпизод» в этом домене — сущность `Episode`, таблица `tbl_episodes`, ссылка `id_episode`; имя в коде и в базе по решению владельца 2026-10-03 (каталог, § «Имена сущностей»). |

## Публичные контракты (API)

Контракт — `specs/001-first-vertical-slice/contracts/admin-api.md`. Пути
экрана админки (решение владельца 2026-10-03: эпизод стала эпизодом):

| Метод и путь | Что делает |
|---|---|
| `GET /api/episodes/{episodeId}/faces` | лица эпизода с кластерами и именами |
| `GET /api/episodes/{episodeId}/faces/clusters` | кластеры безымянных лиц |
| `POST /api/clusters/{clusterId}/person` | дать кластеру имя персоны |
| `GET /api/movies/{movieId}/persons` | справочник персон фильма |
| `PATCH /api/persons/{personId}` | переименовать персону |
| `DELETE /api/persons/{personId}` | удалить персону; лица становятся неопознанными |
| `POST /api/movies/{movieId}/training` | поставить обучение: порог и состав эталонов |
| `GET /api/movies/{movieId}/model-versions` | версии: дата, число эталонов, состав классов, активность |
| `POST /api/model-versions/{id}/activate` | сделать версию активной |
| `POST /api/model-versions/{id}/rollback` | откат: новая версия на прежнем составе эталонов |
| `GET /api/model-versions/{id}` | состав версии |

## Domain Invariants | Инварианты и правила бизнеса

1. Лица ищутся в **каждом** кадре эпизода.
2. У каждого распознанного лица хранится версия модели, которой оно опознано.
3. Предыдущие версии модели сохраняются; откат возможен.
4. Неопознанные лица не исчезают при переобучении и удалении персон.
5. Переименование персоны не ломает модель.
6. В сценарий сборки попадает **снимок** имён персонажей на момент выдачи:
   локальный показ работает без сервера (FR-089d), и правка справочника после
   выдачи не должна «слепить» уже скачанный сценарий.
7. «Нет персоны» выражается **служебной персоной-заглушкой**, а не пустой
   ссылкой; у каждого фильма заглушки заведены базой, удалению не
   подлежат, а удаление именованной персоны переводит её лица в неопознанных,
   а не стирает (Р-12, FR-036).
8. Детектор, который ничего не ищет, **объявляет себя заглушкой**: пустой
   результат заглушки не должен читаться как вывод детектора.
9. Детектор работает **внутри контейнера админки**, на видеокарте, отдельного
   контейнера детекции нет (constitution V, research.md Т-01, Т-20); путь к
   программе, путь к модели, **вид модели**, размер входа и пороги приходят из
   конфигурации развёртывания, а ключ детектора описывает конфигурацию,
   которая **на самом деле поднялась** (FR-090, Р-10, ADR-0010). Модель
   выбирается настройкой: пересборка образа под другую модель не требуется.
11. Модель детектора выбирается замером, а не примером из репозитория модели;
   выбор зафиксирован в `specs/001-first-vertical-slice/measurements/m-02-models.md`,
   порог уверенности подобран на размеченной выборке и является настройкой
   развёртывания.
10. Молчаливый уход вычислений на CPU — **отказ**, а не предупреждение: список
    доступных провайдеров onnxruntime отвечает на вопрос «что скомпилировано»,
    а не «что работает», и по итоговому времени ухода разницы не видно.
12. Определение ракурса лица (анфас, профиль, три четверти) **в домен не
    входит**: рамка и размер плана его заменяют (FR-035). Признак ракурса,
    появившийся в ответе или в таблице, — дефект, и его ловит тест.
13. Принадлежность лица плану всегда соответствует правилу диапазонов кадров;
    столбец хранит **копию вычисленного значения**, и пересчёт выполняется в
    той же транзакции, что и операция с границами плана (FR-034). Доводка
    границы **сцены** пересчёта не вызывает: диапазоны планов при ней не
    меняются, а копия `shot_id` перестаёт соответствовать вычисленному
    значению только при смене границ плана.
14. Кластеры лиц **вычисляются**, а не хранятся: они производны от
    эмбеддингов, и второе место истины о похожестве лиц разошлось бы с
    векторами при первом же изменении (FR-031, Р-09).

## Структура компонентов (C4 L3)

| Компонент | Ответственность |
|---|---|
| `face-detection` | Поиск лиц в каждом кадре. |
| `face-storage` | Хранение рамок, принадлежность планам, отбрасывание нелицевых рамок. |
| `persons` | Персоны фильма и служебные заглушки «распознано, но имя не подтверждено» и «не лицо». |
| `face-embedding` | Векторные представления лиц. |
| `face-clustering` | Группировка похожих лиц в кластеры. |
| `model-training` | Обучение на эталонах, версии, откат. |

Спецификации компонентов: [поиск лиц](components/face-detection.md),
