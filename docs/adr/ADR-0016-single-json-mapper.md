# ADR-0016: один разборщик JSON на проект

**Статус**: принято
**Дата**: 2026-10-03

## Decision | Решение

Разбор и запись JSON выполняет один объект `syp-core/core/json/Json.mapper()`.
Приложение и тесты пользуются им оба.

## Context & Problem | Контекст и проблема

Ответ с датой отдавал 500: `java.time.Instant not supported by default`.
Модуль времени был в classpath, но не был зарегистрирован — в проекте объявлен
собственный бин `ObjectMapper`, а увидев его, Spring Boot перестаёт
конфигурировать свой, и модуль времени не подхватывался.

Чинить это оказалось мало. Пока разборщик создавался в каждом месте отдельно,
тесты пользовались тем же, что и приложение, но **без** модуля времени: ни один
тест не сериализовал ответ с датой, поэтому все проходили, а живой стенд
отдавал 500. Тест, проверяющий домен, проходит — и не замечает, что
упавший слой сериализации о нём не знает.

Пока разборщик может быть собран по-разному, класс дефектов «проверка проходит,
ничего не проверяя» остаётся открытым: достаточно одного места, где модуль
забыли.

## Rationale | Обоснование

### Почему один разборщик, а не регистрация в каждом месте

Пока разборщик создаётся в каждом месте отдельно, класс дефектов «проверка
проходит, ничего не проверяя» остаётся открытым: достаточно одного места, где
модуль забыли. Именно так и вышло — два разборщика, один без модуля времени.

## Consequences | Последствия

- `syp-core` объявляет зависимости Jackson как `api` — разборщик используется
  всеми модулями.
- Даты пишутся в читаемом виде, а не числом: `WRITE_DATES_AS_TIMESTAMPS`
  выключен, иначе в ответе вместо даты оказывается `1790961574.414950000`,
  что читается только догадкой.
- Неизвестные поля при чтении не роняют разбор: клиент может получить ответ с
  полем, которого ещё не знает.
- `JsonContractTest` фиксирует оба свойства. Тест написан по истории: он
  повторит ту же ошибку, если модуль времени снова не зарегистрируют.

## Отвергнуто

- **Регистрация модуля в каждом месте отдельно** — работает, пока не появится
  новое место. Именно так и вышло: два разборщика, один из них без модуля.
- **Тест только на ответ контроллера через MockMvc** — не ловит случай с
  собственным бин��м, потому что MockMvc собирает свой разборщик.
