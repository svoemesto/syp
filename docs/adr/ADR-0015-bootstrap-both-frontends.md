# ADR-0015: Обе части SYP оформлены Bootstrap с общей темой проекта

## Context & Problem | Контекст и проблема

Решение владельца 2026-10-03: «про внешний вид веба — надо чтобы сразу было
красиво, используй тот же подход, что в Караоке».

Проверено, что в Караоке действительно две части, и оформлены они по-разному:

| Часть Karaoke | Стек оформления |
|---|---|
| админка `karaoke-webvue3` | Vue 3, `bootstrap-vue-next`, своя `src/style.css` |
| публичная `karaoke-web` | Bootstrap 4.6 с CDN, jQuery, Roboto, серверные страницы |

Общее у них одно: **основа — Bootstrap, своя вёрстка поверх**. Различаются они
способом доставки, потому что это разные приложения: у Karaoke публичная часть
серверная, а в SYP обе части — Vue 3 и Vite.

Проблема на стороне SYP была не в выборе, а в отсутствии выбора. UI-библиотеки
не было ни в одном фронтенде, при том что в `syp-admin-web` уже было около
890 строк кода: `api/`, `App.vue`, `components/`, `stores/`, `router.ts`,
`views/`, включая `StructureView.vue` на 286 строк. Написано было — оформлено
не было. Публичная часть к этому моменту содержала заголовок и одну строку
пояснения.

## Decision | Решение

**Основа оформления обоих фронтендов — Bootstrap 5.3.8. Поверх него — тема
проекта, одна на обе части.**

1. **Bootstrap 5.3.8** подключается в оба фронтенда. Версия совпадает с
   админкой Karaoke (`bootstrap@^5.3.8`) — переносится проверенное, а не
   последнее доступное.
2. **`bootstrap-vue-next` 0.40.5 подключается только в админке** — ради
   `BApp` и тостов, которыми она уже пользуется в Karaoke. В публичной части
   интерактивных компонентов нет, и зависимость была бы ballast'ом.
3. **Тема — один файл `src/theme/theme.css`, одинаковый в обоих
   фронтендах.** Общего пакета у них нет намеренно: в корне репозитория файла
   `package.json` нет (R-375). Файл копируется в обе части тем же коммитом, и
   расхождение видно сразу — оба проверяются `npm run format:check`.
4. **Тема переопределяет переменные Bootstrap, а не подменяет библиотеку.**
   Новый цвет добавляется токеном в теме; своих цветов «поверх» не появляется.
5. **Схема одна и светлая.** Обоснование — в разделе Rationale.
6. **Обращения к полям ответа вынесены в `api/view-model.ts` обеих частей.**
   Экраны не читают поля ответа напрямую. Переименование `Serial` → `Movie` и
   `Series` → `Episode` идёт параллельно в ветке `037-rename`; после него правка
   затронет `api/` и ничего кроме.
7. **Состояния загрузки, пустоты и отказа — один компонент на экран**, а не
   три разные разметки: это одно решение, и одинаковое место на экране должно
   означать одно и то же.
8. **Раздел без экрана показывается как «в работе», а не как ошибка.**
   Навигация админки перечисляет все разделы, включая те, чей экран ещё не
   сделан.

## Rationale | Обоснование

**Почему светлая схема.**

- Админкой оператор работает часами над плотными таблицами и листами превью.
  Лист превью — это кадры видео: на тёмном фоне они выглядят вырезанными из
  другого изображения, а мелкий текст таблиц теряет контраст.
- Публичную часть открывает обычный пользователь. Принудительная тёмная схема
  означала бы светлый текст на светлом окне у того, у кого в браузере включена
  тёмная тема.
- Тёмная схема в админке Karaoke — не решение, а остаток шаблона Vite: в
  `webvue3/src/style.css` стоят цвета стартовой заготовки `#242424` и
  `#646cff`. Переносить заготовку как «подход» незачем.

**Палитра.** Смысловые цвета взяты из кода, который до этого решения уже
работал: отказ `#b3261e`, происхождение границы — алгоритм `#b02020`, оператор
`#1f7a35`, отмена `#d06000` (FR-015, FR-016). Основной цвет `#2f5aa8` даёт
контраст 6,67:1 к белому.

Контрасты пересчитаны по формуле WCAG и один цвет изменён: отмена границы
затемнена с `#d06000` до `#a84800`, потому что на своей подложке прежний оттенок
давал 3,38:1 — ниже порога AA для обычного текста. Итоговые значения на своих
подложках: алгоритм 5,79:1, оператор 4,72:1, отмена 4,90:1; основной цвет на
белом 6,67:1, приглушённый текст на фоне 5,39:1. Палитра вынесена в токены
`--syp-*`, чтобы «цвет происхождения один раз в CSS» (FR-015) держалось и
дальше.

**Альтернативы.**

- **Отдельные темы для админки и публичной части.** Отвергнуто: части
  принадлежат одной системе, и оператор, переходя из одной в другую, попал бы
  в другой интерфейс.
- **Bootstrap 5.3 с тёмной схемой.** Отвергнуто по двум пунктам выше.
- **UI-кит целиком (PrimeVue, Vuetify, Element Plus).** Отвергнуто: в проекте
  уже выбран стек (Vue 3 + Vite), а кит приносит с собой собственные цвета,
  шрифты и правила — то есть ровно ту несовместимость, ради устранения которой
  решение принято.
- **Оформить админку `bootstrap-vue-next`, публичную часть — сырым
  Bootstrap.** Это текущее состояние. Оно допустимо, но оставляет две
  независимые темы и две расходящиеся подписи; общая тема дешевле.

## Consequences | Последствия

1. **Запрет**: добавлять цвет, отступ или шрифт в компонент мимо темы.
   Расхождение между частями — прямое следствие.
2. **Запрет**: править файл темы в одной части, не правя в другой. Файлы
   должны быть побайтово одинаковыми.
3. **Инвариант**: экран читает поля ответа только через `api/view-model.ts`.
   Проверяется поиском обращений к полям вне `api/`, а не договорённостью.
4. **Инвариант**: каждая часть собирается из своего каталога командой
   `cd <каталог> && npm run` (R-375).
5. **Требуется**: при смене версии Bootstrap проверять сборку обеих частей
   вместе — тема опирается на переменные `--bs-*`, и их состав меняется от
   версии к версии.
6. **Required Update**: `docs/features/first-vertical-slice.md`,
   `docs/domains/showcase/domain.md`, `docs/domains/analysis/domain.md`.
