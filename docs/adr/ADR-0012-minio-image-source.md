# ADR-0012: Источник образа MinIO — elestio в Docker Hub

**Статус**: принято
**Дата**: 2026-10-03
**Заменит**: образ `minio/minio` из Docker Hub (недоступен)

## Context & Problem | Контекст и проблема

`minio/minio` убрана из Docker Hub: публичный API отвечает «object not found»
на репозиторий, а `docker pull` — «pull access denied … may require
'docker login'». Сообщение выглядит как проблема авторизации, но ей не является:
учётные данные валидны, `hello-world` тянется свободно. Образ отсутствует в
реестре.

Официальный образ MinIO раздаётся через `quay.io`. На новом проде в Караоке
стоит `quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z` (см.
`Karaoke/deploy/prod-single-host/README.md`). С этой машины `quay.io` отвечает
401 и без логинов, а образов из quay в локальном кэше нет — воспроизвести
такой путь здесь нельзя.

## Decision | Решение

Объектное хранилище — `elestio/minio:latest` из Docker Hub, единственная
доступная в реестре сборка MinIO. Проверено фактами: внутри
`minio version RELEASE.2025-09-07T16-13-09Z`, то есть тот же официальный релиз,
что на проде в Караоке, вплоть до имени тега.

Так как единственный тег — `latest`, версия фиксируется digest:
`sha256:25348a257f1ece1b192f25f6cd9854618fa86422ac87b494b5d4e629c556d4bd`.
Digest записан в compose полем `x-image-digest` и в этом ADR.

Отказ от MinIO в пользу S3-совместимого аналога рассматривался и отклонён
владельцем: нужна именно MinIO. Из аналогов в Docker Hub доступен только
`rustfs/rustfs`, и он в статусе preview.

## Rationale | Обоснование

Воспроизводимость развёртывания важнее формальной «официальности» сборки:
образ в реестре нужен на каждой новой машине, а происхождение сборки проверяется
по версии внутри. Elestio выбрана потому, что содержимое — официальный релиз
MinIO, а не форк с неясной историей, и альтернатив в Docker Hub нет: из
проверенных кандидатов доступен только preview-образ rustfs, который владелец
отверг. Отказ от MinIO в пользу аналога рассматривался и не принят.

## Отвергнутые варианты

- Развёртывание воспроизводимо из Docker Hub, логины не нужны.
- Версия MinIO теперь проверяема: релиз известен и совпадает с продом.
- Требуется следить за тем, чтобы elestio не перестал публиковать образ.
- Локальному кэшу доверять нельзя: образ с тегом
  `minio/minio:RELEASE.2024-12-18T13-15-44Z` содержит бинарник релиза
  `2025-09-07`. Теги в локальном хранилище не гарантируют содержимое — версию
  проверять через `minio --version` внутри контейнера.


| Вариант | Почему нет |
|---|---|
| `quay.io/minio/minio` | 401 с этой машины, локального кэша нет |
| `minio/minio` из Docker Hub | репозиторий отсутствует в реестре |
| `rustfs/rustfs` | в реестре есть, но preview; владелец решил оставить MinIO |
| `deuxfleurs/garage`, `seaweedfs/seaweedfs` | в Docker Hub отсутствуют (404) |
